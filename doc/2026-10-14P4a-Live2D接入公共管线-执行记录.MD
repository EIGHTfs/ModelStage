## 一、目标与结论

| 验收点 | 结果 |
|--------|------|
| ① 原版右栏「动作」区显示**当前 L2D 的 motions** + 点击真实切换 | ✅ 14 个 motions（`idle / idle` … `wedding / wedding`），点击后 `activeAnimation`、模型内部状态、画面像素全部变化 |
| ② 公共事件层（双指缩放/拖动/滚轮）对 L2D 与 Spine **同源**生效 | ✅ 同一合成手势下 L2D：`userScale 1→2`、`modelScale 0.1764→0.0882`（同一引擎状态）；Spine：`userScale 1→2` + 画面变化 |
| ③ Spine 路径零回归 | ✅ 产物页 vs 基线页同模型同冻结态：**diffPixels 0 / diffGt2 0 / maxDelta 0（共 992,160 像素）**，摘要同为 `f6f6fb38/954x1040/872886`；判别力对照 diffPixels 244,675 |
| ④ 控制台 0 error + 8803 可跑 | ✅ `error / unhandledrejection / console.error` 全 0（整条 L2D 流程 + 切回 Spine）；8803 HTTP 200 |

**核心结论（一句话）**：不需要给 L2D 另造 UI/事件——**让 Live2D「被引擎接受」**（`loadModel` 认出 `kind==="live2d"` 并返回与 Spine 同形的结果、相机四方法在 L2D 激活时委托给桥），
原版右栏动作区、原版公共指针事件层就**自动**对 L2D 生效了。

## 二、设计（三层，全部走原版数据通路）

```
用户点我们的角色库某个 Live2D 变体
   ↓
live2d-stage.show(m)  ── ① 把 L2D 模型补成 store 需要的形状并并入 store.models，再 setCurrentModel(m.id)
   ↓
原版 React「当前模型变化」effect（main-component.js 一行未改）
   ↓
engine.loadModel(m)  ── ② 认出 kind==="live2d" → bridge.loadForEngine(m)
   ↓                        （同模型已加载则复用，不重复加载）
bridge 返回 { animations, skins, version }  ── ③ 与原 Spine 返回**同形**
   ↓
原版 effect 继续执行：updateModel(id,{animations,skins,…}) → 右栏动作区渲染 → setAnimation(animations[0])
   ↓
engine.setAnimation(name, loop)  ── ④ L2D 激活时委托 bridge.playLabel(name) → PIXI model.motion(group,index)
```

**为什么必须补 `animations` / `skins`**（读代码得出，非臆造）：
`store-utils.js` 的 `setCurrentModel()` 会读 `model.animations.length`、`model.skins.length`、`.includes()`；
服务端 `/api/live2d/models` 给的 L2D 对象只有 `motions` / `expressions`（实测 keys：`id,kind,cubism,name,srcDir,rootId,rootName,modelUrl,defFile,mocFile,textureFiles,expressions,motions,iconUrl,fileSize`）——
不补就抛 TypeError。且该 action 是**按 id 在 `store.models` 里找模型对象**，而 L2D 模型默认不在 `store.models`（char-tree 只把它并进自己的树），
故 `syncStoreForEngine()` 用原版 `addModels()`（自带 name+fileSize+目录去重）把它并入列表，再 `setCurrentModel()`。

**公共事件层为什么零改动就生效**：`main-component.js` 的指针 Map / 两指距离 / `_f`/`au`/`ru` / 滚轮回调
只调 `c.current.applyZoom / applyPan / setCameraZoom / resetCamera / getCameraZoom`（对模型类型无假设）。
引擎在这四个方法里加 L2D 分支即可；缩放状态**继续复用 `this.userScale`**（Spine 语义：值越大视野越大 ⇒ 模型越小），
换算到 Live2D 的适配倍数即 `1/userScale`，于是两边同一手势得到同一方向、同一数值。

**指针事件怎么落到 L2D 上（关键）**：原版指针事件绑在 **Spine 画布** 上（`main-component.js` 的 `<canvas ref={E} onPointerDown={_f} …>`）。
P3 时 L2D 激活会把该画布 `visibility:hidden` —— 那会退出命中测试，事件永远收不到。
故 P4a 改为：L2D 覆盖层 `pointer-events:none`（事件下穿）+ Spine 画布用 `opacity:0` 隐藏（视觉隐藏但保留命中测试）。
这样事件由**原版公共事件层**接住 → 引擎 → 委托给 L2D 桥。**补丁层不再有第二套 pointer 事件**（历史自创绑定随之失效，P4b 删除）。

## 三、新增的「MOD 标记块」机制（保护逐字节校验链）

**矛盾**：P3 的 `src/**` 是逐字节可回填的原文分片（区间表 + 校验链）；P4 起要改源码，若直接改分片正文就永久丢掉原文区间信息。

**解法**：改动以显式标记块写在原文旁边，原文一个字不动：

```js
/*<<<MOD l2d-camera-zoom>>>*/
    if(this.l2dActive()){this.l2dBridge().setZoomRatio(1/this.userScale);return;}
/*<<<ENDMOD l2d-camera-zoom>>>*/
```

两条读取路径（`tool/lib/mods.mjs`）：

| 路径 | 处理 | 结果 |
|------|------|------|
| **基线**（默认） | `stripMods()` 剥掉全部 MOD 块（连同块前那一个 `\n`、块后 `\n` 与其行首缩进） | 逐字节 ≡ 原版区间 → `tool/build-byte-equal.mjs` 仍全绿（原文区间信息未丢） |
| **产物** | 保留 MOD 块 | 装配出「原版 + 本次改动」页面（新 sha256，属预期） |

剥离规则是字符级且可验证的：任何写歪（多留一个空格）都会被「拼接 ≡ 原文 module 体」的断言当场抓住 —— 实测第一版就抓到 36 字符多余（块后缩进），修正后通过。

**改动落点（8 处，全部在 `src/engine.js`，行号为文件内行号）**：

| # | MOD id | 位置 | 作用 |
|---|--------|------|------|
| 1 | `l2d-loadmodel-dispatch` | `loadModel` 开头 | `kind==="live2d"` → 走桥；从 L2D 切回其它 → 收起覆盖层 |
| 2 | `l2d-bridge-methods` | 类内新增方法块 | `l2dBridge()` / `l2dActive()` / `loadL2DModel()`（同形返回 + `onLoadComplete` + 同形 PMA 信息） |
| 3 | `l2d-camera-zoom` | `applyUserScale` 开头 | L2D：`setZoomRatio(1/userScale)` |
| 4 | `l2d-camera-pan` | `applyPan` 开头 | L2D：`pan(dx,dy)`（1:1 像素，沿用 L2D 既有手感） |
| 5 | `l2d-camera-reset` | `resetCamera` 开头 | L2D：`userScale=1` + `resetView()` |
| 6 | `l2d-set-animation` | `setAnimation` 开头 | L2D：`playLabel(name)` |
| 7 | `l2d-set-skins` | `setSkins` 开头 | L2D：`setExpressions(names)`（右栏「皮肤」区 = L2D 表情） |
| 8 | `l2d-present` | `presentFirstFrame` 开头 | L2D：跳过 Spine 侧首帧呈现 |

`src/js/**`（应用层）**一个字未改** —— 这也是本方案的价值：全部接入靠「引擎能接受 L2D」这一件事。

## 四、`public/live2d-stage.js` 改动（补丁层，非分片文件，直接改）

## 七、遗留 / 说明（P4b 待办）

1. **本轮只加能力，未删自创件**（按 Lead 定的顺序）：右栏紫色 Live2D 区块、缩放滑杆、自建动作/表情下拉、`bindPanZoom` 自带 pointer 绑定仍在（后者已因 `pointer-events:none` 失效）→ P4b 删除。
2. **暂停 / 截图导出 / 帧率**对 L2D 尚未接管：`togglePlay`、`exportPNG`、FPS 面板仍是 Spine 的（L2D 有自己的 PIXI ticker）。本轮未改，避免扩大影响面。
3. **资源缺口（非本次引入）**：`local-azurlane_spine-*` 这类模型的 `textureFiles` 为空，引擎加载失败 → 动作表为空；
   已在**基线页**复现同样结果（`animCount 0`、`textures 0`），确认与 P4a 无关，属该资源根的模型数据问题。
4. `public/live2d-stage.js` 现 826 行（原 582），超「单文件 ≤400 行」约数：它是补丁层文件、且 P4b 会删掉其中一批自创件；若仍超，建议按「桥 / 覆盖层 / 自创 UI」三块拆分。
5. `src/engine.js` 现 78,201 字节（含 8 个 MOD 块，+4,364 字符）：MOD 块保留在原文旁边（可读、可追溯）；基线读法自动剥离。
6. **产物尚未落 `dist/`**（本次边界禁止）：`tool/build-product.mjs` 主动拒绝写 `dist/`。
   若批准发布，命令是 `node tool/build-product.mjs --out <tmp> && cp <tmp> dist/index.html`（或给该工具加 `--publish` 开关），发布后 8803 即为「原版 + P4a」。
