# 展示类型插件机制 + 碧蓝航线 Live2D 单文件渲染方案

> **本文件取代** `doc/2026-10-14碧蓝Live2D资源包导入方案.MD`（那份是「服务端预解包成模型文件夹」路线，已废弃）。
>
> 目标形态变更：**不预解包**。资源就是一个**文件夹里全是这种单文件**（无扩展名，UnityFS），
> 网页要能**动态加载"展示类型"插件**去读它，并让它**进现有的角色库**（左栏三级树），
> 点开即渲染 —— 与现有 Live2D 模型同等待遇。

---

## 一、需求（已确认的设计决策）

| 决策点 | 结论 |
|---|---|
| 插件目录 | **项目根 `plugins/`**（不是 `public/`） |
| 插件形态 | 往该目录**放 js 即获得能力**（支持子目录 + `plugin.json` 清单声明入口与**加载顺序**） |
| 模块命名 | **按功能命名，不带序号**（`bytes.js` / `unityfs.js`…）；先后顺序由清单声明 |
| 插件定位 | **通用**：面向「Unity AssetBundle 内嵌 Live2D/Cubism」这一类文件，**不绑定单一游戏**；各游戏差异走 `profiles/<游戏>.json` |
| 实际输入 | 一个**文件夹里全是这种单文件**（当前先用单个样本做测试） |
| 呈现位置 | **进现在的角色库**（左栏三级树，与 Live2D 模型并列，按名表归组） |
| 渲染路径 | 复用已建好的 Live2D 桥与公共管线（原版右栏动作区、双指缩放同源） |
| 样本 | `adaerbote_3`（42 MiB，UnityFS AssetBundle，**碧蓝航线适配 = 首个 profile**）。测试根目录已备：`工作区/azurlane_bundle/adaerbote_3`（硬链接） |
| dist 核心 | **不动**（能力全部走插件层 + server 新增只读 API） |

## 二、现状（实测，供实现对照）

### 2.1 已有的「加 js 加能力」雏形（但写死）

`server.mjs:1395-1399` 硬编码注入 5 个脚本：

```js
const SCRIPT_TAGS = '<script src="/local-roots.js"></script>'
  + '<script src="/roots-ui.js"></script>'
  + '<script src="/char-tree.js"></script>'
  + '<script src="/live2d-stage.js"></script>'
  + '<script src="/settings-io.js"></script>';
```

→ 本方案要把它升级为**动态插件发现**，且原 5 个脚本行为保持不变。

### 2.2 服务端现有 API

| API | 作用 |
|---|---|
| `GET /api/roots` | 资源根列表（读 `config/resources.json`，JSONC） |
| `GET /api/tree?root=<id>&path=<相对>` | 列目录：子目录 + Spine 模型文件（按扩展名识别） |
| `GET /api/file?root=<id>&path=<相对>` | 读文件内容（带 MIME） |

**缺口**：
- 资源根目前只能是**目录**，且 `/api/tree` 按**扩展名**识别模型文件 → 无扩展名的 bundle 文件列不出来
- 没有「按插件能力列文件」的概念

### 2.3 样本实况（`adaerbote_3`，UnityPy 1.25.4 权威解析）

| 层 | 数据 |
|---|---|
| 容器 | `UnityFS` v8，Unity `2020.3.48f1`，42 MiB；flags `0x240`（**未压缩**，需 16 字节对齐填充 14 字节）；1 块；2 节点：`CAB-f3d748c3…`（23,050,320 B）+ `.resS`（20,971,520 B）；**blocksInfo 表内容结束于 217**（声明长度 160 = 表内容 153 + 7 字节表尾填充），**节点数据起点 224**（校验：224 + 23,050,320 + 20,971,520 = 44,022,064 = 文件大小；用 217 则差 7 字节） |
| 资源 | AssetBundle 名 `live2d/adaerbote_3`；容器 1 条 `assets/artresource/live2d/adaerbote_3/adaerbote_3.prefab` |
| 对象 | MonoBehaviour 2167 / GameObject 1303 / Transform 1303 / MeshFilter 685 / MeshRenderer 685 / **AnimationClip 34** / MonoScript 25 / **Texture2D 2** / Animator 1 / AssetBundle 1 / AnimatorController 1 / **TextAsset 1** |
| **moc3** | `MonoBehaviour` pathID `281177717138344885`，对象 3,225,648 B，`MOC3` 魔数在对象内 **+48**，前 4 字节 u32(LE) = **3,225,600**（与实际剩余**完全相等**）→ 已提取，`sha256 = cb881e62981b6aafec9b4e33…`，**现有 Cubism 4 Core 解析成功** |
| **physics3.json** | `TextAsset`，`m_Name = "adaerbote_3.physics3"`，49,206 B |

| **动作 34** | `complete, effect, home, idle, idle1..idle7, login, mail, main_1..main_4, mission, mission_complete, touch_body, touch_drag2, touch_head, touch_idle1..touch_idle10, touch_special, wedding`（Unity AnimationClip，每个 Cubism 参数一条曲线） |

## 三、设计总览（三层，互不侵入）

```
① 插件宿主（新增）        ② 资源根扩展（新增）           ③ 首个插件（新增，通用）
public/plugin-host.js      server.mjs：                  plugins/unity-live2d-bundle/
  · GET /api/plugins         · GET /api/plugins            plugin.json     ← 清单：声明入口与加载顺序
  · 动态 <script> 注入        · GET /api/file 支持根内任意文件   index.js        ← 注册：probe + open
  · window.SpineViewerPlugins · /api/tree 识别"插件可读文件"     lib/bytes.js        二进制原语
  · 失败隔离 / 开关           · 资源根新增 kind:"bundle"          lib/unityfs.js      UnityFS 容器
                                                              lib/serialized.js   SerializedFile
                                                              lib/extract.js      通用抽取
                                                              lib/texdecode.js    纹理格式分发
                                                              lib/etc2.js         ETC2/EAC 解码
                                                              lib/png.js          PNG 编码
                                                              lib/model3.js       重建 model3.json
                                                              lib/anim-to-motion.js  Unity 动画 → motion3
                                                              profiles/<游戏>.json  各游戏适配（数据）
```

> **两条命名/结构纪律**（来自实现约定）：
> 1. **模块文件名按功能命名，不带序号**（`bytes.js` 而非 `01-bytes.js`）；
>    「从简到难」体现在**依赖顺序**上，由 `plugin.json` 的 `files` 数组显式声明，宿主按序加载。
> 2. **插件本体保持通用**：`unity-live2d-bundle` 面向「Unity AssetBundle 内嵌 Live2D/Cubism」
>    这一类文件，**不针对单一游戏**；各游戏差异（命名约定、名表、分组规则）放进
>    `profiles/<游戏>.json`（数据），代码里不写死游戏名。

数据流：

```
用户加资源根(文件夹) → /api/tree 列出其中的 UnityFS 单文件（插件声明可读）
   → 角色库左栏出现条目（走现有名表归组，与 Live2D 并列）
   → 点击 → 前端取该文件字节(/api/file) → 插件 probe 命中 → 插件解析
   → 产出 {moc3, 纹理 PNG, physics3, motion3×N, model3} 的 Blob URL
   → 注册成 store 里的模型（kind:"live2d"）→ 现有 Live2D 桥/舞台/原版右栏动作区直接可用
```

## 四、插件契约（宿主 API `window.SpineViewerPlugins`）

```js
// 宿主暴露（public/plugin-host.js）
window.SpineViewerPlugins = {
  register(plugin),            // 插件注册（重复 id 拒绝并告警）
  list(),                      // 已注册插件（调试/UI 用）
  host: {                      // 宿主能力，插件只能通过它碰页面
    getStore(), getStage(),    // 现有 zustand store / Live2D 舞台
    fetchFile(rootId, rel),    // 走 /api/file 读字节
    notify(kind, msg),         // 复用现有提示通道
    registerModel(model),      // 把插件产出的模型登记进角色库/商店
  },
  version: 1,
};

// 插件文件末尾（每个插件只调用一次）
window.SpineViewerPlugins.register({
  id: 'unity-live2d-bundle',          // 唯一 id（通用：Unity AssetBundle 内嵌 Live2D）
  name: 'Unity Live2D 资源包',          // 界面显示名
  label: 'Live2D包',                   // 角色库里变体标签用它（不自创样式，沿用现有标签体系）
  version: 1,
  fileKinds: ['bundle'],               // 声明可读的资源根种类
  probe(bytes, meta) {                 // 返回 0..1 置信度（魔数/大小/结构）
    // 例：前 8 字节 === 'UnityFS\0' 且包内可定位 'MOC3' → 0.95
  },
  async open(ctx) {                    // ctx: {bytes, name, path, host, profile}
    // 解析 → 产出模型 → ctx.host.registerModel(model)
  },
});
```

**宿主纪律**：
- 插件加载失败/抛错**不得**影响页面与其它插件（每个 `<script>` 独立 try/catch + `window.onerror` 归属标注）
- 插件只通过 `host` 触碰页面，禁止直接改 dist 核心产物
- 清单形态：`plugins/<id>/plugin.json`（`{ id, name, entry, files: [...] }`）声明**按序加载**的 js；平铺单文件 `.js` 也支持（无清单时按文件名序）

## 五、资源根扩展（让单文件进角色库）

1. `config/resources.json` 的根新增可选字段 `kind`：
   - `kind: "spine"`（默认，行为不变）
   - `kind: "bundle"`：目录里是 UnityFS 单文件；**不按扩展名过滤**，改为「按魔数 `UnityFS\0` 识别」
2. `/api/tree?root=<bundle根>` 返回该目录下的 UnityFS 文件（`{ name, size, kind:'bundle' }`），供角色库构造条目
3. `/api/file?root=<id>&path=<相对>` 已可读任意文件（含无扩展名）——补 MIME `application/octet-stream` 并确认大文件流式返回（42 MiB）
4. 角色库（`public/char-tree.js`）：
   - 把 bundle 根的文件当**模型变体**并入现有三级树；归组沿用现有规则（碧蓝名表命中 → 角色名；`_N` 后缀归一）
   - 变体标签新增一种：`Bundle`（颜色沿用现有标签体系，不自创样式）
   - 点击 → 走插件（若插件已注册且 probe 命中）→ 渲染

## 六、首个插件模块（项目根 `plugins/unity-live2d-bundle/`）

**通用定位**：面向「Unity AssetBundle 内嵌 Live2D/Cubism」这一类文件（不止碧蓝航线）。
游戏差异放 `profiles/<游戏>.json`，代码不写游戏名。

**文件名按功能命名（不带序号）**；「从简到难」体现在依赖顺序，由 `plugin.json` 的 `files` 声明：

| 加载序 | 文件 | 职责 | 难度 |
|---|---|---|---|
| — | `plugin.json` | 清单：`{ id, name, entry, files: [...] }`，声明按序加载（替代文件名序号） | ★ |
| 1 | `lib/bytes.js` | 二进制原语：BE/LE、u8..i64、变长字符串、对齐、hex/sha256 | ★ |
| 2 | `lib/unityfs.js` | UnityFS 容器：header / blocksInfo（16 字节对齐）/ blocks / nodes；未压缩 + LZ4 分支 | ★★ |
| 3 | `lib/serialized.js` | SerializedFile：头部 / 类型树 / 对象表（对象 → 字节区间） | ★★★★ |
| 4 | `lib/extract.js` | 通用抽取：`moc3`（魔数 + 字节数组）/ `TextAsset`（`.model3.json` / `.motion3.json` / `physics3.json`）/ `Texture2D` 头 | ★★★ |
| 5 | `lib/texdecode.js` | 纹理格式分发：`m_TextureFormat` → 对应解码器；不支持时抛**可读错误** | ★★ |
| 6 | `lib/etc2.js` | ETC2_RGBA8（及同族 EAC）→ RGBA8888，按块模式 | ★★★★ |
| 7 | `lib/png.js` | RGBA → PNG（浏览器用 canvas；Node 侧用 `node:zlib`） | ★★ |
| 8 | `lib/model3.js` | 重建/补全 `model3.json`（Moc / Textures / Physics / Motions / Groups） | ★★ |
| 9 | `lib/anim-to-motion.js` | **Unity 集成版专用**：AnimationClip 曲线 → `motion3.json` | ★★★★★ |
| 10 | `index.js` | 注册：`probe`（魔数判定）+ `open`（编排上面各步 → 产出 Blob URL → `host.registerModel`） | ★★ |
| — | `profiles/azurlane.json` | 碧蓝航线适配数据（名表引用、目录/命名约定、分组规则）；**首个 profile** | ★ |

**两种包型都要能处理**（这决定通用性）：

| 包型 | 特征 | 处理方式 |
|---|---|---|
| **原生 Cubism 文件集** | 包内直接有 `.moc3` + `.model3.json` + `.motion3.json`（+ 纹理） | 直接抽取即可，**不需要** `anim-to-motion.js` |
| **Unity 集成版**（本样本） | 只有 moc3（藏在 MonoBehaviour 字节数组）+ `physics3.json`（TextAsset）+ 纹理 + **AnimationClip ×34**；**无** `model3.json` / `motion3.json` | 需 `model3.js` 重建 + `anim-to-motion.js` 转换 |

## 八、风险与预案

| 风险 | 预案 |
|---|---|
| SerializedFile 类型树解析（version 22）复杂 | 只解析必需对象；类型树走不通时用「对象表 + 魔数/长度前缀」兜底（本样本已证：`MOC3` + 前置 u32 长度） |
| ETC2 块模式实现出错 | 与 oracle PNG **逐像素比对**，先跑通单一模式再补全 |
| AnimationClip → motion3 语义（参数名/采样率/Loop/淡入淡出） | 以 oracle typetree 数值逐条核对；淡入淡出给保守默认并在文档写明 |
| 42 MiB 包 + 解码卡 UI | 先主线程带进度；实测卡顿则挪 Worker（解析与 ETC2 解码均可离线） |
| 大文件传输 | `/api/file` 流式返回；前端用 `fetch → arrayBuffer`，避免多次拷贝 |
| 插件互相干扰 | 每个插件独立 try/catch + 加载失败隔离；宿主 API 走白名单 |
| 其他包变体（压缩 / 无 moc3 / 不同纹理格式） | 容器实现 LZ4 分支；缺 moc3 或格式不支持时**抛可读错误**，绝不产出坏模型 |
