# 前端从零复刻方案（去原版残留）

> **⚠️ 实验状态：已中止（2026-10-14）**。自建渲染层（spine-webgl 手动装载）在适配/装载
> 环节反复踩坑（OrthoCamera lookAt 目标点语义、skeleton.x/y 不参与 updateWorldTransform、
> AssetManager 无法挂缓存），复刻现场已移 `.trash/`，`rebuild/`、`dist-rebuild/` 出库。
> 主站改回「原版 + 补丁」形态继续演进（见 doc/2026-10-14主站刷新闪烁修复.MD）。
> 本文保留作决策记录；「运行时 API 实测结论」（第四节下方）与「原版功能清单」（第 4 节）
> 对后续原版改造仍有参考价值。
>
> 本文档记录「自建前端、不再改造原版」的方案。起因：页面刷新瞬间会先渲染原版 原版 的
> 空状态说明页与左侧模型库，随后才被本项目脚本覆盖，出现可见闪烁。
> 方案定稿并实施后，本文档转为实施记录。

## 1. 问题与根因

### 现象

刷新页面时有一瞬间显示原版 UI：中间的空状态说明页（「Spine 骨骼动画预览器 / 拖入 .skel / .json / .atlas / .zip 文件开始」+ 快捷键提示）与左侧模型库面板（「模型库 583 个」+ 原版列表）。

### 根因（实测）

当前页面是「原版应用 + 外部补丁」形态：

| 层 | 内容 | 证据 |
|---|---|---|
| 运行时层 | 7 个 Spine 版本运行时（3.6~4.3，各 0.36~0.61MB），以 JSON 转义字符串内联在 `window.__SPINE_RUNTIME_SOURCES__` | 占基线 81%（3.39MB / 4.17MB） |
| 应用层 | 原版 原版 应用代码（798KB，压缩后的 React bundle） | `src/app-shell.html` |
| 补丁层 | 本项目 5 个脚本（115KB），由服务端在 `</body>` 前追加 `<script src>` | `server.mjs` 注入逻辑 |

闪烁链路：

1. 浏览器解析 `dist/index.html`，执行内联 module script（4.17MB，含 React 应用）
2. React 挂载到 `#root`，渲染原版完整 UI——此时**空状态说明页与原版左栏都是可见的**
3. body 末尾的补丁脚本（module 语义为 defer，必须等前面的 module 执行完）才开始运行
4. `char-tree.js` 运行时注入 CSS `.bv-sidebar.left-0{display:none}` 隐藏原版左栏；模型加载后空状态被替换

第 2 步到第 4 步之间存在若干帧，即为可见闪烁。原版左栏是 React 运行时渲染的（不在 HTML 源里），只能靠运行时 CSS 隐藏，无法从源码删除。

### 相关约束

- `baseline/index.html` 是原版的逐字节参照，`tool/verify.mjs` 依赖它做运行时一致性校验，不应改动。
- Spine 运行时受 Esoteric Software 授权约束，不入库（`.gitignore` 排除 `src/spine-runtimes/`），由 `tool/resolve-runtimes.mjs` 在构建时自动探测获取。
- 「双击即用」是原版核心特性（`file://` 直接打开单文件），运行时不能改为外链 `<script src>`（会被 CORS 拦截）。

## 2. 目标与边界

### 目标

自建前端应用层，替换原版 798KB bundle，做到：

1. **无原版残留**：首屏不出现原版说明页与模型库，不存在「先渲染再隐藏」的过程。
2. **视觉效果一致**：布局、配色、控件位置与原版保持一致的观感（以截图对照验收）。
3. **功能对齐**：原版可见功能（第 4 节清单）全部具备，行为一致。
4. **保留既有能力**：多游戏资源根、角色树三级聚合、Live2D 覆盖层、每游戏上次浏览、服务端 API 全部沿用。

### 边界

- 不改 `baseline/index.html`（继续作为运行时来源与校验基准）。
- 不改服务端资源扫描与 API 契约（`server.mjs` 的 `/api/roots`、`/api/models`、`/api/live2d/models`、`/files`、`/icons`、`/api/names`）。
- 不引入 npm 依赖与构建产物入库（项目为零依赖形态）。
- 不改名表/头像映射方案（另见 `doc/name-table-v2.md`）。

## 3. 技术路径

### 保留

| 保留项 | 说明 |
|---|---|
| `__SPINE_RUNTIME_SOURCES__` 机制 | 运行时仍从基线抽取、构建时内联回占位符，`file://` 可用性不变 |
| 执行运行时源码取 `spine` 全局对象 | 实测：执行任一版本源码后可取到 `spine` 全局对象，含 148 个 API |
| 服务端 API | 资源扫描、名表、文件与头像路由全部不动 |
| 业务脚本 | `public/` 的角色树聚合、Live2D 舞台、根管理、设置持久化逻辑可迁移复用 |

### 替换

| 替换项 | 现状 | 方案 |
|---|---|---|
| 应用外壳 | `src/app-shell.html`（原版 React bundle） | 自建外壳：原生 JS + 自有 CSS，不依赖 React 与 Tailwind 运行时 |
| 渲染层 | 原版内部实现（压缩不可读） | 用运行时公开 API 自建：`AssetManager` / `SkeletonJson` / `SkeletonBinary` / `TextureAtlas` / `SceneRenderer` / `AnimationState` |
| UI 层 | 原版组件 | 自建：顶部工具栏、左侧角色库、右侧控制栏、底部播放条、空状态 |

### 运行时 API 可用性（实测 4.1）

可用：`SceneRenderer`、`AssetManager`、`SkeletonJson`、`SkeletonBinary`、`TextureAtlas`、`AnimationState`、`AnimationStateData`、`Skeleton`、`AtlasAttachmentLoader`、`ManagedWebGLRenderingContext`、`Vector2`、`Color`、`MathUtils` 等 148 项。

不可用：`SpinePlayer`（属独立包，不在本 bundle 内）——自建渲染层需基于 `SceneRenderer` 自行组织渲染循环与相机控制。

### 渲染层要点

- 资源装载：`.json`（`SkeletonJson`）/ `.skel`（`SkeletonBinary`）+ `.atlas`（`TextureAtlas`）+ 贴图；ZIP 与文件夹导入走 `AssetManager`。
- 渲染循环：`SceneRenderer` + `requestAnimationFrame`，含 DPR 处理、上下文丢失恢复。
- 动画控制：`AnimationState` + `AnimationStateData`，支持单动作循环、动作切换、皮肤切换、时间轴与播放/暂停。
- 交互：滚轮缩放、拖拽平移、重置视图、影院模式。
- 混合：PMA（预乘/非预乘直通）按运行时能力分支处理。

## 4. 功能清单（复刻范围，按原版文案归纳）

| 滤镜 | 棋盘格 / 纯色 / 透明 / 自定义 / 炭黑 / 暖暗 / 骨白 / 绿幕 / 蓝幕 / 原画 |

## 5. 分期计划

| 期 | 内容 | 交付判据 |
|---|---|---|
| 期 1 | 自建外壳骨架 + 渲染核心（装载 .json/.skel/.atlas、播放、缩放/拖拽） | 能用自建页面打开一个 Spine 模型并播放动作，首屏无原版残留 |
| 期 2 | 左侧角色库（迁移现有三级树逻辑）+ 右侧动作/皮肤 + 底部播放条 | 角色树聚合与 Live2D 项可用，动作/皮肤可切换 |
| 期 3 | 高级功能：滤镜、PMA、运行时切换、调试绘制、主题背景、设置项全套 | 设置项与原版逐项对照可用，偏好持久化 |
| 期 4 | 导入（文件/文件夹/ZIP/URL）、截图导出、影院模式/全屏、清空画面 | 导入导出链路完整 |
| 期 5 | 收尾：Live2D 覆盖层迁移、移除对原版 DOM 的依赖、文档与校验更新 | 代码中不再引用 `.bv-sidebar` 等原版选择器 |

每期独立提交，可回退。

## 6. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 功能遗漏 | 原版可见文案 168 条，逐条对齐工作量大 | 以第 4 节清单为验收表，逐项打勾；每期对照原版截图 |
| 视觉不一致 | 原版用 Tailwind，自建 CSS 难以逐像素一致 | 以「观感一致」为验收标准（布局/配色/控件位置），不追求像素级；关键界面截图对照 |
| 运行时版本差异 | 3.6~4.3 的 API 能力不同（如 TextureAtlas、PMA 直通支持） | 沿用原版的「按运行时能力分支 + 自动降级」策略；切换运行时后重载模型 |
| 校验基准变化 | `tool/verify.mjs` 依赖 `baseline/index.html` 做逐字节等价校验 | 校验对象限定为「运行时对象一致性」，应用层不再与基线对比 |
| 过渡期双实现 | 自建与补丁脚本并存会造成两套逻辑 | 按期迁移，每期结束删除被替代的补丁代码，不留双份 |
| file:// 可用性 | 自建外壳若引用外部资源会破坏双击即用 | 产物仍为单文件内联（运行时 + 外壳 + 脚本），构建时合并 |

## 7. 验收标准

1. 首屏（含刷新、清缓存刷新）不出现原版说明页与原版模型库，无闪烁。
2. 原版功能清单逐项可用（第 4 节表格全部打勾）。
3. 关键界面与原版截图对照，布局与配色观感一致。
4. 代码中不再存在针对原版 DOM 的隐藏/覆盖逻辑（`.bv-sidebar`、原版按钮拦截等）。
5. `node tool/build.mjs` 产物仍为单文件，`file://` 双击可用。
6. 服务端 API 与资源根配置行为不变（bd2 / azurlane / azurlane_spine 三根扫描结果与改造前一致）。

## 8. 待确认决策点

1. **复刻范围**：第 4 节全部功能（含滤镜、PMA 检测、调试绘制、影院模式等小众项）是否都要，还是先做主干（模型浏览 + 动作/皮肤 + 设置）后补小众项。
2. **技术选型**：自建 UI 用原生 JS（零依赖，与现有一致）还是引入轻量框架（会增加构建步骤）。
3. **样式来源**：是否直接复用原版 Tailwind 编译出的 CSS（可从基线提取，省去重写样式）还是全新自写。
4. **原版资产处置**：`baseline/index.html` 与 `src/app-shell.html` 在自建完成后保留（作参照）还是移入回收站。
5. **Live2D 迁移时点**：随期 2 一并迁移，还是留到期 5。
