## 一、三件套与占位符机制（验收点④）

| 件 | 文件 | 内容 | 大小 |
|----|------|------|------|
| ① 骨架 | `src/index.html` | HTML 结构 + `<style>`/`<script type="module">` 标签 + boot 内联脚本；两处内容位写成占位符 | 778 B / 701 chars |
| ② 样式 | `src/styles.css` | 原 `<style>` 内的 CSS **逐字节原文**（tailwindcss v4.3.3 产物，未格式化） | 133,953 chars，sha256 `d7bd2705…cde0` |
| ③ JS | 原文区间表（`tool/rebuild-from-slices.mjs` 的 `SLICES` + `src/engine.js` 阅读视图） | module 脚本内容 = 原文 `[134565, 521938)` + `engine.js` 反重命名还原的 `[521938, 589360)` + 原文 `[589360, 816818)` | 682,253 chars |

占位符（各出现 **恰好 1 次**，脚本启动即断言）：

```
<style>/*__STYLES_CSS__*/</style>
<script type="module">/*__APP_JS__*/</script>
```

装配（`tool/build-from-parts.mjs`）：

```
skeleton.replace(CSS_PH, () => styles.css)
        .replace(JS_PH,  () => jsFromOrigAndSlices())
    ===  src/.app-shell.orig.html   （逐字节）
再按 tool/build.mjs 同一步骤内联运行时 → === dist/index.html
```

两个实现要点（都是踩过的坑）：
1. **必须用函数式 replace**（`.replace(ph, () => content)`）：CSS/JS 原文含大量 `$`（`${…}` 模板串、压缩短名 `$`），
   字符串式 replace 会把 `$&`/`$'` 当特殊变量解释，产物立刻不等。
2. **boot 内联脚本留在骨架里**（仅 108 chars）：它含运行时占位符
   `/*__SPINE_RUNTIME_SOURCES_PLACEHOLDER__*/`，是构建注入点，不属于「应用层 JS」；
   骨架因此不能单独运行（打开是空白），这是设计而非缺陷。

回填/装配校验链（`node tool/build-byte-equal.mjs`，六段全绿）：

| 段 | 校验 | 结果 |
|----|------|------|
| ① | 原文副本 ≡ `src/app-shell.html` | ✅ sha256 `ae8a5cad…521b` |
| ② | `engine.js` 反重命名 ≡ 原文区间；按原偏移回填 ≡ 原文；篡改 1 字符必被检出 | ✅ |
| **②b** | `src/styles.css` 逐字节等于原文 CSS；骨架 ≡ 由原文重生成；**装配 ≡ 原文**；篡改 CSS 1 字符必被检出；装配 + dist 内联运行时 ≡ dist | ✅ 产物 sha256 `ae8a5cad…521b` |
| ③ | 回填 + 运行时注入 ≡ `dist/index.html` | ✅ `fe640bf5…b849` |
| ③b | **三件套装配 + 运行时注入 ≡ `dist/index.html`** | ✅ `fe640bf5…b849` |
| ④ | `dist/index.html` ≡ `baseline/index.html` | ✅ `fe640bf5…b849` |
