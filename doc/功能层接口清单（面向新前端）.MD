# 功能层接口清单（面向新前端）

> 本文记录**与具体前端框架无关**的能力面：服务端 API、插件机制、纯函数库，以及新前端接入所需的最小契约。
> 背景：项目后续开发重心转向功能层，现有 React 前端仅作行为参考，后续将更换前端框架。
> 因此本文把"可复用能力"与"前端专属实现"分开写清楚，避免新前端重复实现或误把前端内部状态当契约。

## 一、服务端 API（`server.mjs`，零依赖，默认端口 8803）

以下均**实测 200/400 可响应**（2026-10-17 于本机 8803 验证）。

| 方法 | 路径 | 参数 | 返回要点 |
|---|---|---|---|
| GET | `/api/roots` | — | `{roots:[{id,name,path,kind,...}]}` 资源根清单 |
| GET | `/api/plugins` | — | `{ok,dir,plugins:[{id,name,label,version,fileKinds,entry,...}]}` 已发现插件（含被禁用标记） |
| GET | `/api/tree` | `root`（必需） | 目录树：`{root,path,kind,dirs:[{name,...}],files:[...]}`；按魔数识别 bundle/目录型资源；被插件禁用的条目带 `hiddenByPlugin` 与原因 |
| GET | `/api/models` | `root`（必需） | 该根的模型索引（可缓存落盘 `config/models.<rootId>.json`） |
| GET | `/api/names` | `root`（必需） | 名称表（角色/皮肤中文名映射） |
| GET | `/api/browse` | `root`,`path` | 目录浏览（服务端视角的路径与条目） |
| GET | `/api/bundle/probe` | `root`,`path` | **资源包装载前预检**（不解码纹理像素）：`{ok,code?,error?,resolvedFile,container?,objects?,moc3?,physics3?,textures?:[{name,width,height,format,formatName,supported}],motions?,warnings?,ms}`；`path` 支持目录或文件；不支持的纹理格式只标 `supported:false`，不整体失败；耗时含文件读取 |
| GET | `/api/file` | `root`,`path` | 单文件内容（带 MIME；路径穿越受保护） |
| GET | `/api/model-meta` | `root`,`path` | **Spine 模型元数据**（能力层）：`{kind,version,designSize,bbox,bones,slots,animations,motions,skins,runtime,resolvedFile}`；`motions` 为 `[{name,group,loop,confidence,rule}]`；与 Cubism 的 `modelMeta` 同字段名；**`path` 可以是模型目录或骨架文件**；失败带 `SPINE_ERR_*` 码 |
| GET | `/api/live2d/models` | `root`（必需，缺省返回 400） | Live2D 模型清单 |
| POST | `/api/diag` | JSON 体 `{entries:[...]}` | 追加写 `data/diag.jsonl`（8 MB 轮转、单请求 ≤500 条、单条 ≤8000 字符）；GET 该路径为 404（仅 POST） |
| GET | `/api/config/export` | — | 导出前端配置 |
| POST | `/api/config/import` | JSON 体 | 导入前端配置（自动备份） |
| GET | `/api/roots`（重复列出见上） | — | — |

### 1.1 调用顺序（**枚举类接口必须带 `root`**）

正确链路是**三步**，不要跳步：

1. `GET /api/roots` → 拿资源根清单，取其中的 `id`
2. `GET /api/tree?root=<id>`（或 `GET /api/models?root=<id>`）→ 拿该根的目录/模型
3. `GET /api/file?root=<id>&path=<rel>` → 取单个文件内容

**常见 400 及原因**（本机实测）：

| 请求 | 响应 | 原因 |
|---|---|---|
| `GET /api/tree`（不带 root） | `400 {"error":"未找到资源根: "}` | 枚举类接口**必须**带 `root` |
| `GET /api/models`（不带 root） | `400 {"error":"未找到资源根: "}` | 同上 |
| `GET /api/names`（不带 root） | `400 {"error":"未找到资源根: "}` | 同上 |
| `GET /api/tree?root=<不存在的 id>` | `400 {"error":"未找到资源根: <id>"}` | 根 id 不存在或未启用 |
| `GET /api/file?root=<id>&path=../x` | `403 {"error":"路径越界"}` | 路径穿越保护 |

**实测响应样例（截断）**：

```jsonc
// GET /api/roots
{"ok":true,"roots":[{"id":"azurlane_spine","name":"碧蓝航线","path":"…","enabled":true}, …]}

// GET /api/tree?root=azurlane_spine
{"root":"azurlane_spine","path":"","kind":"spine","dirs":[{"name":"aerbien","type":"dir"}, …]}

// GET /api/model-meta?root=azurlane_spine&path=aijier/aijier/aijierB.skel
{"ok":true,"kind":"spine","version":"3.8","designSize":{"width":3024.00048828125,"height":2328.28125},
 "bbox":{"x":-1594.927,"y":-276.802,"width":3024,"height":2328.278,"unit":"model","pose":"rest"},
 "bboxNote":null,"bones":246,"slots":29,"animations":1,"skins":1,
 "runtime":{"version":"3.8","origin":"inline:baseline/index.html"}}
```

**注意（当前状态）**：`/api/live2d/settings` 已停用（返回 404），其原本用途是"关闭裁剪遮罩"的实验开关，随该实验一并注释保留；新前端若需要类似开关，应作为自身配置承载，不要依赖此端点。

### 1.2 `/api/model-meta` 的支持范围与已知限制

**已支持**：Spine **3.6 / 3.7 / 3.8 / 4.1**（实测 3.8 与 4.1 均通过；4.2/4.3 运行时无法解析 4.1 骨架，属版本不匹配，不是本接口问题）。
**运行时来源**：`src/spine-runtimes/` → `../spine-runtimes/` → `baseline/index.html` 内联 → `dist/index.html` 内联（按此优先级；返回里 `runtime.origin` 会写明实际用了哪条）。
**`bbox` 口径**：**rest pose（setup pose）** 下、**模型单位**的包围盒，不含动作/物理变形。
**`designSize` 口径**：SkeletonData 的 `width/height`（Spine 的设计画布尺寸）。

**已知限制（实测记录，避免重复踩）**：
- 4.x 的解析要求附件**真的绑定了 region**：桩加载器（返回 null）会抛 `Cannot read properties of null (reading 'bones')`，自定义"new 出空附件"的桩会抛 `Region not set.` —— 所以必须走真实 atlas。
- 4.x 在解析期会读 `page.texture.getImage()`，而部分版本的 `page.setTexture()` 是空实现 ⇒ 本实现**构造 atlas 后直接把 texture 挂到每个 page 上**（对 3.8 无副作用）。
- 4.2/4.3 运行时**不能**解析 4.1 的骨架（实测报 `Bone name must not be null.`）——版本必须匹配到 minor。
- 同目录没有同名 `.atlas` 时：`designSize`/计数照出，`bbox` 为 `null`（并在 `bboxNote` 说明原因）。

### 1.3 Spine 动作分组/循环规则（数据文件 + 纯函数）

Spine 的动作命名规则**因游戏而异**，能力层不把它写进引擎，而是提供「规则数据 + 判定函数」：

- 规则文件：`tool/spine-motion-rules.json`（可注释、可编辑；改完重启服务生效）
- 纯函数：`tool/lib/spine-motions.mjs`（`loadRules` / `validateRules` / `classify` / `classifyAll` / `countHits`）
- 接口产出：`/api/model-meta` 的 `motions: [{name, group, loop, confidence, rule}]`，`animations` 计数保持不变

**判定优先级**：`overrides`（精确名）→ `families`（正则族，声明顺序首个命中）→ `defaults`。

**置信度语义**：
- `high` = 规则显式匹配且有实测样本（如 `idle*` 判循环、`_faceN`／`cut_*` 判一次性）
- `low` = 未命中任何规则（`group` 回退为动作名本身、`loop=false`），或该族循环语义无实测依据（如 `mix*`、`motion*`、纯数字命名）
- **宁可判一次性，也不误判成循环**：拿不准时一律 `loop:false`

**规则依据（全量实测）**：对 `bd2`（393 个 skel，成功 389）与 `azurlane_spine`（195 个，成功 194）**全量**扫描（`spine_mod` 下无 `.skel`），合计 **1075 个去重动作名**，其中 948 个被下列族覆盖，其余走 `defaults`。每条族的 `hits` 是**全量**命中数，`note` 写明依据：

| 族 | 命中（全量） | 分组 | 循环 | 置信 |
|---|---|---|---|---|
| `loop` | 26 | loop | true | high |
| `idle` | 24 | idle | true | high |
| `face` | 64 | face | false | high |
| `cut` | 148 | cut | false | high |
| `mix` | 618 | mix | false | low |
| `motion` | 42 | motion | false | low |
| `normal` | 1 | normal | false | low |
| `variant`（纯数字） | 24 | variant | false | low |
| `zhayan`（override） | 1 | blink | false | high |

**全量扫描里 5 个模型解析失败**（`SPINE_ERR_PARSE`，`Cannot read properties of null (reading 'bones')`）：`bd2` 的 4 个 cutscene/illust 骨架 + `azurlane_spine` 的 `jinshi.skel`。共同点是**目录里没有同名 `.atlas`**（已实测确认）——这批属于零件/切片或贴图在别处，元数据接口对它们如实报错，不产出错误数据。

**新增一个游戏的命名族**：在该文件 `families` 里加一条（`patterns` + `group` + `loop` + `confidence` + `hits` + `note`），用真实样本回填 `hits`；未命中的名字自动走 `defaults`，不会报错。

## 二、插件机制（能力扩展点）

### 2.1 目录与清单契约

```
plugins/<pluginId>/
  plugin.json      # 清单
  index.js         # 入口（ESM）
  lib/*.js         # 纯函数库（可选）
  profiles/*.json  # 游戏/资源档案（可选）
```

`plugin.json` 字段（以 `unity-live2d-bundle` 为例，实测有效）：

```json
{
  "id": "unity-live2d-bundle",
  "name": "Unity Live2D 资源包",
  "label": "Live2D包",
  "version": 1,
  "entry": "index.js",
  "fileKinds": ["bundle"],
  "files": ["lib/bytes.js", "…", "index.js"],
  "assets": ["profiles/azurlane.json"]
}
```

- `fileKinds` 决定该插件"接管哪类条目"（当前支持 `bundle`）；`/api/tree` 会据此把对应条目暴露给前端。
- `files` 是**加载顺序**（浏览器侧按序注入，插件内部不要假设其它文件的加载时机）。
- 开关：`config/plugins.json` 的 `disabled` 数组可整根停用某插件；停用后 `/api/tree` 对应条目会带 `hiddenByPlugin` 与原因说明。

### 2.2 前端宿主接口（`window.SpineViewerPlugins`）

由 `public/plugin-host.js` 提供，供插件注册与调用宿主能力：

- `register(plugin)` / `list()` / `labelFor(kind)` / `pickFor(kind)` / `discovered` / `ready` / `loadReport`
- `host`：`{ getStore, getStage, fetchFile, notify, registerModel }`

**这是"当前前端"的胶水层**：`host` 里的 store/stage 都是现前端的内部对象，**不构成稳定契约**。新前端应实现等价的宿主（提供"取当前视图/取舞台/取文件/提示/注册模型"五项能力）后，插件即可复用。

### 2.3 插件内部的两段式接口（建议新前端沿用）

- `prepare(input)` → **纯数据产出**（解析容器、抽取 moc3/纹理/动作、生成 model3 等），不接触渲染；
- `open(input)` → 在当前宿主上完成挂载。

新前端只接 `prepare()` 的产出即可（拿到模型数据与资源 URL），渲染由新前端自行负责——这样能力层与渲染层解耦，换框架时解析能力零改动。

### 2.4 游戏适配 profile（`profiles/*.json`）

**作用范围**：只影响**UnityFS 资源包**模型的产出（动作分组、循环判定、淡入淡出、点击热区、model3 顶层覆盖）。
对 Spine 模型与「目录型 Live2D」（自带 `model3.json`）**不生效**——这两类不需要也没有 profile 机制。

**选择机制**：资源根在 `config/resources.json` 里的 `profile` 字段 → 插件 `open()` 的 `ctx.profile` → `loadProfile()` 读 `plugins/unity-live2d-bundle/profiles/<name>.json`。没配就按通用规则（不循环、不分组、无热区）。

**真正被消费的字段**（其余字段写了也不生效）：

| 字段 | 作用 | 缺省行为 |
|---|---|---|
| `motion.loopPatterns` | 正则数组，命中即 `Loop: true` | 不循环 |
| `motion.fadeInTime` / `fadeOutTime` | 写进 model3 动作项 | 不写（用运行时默认） |
| `motion.groups` | `[{group, patterns[]}]`，把动作名归到语义组；不命中则**组名=动作名** | 每个动作自成一组 |
| `hitAreas` | `[{Id, Motion}]`，动作存在时才写入 `HitAreas` | 无热区 |
| `model3` | 覆盖/补充 model3 顶层（如 `Layout`） | 不覆盖 |

**不参与判定**：`comment` / `notes` / `label`（仅说明性，曾存在的 `namePatterns` 无任何消费点，已删除）。

**新增一个游戏 profile 的步骤**：
1. 确认该游戏资源是 **UnityFS 资源包**（`/api/bundle/probe` 能出 `ok:true`）；Spine/目录型不用做 profile
2. 用 `/api/model-meta` 或插件解析拿到**真实动作名**（不要照角色名猜）
3. 按命名规律归纳 `motion.loopPatterns` / `motion.groups` / `hitAreas`
4. 新建 `profiles/<game>.json`，并在 `config/resources.json` 对应资源根加 `"profile": "<game>"`
5. 抽 2~3 个模型做「profile 前 vs 后」对照（分组、循环逐条比对），确认无回归

**已验证的现实（避免重复找）**：工作区里唯一的资源包目录是 `live2d/`（19 个包，均为碧蓝航线）；`bd2`、`spine_mod`、`azurlane_spine` 是 Spine（`.skel`），`AzurLane-Live2D-Viewer-full/live2d` 是目录型（自带 `model3.json`），`DestinyChildLive2D/assets/live2d` 为空。因此**目前只有 `azurlane.json` 一个 profile 有实际作用对象**。

## 三、纯函数库（与前端无关，可直接复用）

`plugins/unity-live2d-bundle/lib/` 下 11 个模块，全部零依赖、纯 JS：

| 模块 | 职责 |
|---|---|
| `bytes.js` | 字节读写（大端/小端、对齐、变长整数） |
| `unityfs.js` | UnityFS 容器解析（版本、节点、块信息、解压） |
| `serialized.js` | Unity SerializedFile 解析（类型树、对象表） |
| `typetree.js` | 类型树到对象结构的还原 |
| `extract.js` | 从解析结果中抽取目标资源（moc3 / physics3 / 贴图 / 动画片段） |
| `etc2.js` | ETC2/EAC 纹理块解码 |
| `texdecode.js` | 纹理格式分发与像素转换 |
| `png.js` | PNG 编码（零依赖，输出可直接 `Blob`） |
| `model3.js` | 生成 Cubism `model3.json` |
| `anim-to-motion.js` | AnimationClip → motion3（含参数表白名单过滤、单点曲线补点） |
| `common-strings.js` | 常见字符串/哈希表 |

自检：`node plugins/unity-live2d-bundle/self-test.mjs`（当前 50 通过 / 0 失败）。

## 四、前端专属实现（新前端不必移植）

以下均为**现前端的行为参考**，不属能力层：

- `public/char-tree.js`（角色库树与显示规则）、`roots-ui.js`、`local-roots.js`、`settings-io.js`：现前端的 UI 与交互补丁
- `public/brand.js` 已停用（顶部栏品牌改为原版参数化）
- `public/diag.js`：诊断探针（**可复用**，见下）
- 全局对象 `__CHAR_TREE_*`、`__ROOTS_UI__`、`__LOCAL_ROOTS__`、`__SETTINGS_IO__`：现前端内部状态
- `__SPINE_STORE__`：**原版应用**的内部 store，不是本项目定义的契约，新前端不要依赖

## 五、可复用的观测/诊断能力

- `window.__DIAG__`（`public/diag.js`）：`event / dump / errors / warnings / timeline / tail / clear / size / flushNow`；
  内置事件语义 `plugin.load` / `bundle.parse` / `model.mount` / `motion.fail` / `interaction`；
  落盘走 `POST /api/diag` → `data/diag.jsonl`。
  **新前端可直接接入**：只需在入口调用 `__DIAG__.event(...)` 上报自有事件即可。

## 六、新前端接入的最小契约（建议）

1. **资源发现**：`GET /api/roots` → `GET /api/tree?root=`（拿到目录/单文件条目与 `kind`）
2. **插件能力**：`GET /api/plugins` 发现插件；对 `fileKinds` 命中的条目调用插件的 `prepare()` 拿纯数据
3. **文件读取**：`GET /api/file?root=&path=`（或插件产出的 Blob/URL）
4. **渲染**：
   - Spine：需要 `skel/atlas/贴图` + Spine 运行时（`tool/resolve-runtimes.mjs` 自动探测）
   - Live2D：需要 `model3.json + moc3 + 贴图 + physics3 + motion3` + Cubism 运行时（`tool/resolve-live2d-runtimes.mjs` 探测）
5. **诊断**：引入 `public/diag.js`（可选）并接 `POST /api/diag`

## 七、换前端前建议补齐的功能项

1. **`prepare()` 产出结构文档化**：目前产出字段散落在实现里，建议补一份"产出 schema"（字段名、类型、含义），新前端才好消费。
2. **Live2D 遮罩开关的去留**：`/api/live2d/settings` 已停用；若新前端需要"关闭裁剪遮罩"这类逃生开关，应由新前端配置承载并在渲染层实现。
3. **适配异常提示**：`aijierB` 一类"大幅插画型资产"在默认适配下铺满屏幕属正常；提示应由前端展示，但**判定数据（bbox 面积 / 视口面积）应由能力层给出**，避免每个前端各算一遍。
   - **判定规则**：`模型可视包围盒面积 / 视口面积 ≥ 3.0` → 判定为「画布比视口大」的模型，前端给一次性提示（同一模型只提示一次），**不改变任何适配行为**。
     注意：该规则的语义就是"画布面积 ≥ 视口的 3 倍"，**不是**用来区分"插画型 / 角色型"的判据。
   - **实测参照**（1920×1080 视口，引擎 `相机 fit` 日志的 bbox）：
     | 模型 | bbox | 面积 / 视口 | 是否触发 |
     |---|---|---|---|
     | `aijierB`（插画场景） | 2677.5×2328.3 | **3.37** | 触发 |
     | `aijierM`（角色） | 3402.0×1894.0 | **3.11** | 同样触发（两者只差 8%，规则本就不做类型区分） |
   - **当前前端的实现与限制**（仅供新前端参考，不必照搬）：提示放在 `public/settings-io.js`，复用该文件已有的 toast；数据来源是右栏日志里的 `相机 fit` 行，而日志容器**只在「日志」面板打开时才挂进 DOM** —— 因此**面板没开就不会提示**（不误报、会漏报）。这个限制正是"判定数据应由能力层给出"的理由。
   - 建议的数据出口：由插件/服务端在模型元数据里直接给出 `bbox`（宽高）与 `designSize`，前端只做比值判断与展示。
4. **`__SPINE_STORE__` 相关逻辑不要搬**：它是原版应用内部状态，新前端应建立自己的状态层。

## 九、资源包 → 标准模型目录导出（CLI，阶段 1）

```
node tool/export-bundle.mjs --root <id> --path <rel> [--out data/export] [--force] [--dry-run] [--profile <id>]
```

**产出**：`<out>/<资源名>/` 下 `<名>.moc3`、`<名>.physics3.json`、`textures/*.png`、`motions/<动作名>.motion3.json`、`<名>.model3.json`（含 `FileReferences.Motions`）、`export-report.json`。目录形态与常见第三方查看器一致（如 AzurLane-Live2D-Viewer 的 `live2d/<名>/` 布局）。产物落 `data/export/`（`data/` 已在 `.gitignore`）。

**行为约定**：
- PNG 用**真压缩**（`encodePngAsync`）；`encodePng` 是 stored 不压缩，4096² 会写出 ≈67MB
- **原子写**：先写 `.tmp-<名>-<pid>/`，成功后 `rename`；失败自动清理
- **默认跳过已存在**目标目录，`--force` 才覆盖；`--dry-run` 只报将写什么、不落盘
- **磁盘检查**：剩余 < 预估产物 ×1.5 直接拒绝（`ULB_ERR_EXPORT_NO_SPACE`）；中断码 `ULB_ERR_EXPORT_INTERRUPTED`
- 单包内遇到不支持的纹理格式：跳过该贴图 + warning，不整体失败
- `export-report.json`：耗时、逐文件字节、纹理清单、跳过项、警告

**实测对照（`adaerbote_3`，包 41.98 MB）**：

| 阶段 | 文件数 | 产物体积 | 耗时 | 说明 |
|---|---|---|---|---|
| 阶段 1（无 motion3） | 6 | 13.56 MB | 13.0 s | 纹理 PNG 10.4 MB + moc3 3.08 MB |
| 阶段 2（含 motion3） | **40** | **16.55 MB** | **17.1 s** | 34 个 motion3 合计约 3.0 MB |

**内存**：单次导出峰值约 450 MB（4096² ETC2 解码为主）。**同一个包连续 4 次**：RSS 120→135→**140→140 MB 收敛**、`heapUsed` 恒 6 MB ⇒ **没有累积泄漏**；不同包连导 3 次 RSS 会抬到 260 MB 左右（WASM/allocator 一次性高水位 + V8 不主动归还），属平台期而非线性增长。批量导出建议：分批进程或必要时 `--expose-gc`。

**已验证的消费者**（阶段 1 验收依据）：
- 第三方 runtime（pixi-live2d-display 0.4.0 + Cubism Core）加载导出目录 → canvas 8000×8000、纹理 4096²+2048²、drawables 685、**非背景像素 41.89%**（真实渲染）
- 第三方完整 App（AzurLane-Live2D-Viewer）在模型列表点选该导出 → `load_model()` 成功（cookie 切到 `live2d/adaerbote_3/adaerbote_3.model3.json`）、loading 收起、无报错

**motion3 生成（阶段 2）**：需要 moc3 的**真实参数 Id**，故把 Cubism Core（浏览器构建）放进 vm 沙箱：

- 模块：`tool/lib/cubism-core.mjs`；`getParameterIds(moc3)` 返回 `{ids, count, canvas}`
- **沙箱契约**：提供 `document.currentScript` / `location` / `atob` / 只认 `data:` 的 `XMLHttpRequest`（Core 的 Emscripten 外壳用它取内嵌 base64 的 WASM）；**不提供** `process`/`require`（避免它走 Node 分支去 `readFileSync` 一个 data: URI）
- **初始化点**：脚本 eval 完成即初始化（Emscripten 的 `run()` 在 eval 末尾）；随后用 `Version.csmGetVersion()` 自检（实测 `67239938`、`csmGetLatestMocVersion()=4`）
- **释放**：`try { model.release() } finally { moc._release() }`（顺序固定，任一步为 null 就跳过）；导出流程每个包处理完都必须释放
- **转换复用**：`lib/anim-to-motion.js` 的 `clipsToMotions(sf, candidates, {paramWhitelist, isLoop, fadeIn, fadeOut})`，**第二参是"名字候选（字符串数组）"而不是 clip 对象**（传错会让绑定哈希全部认不出）；`paramWhitelist` 传真实参数 Id 的 `Set`
- **曲线口径**（写进 `export-report.json` 的 `motions.curves`）：`total`=全部绑定条数、`emitted`=真正写入 motion3 的曲线数、`skipped`=`skippedUnknownBinding`（绑定哈希认不出的，如实计数，不是 bug）。实测 `adaerbote_3`：total 15376 / emitted 15032 / skipped 344
- **分组**：与现有 profile 语义一致——`motionGroupOf(name, profile)`（profile 的 `motion.groups` 命中则用规则组，否则组名=动作名）；`Loop` 由 `motionLoops(name, profile)` 决定并写进 motion3 的 `Meta.Loop`

**播放验收（阶段 2 硬验收）**：第三方 runtime 加载后播放 `idle`，1.6 s 后对比两帧像素：**71,147 / 1,080,000 = 6.59% 像素发生变化**（证明动作真的在动，不是静帧）；`model3.FileReferences.Motions` 共 **34** 组，与包内动作数一致。
