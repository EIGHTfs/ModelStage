## 二、切点怎么定的（不是拍脑袋）

### 2.1 候选切点 = 顶层语句的「起点 ∪ 终点」

用 acorn 解析 module 体（`ecmaVersion: latest`）得到 **944 条顶层语句**，把每条语句的 start/end 收进一个「接缝集合」（999 个接缝）。
每个库边界（`doc/bundle-map.md` 给的偏移）**吸附到最近的接缝**，于是每片必然由**完整的顶层语句**组成，不会切进语句中间。
吸附结果：**20 个边界零偏移命中接缝**，只有 framer-motion 的起点需要后移 23 字符（见 2.3）。

### 2.2 license 横幅归属自动核对

对每个带横幅的库，检查「横幅偏移 ≥ 片首」：

| 库 | 横幅偏移 | 距片首 |
|----|---------|--------|
| react-jsx-runtime | 136289 | +7 |
| react | 137013 | +7 |
| scheduler | 145139 | +7 |
| react-dom | 149013 | +7 |
| react-dom-client | 152854 | +7 |
| lucide-react（47 个横幅，首个） | 496781 | +7 |
| **其余（zustand / sonner / framer / tailwind-merge / radix）** | 无 license 横幅 | — |

即：**所有横幅都留在自己的库里**，没有被切到邻片。

### 2.3 推定区间与「宁可切大」的三个决定

1. **framer-motion 起点 382123 → 382146**：bundler 把「应用 store」与「Framer 的 React context」`qp=S.createContext({})` 合并成**同一条 const 语句**
   `const Fe=vT(<store>),qp=S.createContext({})`（[367348, 382146)，14,775 字符）。
   - 吸附到语句起点 367348 → 会把 **14.7KB 应用 store 吞进 vendor 片**；
   - 吸附到语句终点 382146（= 下一语句起点）→ 应用片保住 store，只有 **23 字符**的 `qp=` 落在应用片尾（两片都仍是合法语句边界）。
   选后者（代价最小、两片都语法完整）；`qp=S.createContext({})` 属 Framer，已在此记录，若要严格归属需改 bundler 产物（不做）。
2. **radix-ui / tailwind-merge 无横幅、边界推定**：分别取 `const xt=n=>{…}`（tailwind-merge 的 theme getter）与 `var Lj=Object.defineProperty…`（radix 的入口）
   作为片首 —— 两者都**恰好是接缝（零偏移）**，因此按「切大不切小」原则**不需要并片**。
   `Symbol.for("radix-ui")` 出现在 631246（第 17 片 `app/ui-shadcn.js` 内），那是 radix 的 `Primitive` 定义被 bundler 与应用 UI 代码混编；归属已在表中标注。
3. **应用片与 vendor 片交替出现**（bundler 按引用顺序混排），所以：
   - **不采用「单个 `src/js/app.js`」**：一个文件无法同时表示多段**非连续**区间（要引入「文件内二次偏移表」，复杂度不值），改为**一段区间一个文件**；
   - 第 9 片（`app/store-utils.js`）是**跨库混合片**（应用 store + Framer 的 23 字符 + `pd` 工具）——这是 bundler 的 `const` 合并所致，已在表里标 "混合片"。
4. **engine.js 归置：保留 `src/engine.js`，不搬进 `src/js/`**。理由：① 它是 P2 已逐字节验证的链路（含 28 处可逆改名），搬家会同时改动 P2 的验证锚点与记录；② 多片机制不需要它搬家——`slices.json` 里它就是第 13 片，位置只是一条数据。已在文档与表里并列说明。
