# 支持边界（一处索引 + 明确不支持项）

> 只写"支持什么/不支持什么"与权威实现位置。详细机制见各专项文档，本页不重复。

## 一、运行时版本

| 类型 | 支持 | 不支持 | 权威位置 |
|---|---|---|---|
| Spine | 3.6 / 3.7 / 3.8 / 4.0 / 4.1 / 4.2 / **4.3** | **4.4+**（无运行时；版本识别区间止于 4.0–4.3，骨架会被挑到 4.3） | `docs/参考/渲染与纹理.md` §1.6 |
| Live2D | Cubism 2（`.moc`）、Cubism 4（`.moc3`）；两套组合：v6（默认）Core 4.2.2、v8 Core 6.0.1 | **Cubism 5 未验证**（v8 的 Core 6.0.1 具备能力，但无真实 v5 样本验证） | `docs/参考/Live2D.md` §2.1 |

## 二、资源容器

| 容器 | 支持 | 判据 |
|---|---|---|
| UnityFS AssetBundle | ✅ | 文件头 `UnityFS\0`（`src/server/plugins/registry.mjs`） |
| CAB serialized file | ✅ | 文件名结构 `/^CAB-[0-9a-f]{32}$/i`（不按前缀判） |
| ZIP / 7z 归档 | ❌ | 无解包实现；不通过自定义插件则无法直读 |
| Live2DViewerEX `.lpk` | ❌ | 私有加密容器（`encrypt:"true"`），见 `docs/设计/live2dviewex-LPK调研.md` |

## 三、清单（模型索引）格式

| 格式 | 支持 | 说明 |
|---|---|---|
| `.json` | ✅（默认） | 单文档，视为完整 |
| `.jsonl` | ✅（`MODELSTAGE_MANIFEST_FORMAT=jsonl`） | 需 `complete` 末行；未完成一律重建 |
| 其它格式 | ❌ | 无适配器 |

清单头字段固定为 `{rootId, ts, count, generator, dirStamps, models}`；渲染器类型不写入清单，由 catalog 读取时按来源盖章。

## 四、插件角色

| 角色 | 状态 | 边界 |
|---|---|---|
| `asset-provider` | **已落地** | `canHandle` / `resolve`；bundle 类资源已进渲染链路 |
| `bundle-analyzer` | **已落地** | `analyze(bytes)`：只给事实（容器头/对象表/TextAsset/纹理格式），**不下「是不是模型」的结论**（判据在核心） |
| `renderer` | 受限开放 | 只挂后处理效果，不接管渲染器生命周期 |
| `panel` | 受限开放 | 只允许声明式控件，插件不碰 DOM |
| `editor` | **留位，未实现** | `Document` 读写 + `applyCommand(cmd)` 接口已定义 |
| `exporter` | **留位，未实现** | `Document` 只读 + 写输出 |

运行时形态：`runtime:"node"`（进程内 vm 沙盒，按 `files[]` 顺序注入，需 IIFE/UMD 构建产物）与
`runtime:"exec"`（spawn 插件目录里的可执行文件，走「一行一个 JSON」帧协议，**语言不限**；
**默认关闭**，需 `MODELSTAGE_ALLOW_EXEC_PLUGINS=1` 或 `<数据根>/config/plugin-runtime.json` 的
`allowExecRuntime: true` 才启用；未开启时该插件不注册并给可读原因）。

列表条目的显示名由插件在 `analyze()` 的 `displayName` 里声明，核心只渲染不解析（见 `docs/契约/插件.md` §1.3）。

## 五、只读分析（`/api/analyze`）

**能回答什么**：

| 问题 | 从哪来 |
|---|---|
| 这个文件是什么容器、哪个引擎版本、几个节点 | 插件 `analyze()` 的 `container` / `nodes` |
| 包里有几个对象、各是什么类 | `objects` |
| 有哪些 TextAsset、各是什么类型与骨架版本 | `textAssets`（`.skel` / `.atlas` / `.json` + 版本串） |
| 有几张纹理、什么格式、能不能解码 | `textures[].formatName` / `supported` |
| 一句话结论 | `summary` + `verdict` |

**不回答什么**（明确边界）：

```
· 不产模型：不输出可渲染数据，也不写任何文件（这是 asset-provider.resolve 的职责）
· 不解密：加密容器（例如 LPK）只判为 archive 并提示"内部可能加密"，不做解密
· 不递归进容器内部：目录模式只分析"容器/模型"这一层，不展开容器里的文件
· 不保证覆盖所有格式：不在候选判据里的文件不会被分析（见下方扩展名清单）
```

**两种模式**：

```
GET /api/analyze?path=<绝对路径>              单文件
GET /api/analyze?dir=<绝对路径>&maxFiles=500  目录递归 + 聚合
```

**限额**（用"字节/数量上限"，不用时间）：

```
单文件 512MB     超过直接拒绝并说明（不做流式全解析）
目录 500 个候选   超出的写进 warnings，不静默截断（可用 maxFiles 调整）
递归深度 12 层    超过即停（防符号链接环与异常深目录）
并发 1            逐个分析：一个包要解 LZMA + 建对象表，并发会互相拖慢
```

**没有分析插件时**：不报错，降级为**按文件头判定**（UnityFS / CAB- / MOC3 / ZIP / JSON），
`analyzedBy.fallback = true`，并在 `warnings` 里说明「装哪个插件才能细看」。

**候选判据**（目录模式）：

```
扩展名：.skel .atlas .moc .moc3 .model3.json .lpk .unity3d .bundle .ab
魔数  ：UnityFS / CAB- / MOC3 / PK（zip/lpk）
```

普通 `.json` **不在**候选里（`config.json` 之类的配置文件远多于模型，收进来只是噪音）。
