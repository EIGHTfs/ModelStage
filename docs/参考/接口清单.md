## 一、服务端 API

| 方法 | 路径 | 参数 | 返回要点 |
|---|---|---|---|
| GET | `/api/roots` | — | `{roots:[{id,name,path,kind,...}]}` 资源根清单 |
| GET | `/api/plugins` | — | `{ok,dir,plugins:[{id,name,label,version,fileKinds,entry,provides,...}]}` 已发现插件（含禁用标记） |
| GET | `/api/tree` | `root`（必需） | 目录树：`{root,path,kind,dirs,files}`；按魔数识别 bundle / 目录型；被插件禁用的条目带 `hiddenByPlugin` 与原因 |
| GET | `/api/catalog` | `root`（可选） | **统一模型清单**（`ModelEntry`）；前端业务代码的**唯一取数口** |
| GET | `/api/spine/models` | `root`（必需） | 该根的 Spine 模型索引（供诊断与测试；业务代码不要用） |
| GET | `/api/live2d/models` | `root`（必需，缺省 400） | Live2D 模型清单（同上，单路） |
| GET | `/api/names` | `root`（必需） | 名称表（角色/皮肤中文名映射） |
| GET | `/api/browse` | `root`,`path` | 目录浏览（服务端视角的路径与条目） |
| GET | `/api/bundle/probe` | `root`,`path` | **装载前预检**（不解码纹理像素）：`{ok,resolvedFile,container,objects,moc3,physics3,textures:[{name,width,height,format,formatName,supported}],motions,warnings,ms}`；`path` 支持目录或文件；不支持的纹理格式只标 `supported:false`，不整体失败 |
| GET | `/api/file` | `root`,`path` | 单文件内容（带 MIME；路径穿越受保护） |
| GET | `/api/model-meta` | `root`,`path` | 模型元数据：`{kind,version,designSize,bbox,bones,slots,animations,motions,skins,runtime,resolvedFile}`；`motions` 为 `[{name,group,loop,confidence,rule}]`；**`path` 可以是模型目录或骨架文件** |
| POST | `/api/diag` | `{entries:[...]}` | 追加写 `data/diag.jsonl`（8 MB 轮转、单请求 ≤500 条、单条 ≤8000 字符）；GET 该路径 404 |
| GET / POST | `/api/unpack/{resolve,file,capacity,stats}` | — | 服务端解包：准入判断、产物读取、内存容量、分阶段统计 |
| GET / POST | `/api/backgrounds`、`/api/backgrounds/solids` | — | 背景图与纯色预设（后者 5 个接口，见[数据与接口契约](../契约/数据与接口.md) §3） |
| GET | `/api/ready`、`/api/ready/stream` | `stage`（可选） | 就绪信号快照 / SSE（先推全量再推增量） |

### 1.1 调用顺序（枚举类接口必须带 `root`）

```
1. GET /api/roots                          → 拿资源根清单，取 id
2. GET /api/catalog?root=<id>              → 拿该根的模型条目
3. GET /api/file?root=<id>&path=<rel>      → 取单个文件内容
```

**常见 400 / 403 及原因**：

| 请求 | 响应 | 原因 |
|---|---|---|
| 枚举类接口不带 `root` | `400 {"error":"未找到资源根: "}` | 必须带 `root` |
| `root=<不存在的 id>` | `400 {"error":"未找到资源根: <id>"}` | 根 id 不存在或未启用 |
| `/api/file?path=../x` | `403 {"error":"路径越界"}` | 路径穿越保护 |

### 1.2 `/api/model-meta` 的支持范围与限制

**已支持**：Spine **3.6 / 3.7 / 3.8 / 4.1**（4.2/4.3 运行时无法解析 4.1 骨架，属版本不匹配，不是本接口问题）。

**运行时来源**（返回里 `runtime.origin` 写明实际用了哪条）：

```
环境变量 SPINE_RUNTIME_DIR → 项目内 src/spine-runtimes/ → 工作区共享 ../spine-runtimes/
```

**没有兜底**：找不到时显式报错并给修复指引，不静默降级。

**口径说明**：

- `bbox`：**rest pose（setup pose）** 下、**模型单位**的包围盒，不含动作/物理变形
- `designSize`：SkeletonData 的 `width/height`（Spine 的设计画布尺寸）

**已知限制**：

- 4.x 解析要求附件**真的绑定了 region**：桩加载器（返回 null）会抛
  `Cannot read properties of null (reading 'bones')`，自定义空附件会抛 `Region not set.` ⇒ 必须走真实 atlas
- 4.x 解析期会读 `page.texture.getImage()`，而部分版本的 `page.setTexture()` 是空实现
  ⇒ 本实现构造 atlas 后**直接把 texture 挂到每个 page 上**（对 3.8 无副作用）
- 同目录没有同名 `.atlas` 时：`designSize` / 计数照出，`bbox` 为 `null`（`bboxNote` 说明原因）

### 1.3 `/api/unpack/resolve`：容器类模型的唯一入口

**它是什么**：把「一个容器文件」变成「一组成品文件」的那一步。容器条目（`container: 'unityfs'`）在
列举阶段 `kind` 只能是 `null`（解包前判不出是 spine 还是 live2d），所以**能不能打开完全取决于这个接口**。

```
POST /api/unpack/resolve   { rootId, rel, allowOverLimit? }
  → 200 { ok:true, hit, fingerprint, prefix, entry,
          unpackMs, memBasis?, peakEstMb?, phases?, files:[{path,size,url}] }
  → 500 { ok:false, reason, message, (insufficient-memory 时另带 budgetMb / peakEstMb / availMb) }
```

**两条路径（`hit` 区分）**

| 情形 | 行为 | 成本 |
|---|---|---|
| **命中**（`data/unpacked/<fp>/index.json` 已在） | 读清单直接返回，`hit:true` | 毫秒级（实测 0.032s） |
| **未命中** | 串行排队 → 内存准入 → worker 解包 → 原子落盘 → 写 probe → 回清单 | 秒级（33.4MB 的 LZMA 包：`unpackMs` 9.4s、墙钟约 17.8s） |

`fp`（指纹）= 源文件 mtime/size + 插件版本聚合 + `providerFingerprint()`，
所以**换插件或换运行时目录会让缓存整体失效**，这是刻意的。

**失败 `reason` 清单**（每条都要能对上可读提示，别让用户只看到 HTTP 500）

```
not-handled          没有插件的 canHandle 认这个文件（例：Cubism 2 的 .moc 包）
plugin-unavailable   插件装载失败 / 被禁用
insufficient-memory  内存准入不通过（带 budgetMb / peakEstMb / availMb；可 allowOverLimit 强解）
over-limit-allowed   准入本来不过，但调用方显式要求强解（返回里会标明）
source-missing       源文件不在了        source-unresolved  容器路径解析不出文件
source-changed       源文件在排队/解包期间被改（指纹与入队时不一致）
read-failed          读源文件失败
resolve-threw        插件 resolve() 抛错  worker-error      worker 崩溃/超时（120s 上限）
bad-json             请求体不是合法 JSON
```

**与前端回落的关系**：本接口超时或 500 时，前端会**回落到浏览器自己解包**（`src/web/plugin/unpack-worker.js`）。
这条回落是兜底、不是常态 —— 它让「服务端不可用」不表现为「模型打不开」，但也意味着
**日志里出现 resolve 超时时模型仍可能正常显示**（别据此判断服务端没问题）。

> ⚠️ 已知边界：客户端默认超时 8.5s，而合法的 33.4MB LZMA 包要 9.4s（墙钟 17.8s）
> ⇒ 大包必然走回落。这是「默认超时短于合法耗时」的独立问题，**搬 worker 并没有修它**
> （搬 worker 只解决"解包期间事件循环被占、连带所有并发请求超时"）。

## 二、Spine 动作分组与循环规则

动作命名规则**因游戏而异**，能力层不把它写进引擎，而是提供「规则数据 + 判定函数」：

| 项 | 位置 |
|---|---|
| 规则文件 | `tool/spine-motion-rules.json`（可注释、可编辑；改完重启生效） |
| 纯函数 | `tool/lib/spine-motions.mjs`（`loadRules` / `validateRules` / `classify` / `classifyAll` / `countHits`） |
| 接口产出 | `/api/model-meta` 的 `motions: [{name, group, loop, confidence, rule}]` |

**判定优先级**：`overrides`（精确名）→ `families`（正则族，声明顺序首个命中）→ `defaults`。

**置信度语义**：

- `high` = 规则显式匹配且有实测样本（如 `idle*` 判循环、`_faceN` / `cut_*` 判一次性）
- `low` = 未命中任何规则（`group` 回退为动作名本身、`loop=false`），或该族循环语义无实测依据

**红线：宁可判一次性，也不误判成循环** —— 拿不准时一律 `loop:false`。

**已校准的族**（对两个 Spine 根全量扫描，合计 1075 个去重动作名，其中 948 个被下列族覆盖）：

| 族 | 分组 | 循环 | 置信 |
|---|---|---|---|
| `loop` | loop | true | high |
| `idle` | idle | true | high |
| `face` | face | false | high |
| `cut` | cut | false | high |
| `mix` | mix | false | low |
| `motion` | motion | false | low |
| `normal` | normal | false | low |
| `variant`（纯数字） | variant | false | low |
| `zhayan`（override） | blink | false | high |

**新增一个游戏的命名族**：在 `families` 里加一条（`patterns` + `group` + `loop` + `confidence` + `hits` + `note`），
用真实样本回填 `hits`；未命中的名字自动走 `defaults`，不会报错。

**已知解析失败**：少数骨架目录里没有同名 `.atlas`（零件/切片型资产），元数据接口如实报
`SPINE_ERR_PARSE`，不产出错误数据。

## 三、插件机制

### 3.1 目录与清单

```
plugins/<pluginId>/
  plugin.json      # 清单
  index.js         # 入口（注入式经典脚本）
  lib/*.js         # 纯函数库（可选）
  profiles/*.json  # 游戏/资源档案（可选）
```

```json
{
  "id": "unity-live2d-bundle",
  "name": "Unity Live2D 资源包",
  "label": "Live2D包",
  "version": 1,
  "entry": "index.js",
  "fileKinds": ["bundle"],
  "files": ["lib/bytes.js", "…", "index.js"],
  "assets": ["profiles/unityfs-live2d.json"],
  "provides": ["asset-provider"],
  "produces": { "kind": "live2d", "entry": "resolve(file)" }
}
```

- `fileKinds` 决定该插件「接管哪类条目」；`/api/tree` 据此把对应条目暴露给前端
- `files` 是**加载顺序**（按序注入，插件内部不要假设其它文件的加载时机）
- 开关：`config/plugins.json` 的 `disabled` 数组可整根停用；停用后 `/api/tree` 对应条目带 `hiddenByPlugin`

字段语义与注册规则见[插件契约](../契约/插件.md)。

### 3.2 游戏适配 profile

**作用范围**：只影响 **UnityFS 资源包**模型的产出（动作分组、循环判定、淡入淡出、点击热区、model3 顶层覆盖）。
对 Spine 模型与「目录型 Live2D」（自带 `model3.json`）**不生效**。

**选择机制**：资源根在 `config/resources.json` 里的 `profile` 字段 → 插件读
`plugins/unity-live2d-bundle/profiles/<name>.json`。没配就按通用规则（不循环、不分组、无热区）。

**真正被消费的字段**（其余写了也不生效）：

| 字段 | 作用 | 缺省行为 |
|---|---|---|
| `motion.loopPatterns` | 正则数组，命中即 `Loop: true` | 不循环 |
| `motion.fadeInTime` / `fadeOutTime` | 写进 model3 动作项 | 不写（用运行时默认） |
| `motion.groups` | `[{group, patterns[]}]`，把动作名归到语义组；不命中则**组名 = 动作名** | 每个动作自成一组 |
| `hitAreas` | `[{Id, Motion}]`，动作存在时才写入 `HitAreas` | 无热区 |
| `model3` | 覆盖/补充 model3 顶层（如 `Layout`） | 不覆盖 |

**不参与判定**：`comment` / `notes` / `label`（仅说明性）。

**新增一个游戏 profile 的步骤**：

```
1. 确认该游戏资源是 UnityFS 资源包（/api/bundle/probe 能出 ok:true）
2. 用 /api/model-meta 或插件解析拿到真实动作名（不要照角色名猜）
3. 按命名规律归纳 motion.loopPatterns / motion.groups / hitAreas
4. 新建 profiles/<game>.json，并在 config/resources.json 对应资源根加 "profile": "<game>"
5. 抽 2~3 个模型做「profile 前 vs 后」对照（分组、循环逐条比对），确认无回归
```

与前端框架无关、零依赖、可直接复用。完整索引见[架构/能力层](../架构/能力层.md) §二。

核心两组：

- `plugins/unity-live2d-bundle/lib/`：容器解析 → 对象表 → 资产抽取 → 纹理解码 → PNG 编码 → model3/motion3 生成

## 五、资源包 → 标准模型目录导出（CLI）

```
node tool/export-bundle.mjs --root <id> --path <rel> [--out data/export] [--force] [--dry-run] [--profile <id>]
```

**产出**：`<out>/<资源名>/` 下 `<名>.moc3`、`<名>.physics3.json`、`textures/*.png`、
`motions/<动作名>.motion3.json`、`<名>.model3.json`（含 `FileReferences.Motions`）、`export-report.json`。
目录形态与常见第三方查看器一致。

**行为约定**：

- PNG 用**真压缩**（`encodePngAsync`）；不压缩的写法在 4096² 上会产出 ≈67MB
- **原子写**：先写 `.tmp-<名>-<pid>/`，成功后 `rename`；失败自动清理
- **默认跳过已存在**目标目录，`--force` 才覆盖；`--dry-run` 只报将写什么、不落盘
- **磁盘检查**：剩余 < 预估产物 ×1.5 直接拒绝；中断有独立错误码
- 单包内遇到不支持的纹理格式：跳过该贴图 + warning，不整体失败
- `export-report.json`：耗时、逐文件字节、纹理清单、跳过项、警告

**实测对照**（42MB 的资源包）：

| 阶段 | 文件数 | 产物体积 | 耗时 |
|---|---|---|---|
| 无 motion3 | 6 | 13.56 MB | 13.0 s |
| 含 motion3 | **40** | **16.55 MB** | **17.1 s** |

**内存**：单次导出峰值约 450 MB（4096² 纹理解码为主）。同一个包连续 4 次 RSS 收敛、
`heapUsed` 恒定 ⇒ **没有累积泄漏**；不同包连导会抬到 260 MB 左右，属平台期而非线性增长。

**motion3 生成**需要 moc3 的**真实参数 Id**，故把 Cubism Core（浏览器构建）放进 vm 沙箱：

- 模块：`tool/lib/cubism-core.mjs`；`getParameterIds(moc3)` 返回 `{ids, count, canvas}`
- **沙箱契约**：提供 `document.currentScript` / `location` / `atob` / 只认 `data:` 的 `XMLHttpRequest`
  （Core 的 Emscripten 外壳用它取内嵌 base64 的 WASM）；**不提供** `process` / `require`
  （避免它走 Node 分支去读一个 `data:` URI）
- **释放**：`try { model.release() } finally { moc._release() }`（顺序固定），导出流程每个包处理完都必须释放
- **曲线口径**（写进 `export-report.json`）：`total` = 全部绑定条数、`emitted` = 真正写入的曲线数、
  `skipped` = 绑定哈希认不出（如实计数，不是 bug）

**版权**：导出物为游戏原始素材，**仅供本地研究与个人使用**，不要再分发。
