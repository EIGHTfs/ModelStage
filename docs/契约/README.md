## 二、分层与契约对应

```
App Shell ── 状态契约（UI 状态存取与回填）
Domain    ── 数据与接口契约（Catalog / ModelEntry / 单一来源）
Render    ── 渲染面契约（StageSurface / 渲染器 / Document）
Assets    ── 插件契约 + 数据与接口契约（VirtualFS / AssetProvider）
跨层底线   ── 交互与实现约束（事件驱动 / 就绪信号 / 内联禁令 / 不变量）
```

数据流单向：`插件解析 → VirtualFS → Document(ready) → activate → 渲染`。
任何「反向触达核心内部」的写法都是契约违规（见插件与渲染面的禁止事项）。

## 三、契约层要解决的具体问题

右栏曾出现「只有 Spine 有效」，追下来是三类问题叠在一起：

| 类别 | 实例 | 归口 |
|---|---|---|
| 真引擎差异 | 调试绘制 8 项、初始缩放三模式为 Spine 专属 | 声明不构建（[渲染面](渲染面.md) §4.1） |
| 接线缺口 | 控件落地硬绑 Spine 舞台，切到 Live2D 后打到隐藏画布 | INV-01 |
| 声明与实现不符 | Live2D 声明支持某项但无实现 | 能力自检 + INV-04 |

契约层的作用是把后两类**变成可被测试抓到的违规**，而不是靠肉眼发现。

## 四、术语

| 术语 | 含义 |
|---|---|
| 渲染器 | 实现渲染面契约的对象（`spine` / `live2d`，将来 `three`） |
| Surface | `render/surface.js`：舞台几何、背景、渲染面切换与帧时钟的唯一所有者 |
| Document | 运行时唯一数据源；渲染器/编辑器/导出器之间唯一的交流媒介 |
| 资产提供者 | 插件角色之一，把容器解析成文件表 + 入口 |
| 能力键 | 控件声明所需能力的标识（`fps` / `dpr` / `msaa` / `textureFilter` / `presetFilter` / `pma` / `fit`） |
| 几何 | `{cssW, cssH, dpr, res}`，由 `Surface.geometry()` 单点产出 |
| 就绪信号 | 给机器读的阶段状态机（`pending → mounted → painted → settled → interactive / failed`） |

## 五、当前落地状态

**契约主体已全部闭合**，可核验的证据分布在各自的验收条款里。以下只列「仍有口径待定」的项：

| 项 | 状态 |
|---|---|
| 能力设置（`setSetting`/`getSetting` 为唯一落地口） | ✅ 全部经渲染器，能力自检零违规 |
| 非能力类的「内容选择 / 播放动作」 | ⚠️ **口径待定**：皮肤、混合模式、动作选择这类操作仍是「面板 → 渲染器实例」的直接调用，不走 `setSetting`。它们该扩成能力键，还是在契约里显式豁免，尚未决定 |
| 背景图索引写盘的非原子性 | ⚠️ 真实缺陷未修（纯色预设已原子化，背景图索引还没有 fsync） |

> （如「Spine 侧未接入 VirtualFS」「渲染器入参未用 Document」等）已在对应文档的修改记录里注明证据。
