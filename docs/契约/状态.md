# 契约 · 状态

> 本契约约束「UI 状态怎么存、怎么读回、DOM 重建后怎么恢复、写盘怎么保证不损坏用户数据」。
> 与《渲染面》讲控件能力声明不同：那边管「这个控件该不该出现」，这边管「它的值怎么活下来」。**两者正交**
> —— 一个控件可以有能力声明但不持久化，也可以持久化但无能力分叉。

---

## 一、状态项必须归入六类之一

盘点任何 UI 状态项，**必须**落进以下六类之一，不允许「说不太清」：

| 标记 | 含义 | 典型症状 |
|---|---|---|
| ✅ **完整** | 有写、有点读，且**重建后能回填** | — |
| ⚠️ **只写不读** | 写了但启动不读 | 改完刷新就白改 |
| ⚠️ **读的是死值** | 读的键没有任何写入点 | 读到的永远是初始值 |
| ❌ **未持久化** | 完全没存 | 刷新后回到默认 |
| ⚠️ **双份存储** | 两处各存一份 | 两处会漂，可能互相覆盖 |
| 🔶 **命令式回填（重建即丢）** | **写读都全、值也准**，但显示态靠一次性命令同步，DOM 重建后无人回填 | **引擎 / state 是对的，只有 DOM 显示错** |

### 🔶 这类为什么必须单列

前五类**判不出「值对了但显示错」这种故障**：它的写和读都在、值也是准的，坏的只是"显示"。

```
刷新后  stored=true / state.animLoop=true / isCycleLoop()=true / aria-checked=true
重建后  stored=true / state.animLoop=true / isCycleLoop()=true / aria-checked=**false**
```

按前五类，这一格只能填「✅ 完整」—— 而它恰恰是故障本身。所以必须单列这一类。

## 二、三条硬规则

### R1 · 单一真相源

```
UI 显示值 == 生效值 == 工厂里的值
```

**禁止**：

- 控件自己持有一份「我显示成什么」的副本
- 两处各存一份（漂移后无法判断该信谁）
- 「显示态」与「生效态」由两条不同路径各自更新

**判据**：`grep` 该状态项，写入路径只能有一条（工厂的 `set`）。

### R2 · 读回早于首次渲染

```
loadAll() 必须完成于第一次面板 DOM 构建之前（纯内存操作，不碰 DOM）
```

**禁止**：

- 先按 schema 默认值渲染，再用命令式补丁改（会闪，且重建就丢）
- 读回过程中触碰 DOM

**判据**：启动时序里 `loadAll` 的位置必须在 `rebuildPanelFor` 之前。

### R3 · apply 与 render 必须分离

```js
apply(value)   // 生效：下发给引擎/渲染器。必须幂等、可重复调用
render(value)  // 显示：更新面板控件的视觉态。必须能对「当前已存在的 DOM」重放
```

**为什么**：这两件事的失败模式完全不同 —— `apply` 错是「功能不对」，`render` 错是「看起来不对」。
把两者混在一个命令里，必然出现「值对了但显示错」（或反过来），且无法单独修复。

**禁止**：把 `render` 写成一次性副作用（如只在某个事件回调里调一次）。

## 三、面板 DOM 重建必须回填

**任何**面板重建入口，完成后**必须**做两件事：

```js
// ① 派发事件
document.dispatchEvent(new CustomEvent('panel:rebuilt'))

// ② 工厂回填显示态（幂等）
uiState.applyAll({ render: true })
```

**禁止**：

- 新增重建入口却不派发事件（新入口 = 新的丢显示态场景）
- 用「在重建函数里手动 `setChecked`」代替（那是命令式的老坑）

### 3.1 派发点收敛到唯一汇聚处

`mountPanel` 全项目只有一个调用方：`panel-settings.js` 的 `rebuildPanelFor()`。
所以派发与回填**只在 `rebuildPanelFor()` 里实现一处**即可覆盖全部重建。

**为什么不写成「每个调用点各写一次」**：

```
两处复制 = 两处都可能漏；一个汇聚点 = 漏不了
契约的目的是「防止遗漏」，不是「字面覆盖每种写法」
```

**若未来新增直调 `mountPanel` 的入口**（绕过 `rebuildPanelFor`）：
该入口必须同样派发 `panel:rebuilt` + `applyAll({render:true})`，并更新本节说明「汇聚点已不止一处」。

**判据**：

```bash
# ① mountPanel 的调用方只允许是 rebuildPanelFor
grep -rn "mountPanel(" src/web/ | grep -v "function mountPanel"
# 期望：只命中 panel-settings.js 的 rebuildPanelFor 内部一行

# ② 汇聚点本身必须两件事齐备
grep -A5 "function rebuildPanelFor" src/web/panel/panel-settings.js | grep -c "panel:rebuilt\|applyAll"
# 期望：≥2
```

## 四、能力不支持时的语义：**保留不生效，禁止回落默认**

```
读回值不被当前渲染面支持（如 Live2D 面不支持 skin）
  ⇒ 值**保留**
  ⇒ **不 apply、不 render**（面板上对应控件本就置灰 / 不构建）
  ⇒ 切回支持的面时**再 apply**
```

**禁止**：回落默认。

**理由**：回落默认 = **永久丢失用户选择**。用户在 Spine 面设了皮肤，切到 Live2D（不支持）再切回 Spine，皮肤必须还在。

**实现**：SPEC 里声明 `capability` 键，`applyAll` 时按当前渲染器能力过滤。

## 五、默认值权威：schema 派生 + 启动断言

```
默认值的唯一来源 = schema.js（控件声明里的 defaultOn / defaultValue）
工厂 SPEC 的 default **从 schema 派生**，不独立写一份
启动时断言「SPEC.default === schema.default」，不一致直接报错
```

**禁止**：schema 与 SPEC 各写一份默认值（必然漂移）。

**为什么加断言而不是只靠派生**：派生可能被后来的改动破坏（有人为了省事在 SPEC 里直接写字面量），
**断言是唯一能发现这种破坏的手段**。

## 六、验收要求（每个持久化项都要有）

| # | 用例 | 判据 |
|---|---|---|
| A1 | **重建后回填** | 开某状态 → `rebuildPanelFor()` → `state` 与 **DOM 显示态**都等于用户值 |
| A2 | 刷新往返 | 开 → 刷新 → `stored / state / DOM 显示态` 三者全对 |
| A3 | **不闪默认值（控件值）** | 刷新后 0~3s 每 100ms 采样，**不得出现 `true→false→true`**（首帧即终值） |
| A3b | **不闪默认值（布局态）** | 刷新过程中**逐 rAF** 采样左右面板可见性：**`data-layout-ready` 之前不得出现「可见」帧** |
| A4 | 脏数据回落 | 塞非法值 → 回落 default、无 `console.error`、页面可用 |
| A5 | 非法 JSON | 塞 `'{坏的'` → 回落全默认且不抛 |
| A6 | 去抖不丢最后一次 | 连续改 20 次后立刻 `visibilitychange→hidden` → 重载后值 = 最后一次 |
| A7 | **反向自证** | **临时删掉回填那条 → A1 必须变红**。不红 = 门禁没测到这个 bug |

**A7 不是可选项**：没有反向自证的门禁，无法证明它测的是真 bug 而不是「本来就这样」。

### 6.1 A3b 的由来：布局态也会闪

**A3 原本只管「控件值」**，但布局态同样会闪：隐藏左右面板 → 刷新 → 会看到「出现 → 隐藏」。

```
根因（与控件值闪烁同源，但发生在更早的位置）：
  index.html 的 #left-panel / #right-panel 默认**没有** is-hidden
    ⇒ 浏览器首帧就把它们画出来
  main.js 是 ES module，异步执行
    ⇒ 到最后才 applyLayout() 加 is-hidden
  ⇒ 中间那一段用户看到「显示 → 隐藏」
```

**实测（逐 rAF 采样）**：

| | 修复态 | 破环态（CSS 改回 visible） |
|---|---|---|
| 首帧 | `t=30ms vis=hidden ready=''` | `t=54ms vis=visible ready=''` |
| `layoutReady` 之前「可见」帧数 | **0** | **39 / 40** |
| `visible→hidden` 翻转 | 无 | 有 |

**修法三条**：

```css
/* ① CSS 层在读回前先隐藏 */
html:not([data-layout-ready]) #left-panel,
html:not([data-layout-ready]) #right-panel { visibility: hidden; }
```

```js
// ② 读回后放行；**必须 try/finally** —— 否则 applyLayout 抛异常会让左右栏永久不可见
try { applyLayout(uiState.getLayout()); }
finally { document.documentElement.dataset.layoutReady = '1'; }
```

```
③ 用 visibility 不用 display：后者读回时引起重排，页面会跳一下
```

**这是同类问题第三次**（控件值闪烁 → 循环开关显示错 → 布局闪烁）。
**共同模式**：**任何「UI 初始态依赖异步读回」的东西，都会先被浏览器按默认画一遍。**
修法统一为「CSS 层先遮住 + 读回后放行 + try/finally 兜底」。

### 6.2 例外：纯重构步骤允许用「结构性判据」替代反向自证

**实测案例**：删掉 `suspendPanelPersist` 旁路、把默认值回放挪进工厂这一步，反向自证**无法变红**：

```
把 applyAll 改回「只回放默认值」 → 采样序列与正常版完全一致（0 翻转）
原因：默认值回放与用户值读回都在首帧前同帧完成，浏览器不绘制中间态
⇒ 观测层没有可红判据
```

**所以**：纯重构（行为不变）的步骤允许用**结构性判据**替代：

| 可用判据 | 例 |
|---|---|
| 关键字归零 | `grep suspendPanelPersist src/` → 0 命中（只剩注释说明） |
| 数据结构形态 | `panel` 段不再含 `uiTheme` / `background`（双份存储已消除） |
| 既有门禁保绿 | A1 / A2 / A3 全部仍绿 |

**但必须满足三条**：

```
① 明确写出「为什么反向自证不可达」（不能只写「测不出来」）
② 结构性判据要能证明「重构真的发生了」（不是「看起来一样」）
③ 原有门禁仍须全绿（重构不能把已有保障改弱）
```

**反面**：把「懒得造破坏版」写成「不可达」是敷衍。
**判据是「破坏版与正常版观测结果相同」，不是「我没做破坏版」。**

## 七、写盘与迁移纪律

### 7.1 去抖 + flush

```
写盘去抖（建议 150ms）+ visibilitychange / pagehide 时同步 flush
```

**禁止**：只靠防抖 —— 「改完秒关页面」会丢最后一次。

### 7.2 🔴 写入凭证：没有成功读回过就不许写盘

**典型事故**：

```
localStorage 里有 4 个脏值
  ↓
loadAll() 把这 4 个全拒（校验失败）
  ↓
values 变成空
  ↓
页面卸载时 flush() 无条件写出 panel: {}
  ↓
**其余全部设置被清空**
```

**根因**：`flush()` 不知道「这次读回是否成功过」，把「我手里没有值」当成了「用户的值是空」。

**必须的修法（两条都要）**：

```js
① 被拒的键 → **回落默认值并记进内存**（不能留空）
② loadedOnce === false 时 → **拒绝写盘**
```

**判据**：

```
注入 4 个非法值 → 卸载页面 → 存储里的其余键必须还在（不能被清空）
并且被拒的 4 个键回落为 default（不是消失）
```

**推广规则**：**任何「写盘」动作都必须先有「成功读回」的凭证。**
凡「读失败后写回」的路径（配置导入、缓存回写、状态落盘）都有这个风险：
**读失败被误当成「没有数据」，然后把空数据写回去覆盖原数据。**

### 7.3 键迁移

```
旧键 → 新键：幂等 + **写成功之后才删旧键** + 失败不删
```

**禁止**：一次异常就把用户偏好清零。

### 7.4 共享键红线

```
roster 的 tree-state.v1 结构（lastByGame{游戏:变体id} + 兼容 lastModelId）**一字不改**，只能改由谁读写
```

**理由**：改结构 = 用户上次选中的模型丢失。

## 八、静默 catch 必须能区分「预期失败」与「代码 bug」

### 两次真实事故（同一模式，都靠人工操作才发现）

```
坑①  drag.js 里 `import * as uiState` 漏插（锚点未匹配）
      → 调用 uiState.getPanelPos() 抛 ReferenceError
      → 被 `catch { /* 忽略 */ }` 吞掉
      → 位置既存不下也读不回，拖动「看起来正常」但没记忆

坑②  setCollapsed 定义在 wireControls() 内，却在 mountDebugPanel 直接调
      → 抛 ReferenceError（setCollapsed is not defined）
      → 被 try/catch 吞掉 → 「收起怎么都记不住」（工厂 true、DOM 永远 false）

共同点：`node --check` 查不出未定义标识符；测试绿；只有人工拖一次/收一次才发现
```

### 规则

**禁止** `catch { /* 忽略 */ }` 对**任何**异常都吞掉。必须区分：

| 异常类型 | 处置 |
|---|---|
| **预期失败**（`QuotaExceededError`、`SecurityError`、元素不存在、API 不支持） | 静默降级合理，但**注释写明是哪一类** |
| **非预期失败**（`ReferenceError` / `TypeError` / `SyntaxError`） | **这是 bug，必须暴露** |

**做法（二选一，或都做）**：

```js
// A. 按类型判别，非预期写可观测出口
try { ... } catch (e) {
  const expected = e instanceof DOMException || (e && /Quota|Security/.test(e.name || ''));
  if (!expected) {
    try { document.documentElement.dataset.lastStorageError = String(e && e.message); } catch {}
  }
}

// B. 全局静默错误计数器（可查询）
//   __WEB__.silentErrors → [{ tag, message, at }]，最多保留 N 条
```

**判据**：

```
故意把某个 uiState 调用写成不存在的标识符 → 必须能在 dataset 或 __WEB__.silentErrors 里看到
（而不是「什么都没发生」）
```

**为什么这条进状态契约而不是通用规范**：这类静默失败**最容易发生在状态读写路径上** ——
状态读写天然要 try/catch（存储随时可能不可用），天然要用 `catch` 兜底，天然会把 bug 一起兜进去。
**两次事故都在状态层，不是巧合。**

## 九、当前实现现状

```
活动存储键 3 个：
  modelstage-settings-v2            面板设置 / 主题 / 背景 / 视图参数 / 调试浮层（位置+档位）
  modelstage.tree-state.v1     左栏树展开态 + 上次选中的模型
  modelstage.dirpicker.last    目录选择器上次位置

待清理旧键 2 个（不再读取，仅由工厂清理入口发现后删除）：
  spine-viewer-debug-panel-pos / spine-viewer-debug-levels
```

**状态类别分布**：绝大多数面板项已是 ✅ 完整（统一工厂 + `panel:rebuilt` 回填）；
剩余 ❌ 未持久化的项为「当前动作」——**这是有意的**：当前动作是模型属性，
记住它反而会让人困惑（换个模型后"上次那个动作"没有意义）。

- 建立本契约的起因：一个 P0「开循环 → 刷新 → 动作循环但 UI 显示关」。根因不是「没读回」，

  原 debug 位置与档位两个独立键已并入 `view-settings-v2`，旧键只保留清理逻辑。
