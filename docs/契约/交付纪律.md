# 交付纪律（代码质量与复用）

> 适用于**所有**任务（功能 / 重构 / 修复 / 文档）。违反任一条的交付都算未完成，不因"功能能跑"而豁免。

---

## 一、不只是「功能完成」

```
每完成一小步，就用审计工具扫**本次 diff**（code_audit scope=diff），顺手优化本次触及的代码：
  · 短变量名：语义能明确就改（p → reqPath、el → element、c → color），只改动到的函数
  · 魔数：时间 / 尺寸 / 阈值提成命名常量并注释含义（数据表常量如 CRC 表、像素上限不动）
  · 重复调用：同一实参在同函数内重复调用的，合并成局部变量
不留"以后再清"的尾巴 —— 那一版永远不会来
```

**判据**：本次 diff 里新增/修改的代码，读的人不需要猜任何数字或名字的含义。

---

## 二、禁止相似功能多处实现

```
动手前先搜：这个功能是否已有同类实现（工厂 / 公共函数 / 纯函数库 / 既有注册模式）
  有 ⇒ 必须复用
  不能复用 ⇒ 交付时写明"为什么 X 不能用"，具体到 文件:函数名
```

**本项目真实反例**（都发生过，代价是两处真相、改一处漏一处）：

```
· Live2D 清单路径在两个模块各实现一遍（models.mjs 与 live2d.mjs）
· 内存条定位逻辑：舞台版与面板版各一套，改位置时漏掉一处
· DOM 工厂 el() 在 panel/dom.js、roster/rows.js、debug/panel.js 三处重复
```

---

## 三、新增功能优先并入既有工厂 / 公共层

```
优先顺序：扩展既有工厂的参数  >  并入既有公共函数  >  新增独立模块
不许因为"改既有代码麻烦"就新开一条并行路径 —— 并行路径 = 未来的两份真相
```

**判据**：交付时能列出「复用了 X（文件:函数）」。若一项都没复用，必须给出理由，而不是默认新建。

---

## 四、交付时必报的三项

```
1. 复用了哪些既有函数 / 工厂（文件:函数名）
2. 新增了什么，为什么必须新增
3. 本次顺手优化了什么（短名 / 魔数 / 重复调用），以及 diff 审计结果（blocker / warning 数）
```

---

## 五、与其它约束的关系

```
· 行为等价优先于整洁：重构只允许改结构，不改行为（判据写进各自任务）
· 顺手优化只做"触及范围"：不为了改名去动未被本次改动碰到的代码（防止 diff 失控）
· 与《交互与实现约束》《测试脚本结构》并列：那两份管"怎么写"，这份管"交付前做到什么程度"
```
---

## 六、验证不得打断正在使用的实例

```
· 用户在 8804 上看着页面时，**禁止**为验证而 `web.sh restart` 那个实例 ——
  一次重启会让页面所有在途请求失败，实测后果：Live2D 运行时脚本加载被打断 ⇒
  之后每次激活都失败，只能刷新（2026-10-27 真实事故）
· 优先用**独立实例**验证（独立端口 + 独立数据根）；确实必须重启主实例时：
  先确认没人正在用，且**一次改动只重启一次**（不要"改一行重启一次"地刷）
· 前端侧容错不能替代这条：瞬时失败不该被永久缓存（见 live2d/pixi-app.js 的 libsReady 修复），
  但"页面不会坏"不等于"可以随便重启"
```
---

## 七、删改代码禁止"按索引切片"

```
❌ 禁止用 `text[:start] + text[end:]`、正则批量替换、按行号区间删除的方式改代码
   —— 字节/行号偏移一旦算错，会连带删掉区间内的其它定义或导出，且**语法仍合法**，
     直到运行时才炸（本项目已发生两次：一次删掉 ui-state.js 的导出，一次删掉
     panel-settings.js 的 bindPluginPanelRebuild ⇒ 页面停在半初始化）
✅ 一律用 edit 工具做**精确文本替换**：锚点必须唯一命中，命中不到就报错，不静默跳过
```

**改完必须做符号完整性检查**（尤其动初始化路径上的文件：`main.js` / `panel-settings.js` /
`spine.js` / `live2d.js`）：

```
1. 每个"被调用但可能刚被删"的函数名 grep 一遍：定义 1 处 + 调用 ≥1 处
2. node --check
3. 真跑一次页面，确认结构完整（面板组数、控件数、自检 violations 为空）
   —— 不看这一条就继续下一步，等于把错误往后传
```
