# 契约 · 数据与接口

> 本契约约束「数据从哪来、位置如何解析、接口口径是什么」，含三部分：
> **VirtualFS**（资源位置解析的唯一入口）、**单一数据源**（模型清单只走一个接口）、**纯色预设 API**。
>
> **一句话原则**：同一事实只允许有一个来源。凡是"两个地方都能回答同一个问题"的设计，
> 迟早会不一致；不一致时前端表现为"数据凭空消失"，而**两边各自都"工作正常"**，是最难排查的一类。
>
> 关联：[插件契约](插件.md) · [渲染面契约](渲染面.md)

# 第一部分 · VirtualFS（vfs/v1）

**一句话职责**：让「内存里的文件」和「网络上的文件」对渲染器长得一样。

## 1.1 定位

| 事 | 归属 |
|---|---|
| 注册一段虚拟目录、按 URL 解析出可用地址 | **VirtualFS（核心）** |
| 提供文件内容（Blob / 字符串） | **AssetProvider（插件）**，经 `resolve()` 交给 VirtualFS |
| 按 URL 加载资源 | **渲染器 / 加载器**，只问 VirtualFS，再回落真实 URL |
| patch 任何加载器 / 拦截 fetch / 装全局中间件 | ❌ 无人允许（插件尤其禁止） |

VirtualFS 是「资源位置解析」的**唯一入口**；插件与渲染器之间不存在第二条通道。

## 1.2 接口

```js
createVirtualFS({ createObjectURL?, revokeObjectURL? }) → {
  register(prefix, files)   // files: Map<relPath, Blob | string>
  resolve(url) → string | null
  revoke(prefix)
  stats() → { prefixes, entries, createdUrls, hits, misses }
}
```

| 方法 | 语义 | 约束 |
|---|---|---|
| `register(prefix, files)` | 登记一个虚拟前缀下的文件表 | **prefix 全局唯一**；重复注册**直接抛错**（不静默覆盖） |
| `resolve(url)` | 命中返回可用地址（Blob URL），未命中返回 `null` | 只解析**相对引用与该前缀下路径**；绝对 URL 与网络资源照旧直连 |
| `revoke(prefix)` | 释放该前缀全部 Blob URL 并注销前缀 | 之后 `resolve` 必须返回 `null`；与模型生命周期绑定 |
| `stats()` | 观测：哪些前缀在册、建了多少 URL、命中/未命中次数 | 排查「这张图来自内存还是网络」 |

实现要点（已落地）：

1. **Blob URL 懒创建 + 缓存**：第一次 `resolve` 才创建，重复解析复用同一 URL
2. **路径规范化**：解码、去 `./` `../`、大小写与尾斜杠归一，避免同一文件因写法不同解析失败
3. 注入依赖 `createObjectURL / revokeObjectURL` ⇒ 无浏览器环境可单测

## 1.3 生命周期规则

| 时机 | 动作 |
|---|---|
| 插件解析出一个模型包 | `register(prefix, files)`；`prefix` 含插件 id 与资源根，保证跨插件不冲突 |
| 该模型装载完成、开始渲染 | 保持注册 |
| **切换模型 / 卸载模型** | 必须 `revoke(该前缀)`，否则 Blob 泄漏（切 20 个包就攒 20 份内存） |
| 渲染失败 | 同样 `revoke`（失败也不留） |

`prefix` 命名约定：`vfs://<providerId>/<rootId>/<相对目录>/`。

## 1.4 与渲染器的关系（硬约束）

```
渲染器加载任何资源前：
  const hit = vfs.resolve(url)
  hit ? 用 hit : 用原 url
```

- 渲染器**不关心**资源从哪来（磁盘、内存、解包）
- 未命中即回落原 URL ⇒ **插件整体失效也不影响基础能力**（可退化）
- 渲染器不得自己实现「内存资源解析」，也不得接收插件传进来的函数

## 1.5 为什么不用「插件装加载器中间件」

| 问题 | 后果 |
|---|---|
| 插件必须知道核心用哪个加载器 | 核心换实现 ⇒ 插件静默失效（只 warn） |
| 共享一个隐式全局状态 | 无法独立测试插件 |
| 拦截点在库内部 | 出问题时两边都像对的，最难查的一类 |

VirtualFS 把这件事变成**一次显式函数调用**（`resolve`），因此可测、可观测、可退化。

## 1.6 覆盖范围

**Spine 与 Live2D 均已覆盖全部文件类型。**

| 文件类型 | Spine | Live2D |
|---|---|---|
| 入口（`main.json` / `model3.json`） | ✅ | ✅ |
| 骨架（`skel` / `moc3`） | ✅ | ✅ |
| 图集 / 贴图 | ✅ | ✅ |
| 动作 / 物理（`motion3` / `physics3`） | ✅ | ✅ |

两面的介入点不同，但都是单点：

```
Spine     fetchBinary 里做单一前置（骨架 / atlas / 贴图页一次接上）
Live2D    覆盖 settings.resolveURL —— 该库所有内部引用的解析都收敛到这一个钩子
          （moc3 走 _live2d_load(resolveURL(moc))、贴图与 physics 同钩子、
           动作经 FileLoader 的 settings.resolveURL(url)）
```

覆盖的判定证据（**不接受「代码里有 resolve」**）：

```
装载段  hits 必须覆盖入口 + 骨架 + 贴图 + physics，misses = 0
播放段  动作是懒加载：播一个动作 hits 再涨对应条数；未播的不命中属正常
断网    把内部引用的基址换成不可达地址（入口仍从 VFS 来）时仍能装载且画面非空
        —— Live2D 实测 /files/ 网络请求 0 条
```

### 真实限制（一条）

```
new URL('textures/b.bin', 'blob:http://host/uuid') → Invalid URL
blob: 不能作为相对引用的基址 ⇒ 不能简单把「基址」换成 blob 地址
```

### 一个已纠正的误判

```
误判：「该库不接受绝对 blob: 引用」
实测：不成立。用 blob 供 moc3 与贴图时，drawables 408 / coreCanvas 14×14 / textures 1，
      与 http 变体逐项相同。
当时的 Network error 实为 model3.json 内的引用被 url.resolve 拼坏（bridge 拼接 bug），
与 blob 本身无关。
```

**可行介入点（实测）**：该库所有内部文件（moc3 / 贴图 / physics / 动作）的相对引用解析
全部收敛到单一钩子 `settings.resolveURL`（库自带的「拖文件夹上传」功能就是覆盖它）。
把它覆盖成「查 VFS，命中返回 blob，未命中回落网络」即可，无需 patch fetch 或装中间件。

### 对插件（AssetProvider）的意义

```
插件 resolve(file) 返回的 files 表，两台渲染器都能完整消费：
  · Spine   骨架 / atlas / 贴图页 全经 VFS
  · Live2D  入口 + moc3 + 贴图 + physics + 动作 全经 VFS
⇒ 插件产出可被完整消费，不再出现「插件给了文件、渲染器却仍去网络取」的半可用状态
```

## 1.7 验收条款

| # | 条款 | 验证 |
|---|---|---|
| V1 | `register` 重复 prefix 抛错，且不改动已注册内容 | 单测 |
| V2 | `resolve` 未命中返回 `null`，调用方回落原 URL | 单测 + 关插件后加载普通模型仍可用 |
| V3 | `revoke` 后再 `resolve` 返回 `null`，且 Blob URL 被释放 | 单测 + `stats().createdUrls` 变化 |
| V4 | 同一文件不同写法（`./a.png` / `a.png` / 编码）解析到同一 URL | 单测 |
| V5 | 切换模型时旧前缀被 revoke（无 Blob 累积） | 连开 5 个资源包后 `stats()` |
| V6 | 渲染器内无任何「自定义加载器拦截」代码 | 静态 grep |

# 第二部分 · 单一数据源（模型清单只走 `/api/catalog`）

## 2.1 规则

```
前端业务代码拿「某个根 / 某个游戏下的模型清单」，只能走 /api/catalog。
禁止直调单路扫描接口：/api/spine/models、/api/live2d/models。
```

`/api/catalog` 内部已合并三类来源：spine 骨架、live2d 模型、容器类条目（如 UnityFS 单文件包），
输出统一 `ModelEntry`。**「这个根下有哪些模型」只有一个正确答案来源。**

### 为什么必须只有一个来源

```
左栏「碧蓝航线」是**同名根合并节点**：
  azurlane(119 个 live2d) + azurlane_spine(194 个 spine) + azurlane_bundle(19 个容器条目)
  ⇒ 树上共 332 个变体
⇒ 任何「按单个 rootId 取清单」的写法都只能拿到其中一份
⇒ 用户看到的现象：树上有 332 个变体，点翻页却提示「这个根没有可用模型」
```

这不是粗心，而是**命名与双入口导致的必然错误**：`/api/models` 这个名字声称返回 models，
实际只返回 Spine —— 名字在撒谎，调用方无法从名字看出差异。

## 2.2 正确的改法

| 想做什么 | 做法 |
|---|---|
| 要「某个根 / 某个游戏下的全部模型」 | `GET /api/catalog?root=<id>` |
| 要「整棵树（游戏 → 角色 → 变体）」 | `GET /api/catalog`（或名册快照 API） |
| 确实只需要某一种渲染器 | **在服务端**按 `kind` 过滤 catalog 结果，**不要**在客户端挑接口 |
| 要验证「扫描器本身」对不对 | 见 2.3 的例外 |

## 2.3 允许的例外（仅两类）

```
① 诊断探针：src/web/debug/**（调试面板 / HUD 的职责就是看单路细节）
② 测试脚本：test/**（它们的目的正是**分别**验证两个扫描器，走 catalog 反而看不到单路细节）
```

**边界（收紧过的）**：

- 例外按**目录**登记，不按「文件里有 `__WEB__` 出口」这种模糊条件判断
  （前端几乎所有文件都有 `__WEB__` 暴露，判不准；按目录登记可审计、可 grep、不留模糊地带）。
- 新增例外必须同时改门禁脚本里的 `EXCLUDE_DIRS` / `EXCLUDE_FILES` 并写明理由
  —— 例外是**显式清单**，不是「默认允许」。
- **注释不算违规**：历史教训的注释里需要写出旧路径时，门禁会剥离注释后再匹配，不误报。

## 2.4 验收（可自动检查）

```bash
node tool/check-single-source.mjs          # 人工 / CI 直接跑
node tool/check-single-source.mjs --json   # 机器可读
```

- 该脚本是 `tool/test-all.mjs` 的**前置检查**：失败即中止，**不占回归套件名额**
  （套件数是回归清单，「全绿」是可读信号；静态约束挂在门禁层，不该稀释它）。
- **门禁必须自证会变红**（否则等于没做）：在 `src/web/app/` 任意文件插入
  `const x = fetch('/api/spine/models?root=x');` ⇒ 门禁必须失败并指出 `文件:行`；删掉 ⇒ 必须通过。
- 匹配方式：**先剥离注释、保留字符串内容**，再用正向匹配逐条报。
  不要用 `grep -v "api/live2d/models"` 这类反向过滤 —— 同一行里同时出现两个路径时整行会被过滤掉，
  造成假阴性。

# 第三部分 · 纯色背景预设 API

> 前端（背景面板）与本服务端按本节对齐，**字段名不得单方改动**。
>
> 实现：`src/server/routes/background-solids.mjs`（路由）+ `src/server/http/background-solids.mjs`（数据层）
> 数据：`data/backgrounds/solids.json`（运行时数据，不入库）
> 测试：`test/background-solids.test.mjs`（13 条，全隔离在临时目录）

## 3.1 接口

| 方法 | 路径 | 入参 | 成功响应 |
|---|---|---|---|
| GET | `/api/backgrounds/solids` | — | `200 { items: [{ id, name, color, createdAt }] }` |
| POST | `/api/backgrounds/solids` | `{ name, color }` | `200 { item }` |
| POST | `/api/backgrounds/solids/rename` | `{ id, name }` | `200 { item }` |
| POST | `/api/backgrounds/solids/remove` | `{ id }` | `200 { removed: true, id }` |
| POST | `/api/backgrounds/solids/reset` | — | `200 { items }`（重建默认 5 个） |

**字段语义**

- `id`：服务端生成；**改名 / 改色不变**。默认 5 条用确定性 slug（`solid-default-carbon` 等），
  因为 `reset` 是幂等操作，产出变化的 id 反直觉，且确定性 id 让测试能直接断言。
- `color`：`#RRGGBB`（6 位）。输入接受大小写，**输出统一小写**。
- `createdAt`：epoch ms（number）。
- 失败一律 `{ error: "<可直接展示给用户的中文文案>" }`，前端原样显示。

## 3.2 校验规则（服务端唯一权威，前端不要另写一套）

| 项 | 规则 |
|---|---|
| color | 必须匹配 `^#[0-9a-fA-F]{6}$`；**3 位缩写不接受**（避免前端要处理两种形态） |
| name | 去首尾空格后非空、≤30 字符（按字符数，中文一个字算一个） |
| 重名 | **大小写敏感**去重。新增查重；**改名也查重（排除自身）** |
| 数量 | 上限 50 个 |

错误文案（前端原样显示，不要写成 `invalid color` 这种给程序看的话）：

```
颜色格式不对，应为 #RRGGBB 形式（如 #3d8f5c）
名称不能为空
名称太长（最多 30 个字，当前 N 个）
已经有同名颜色了（"炭黑"），换个名字
颜色数量已达上限（最多 50 个），先删几个再加
找不到这个颜色（id=xxx），可能已被删除
读取颜色数据失败，本次操作已取消（不会覆盖你的数据）
```

## 3.3 落盘与自愈

- **原子写**：写 `<file>.tmp` → `fsync` → `rename` 覆盖（见 `src/server/http/atomic-json.mjs`）。
  fsync 不能省：`rename` 的原子性只保证「看到旧文件或新文件」，不保证数据块已落盘。
  **纯色预设索引与背景图索引都走这一条**（`writeJsonAtomic`）；上传的图片本体走
  `writeFileAtomic`（同一顺序的二进制版）——图片是 0 字节时 `resolveFile` 只做 `isFile()`
  校验、会认它存在，所以图片不 fsync 就变成「索引有、图片空、永不自愈」。
- **串行队列**：写操作排队（统一用 `createSerialQueue()`），避免两次并发修改互相覆盖。
- **自愈分级**：

| 情况 | 行为 |
|---|---|
| 文件不存在 | 写默认 5 条（首次初始化） |
| JSON 解析失败 / `items` 不是数组 | **先把坏文件备份成 `solids.corrupt-<epoch>.json`**，再用默认 5 条重建 |
| 单条缺 `id`/`name`/`color` 或格式非法 | **只丢该条**（其余保留）+ warn 日志；不写 corrupt 备份 |
| 读时 IO 失败（EACCES/EIO…） | **不重建、不写盘**，返回 `500 { error }` |

- **`reset` 前备份**：当前文件先复制成 `solids.bak-<epoch>.json` 再重建默认。
- **备份轮转**：`solids.bak-*` 与 `solids.corrupt-*` **各自只保留最近 5 份**，更早的删除。
  不轮转的话点十次 reset 就堆十个文件（都是运行数据，不入库、只占空间）。

> **为什么「读失败」与「没有数据」必须分开**：读失败时写默认值回去 = 把用户的列表清空了。
> 测试用「非法输入后数据文件逐字节不变」与「corrupt 备份内容逐字节等于原始坏内容」钉住这条。

## 3.4 并发语义

```
本接口保证 **单实例内**串行一致（同一进程内的并发请求不会丢条目）。
**多实例共享同一 dataDir 时不保证** —— 没有文件锁。
若将来要支持多实例，此处需要文件锁或「单写者进程」模型。
```

为什么不加锁文件：**「进程崩了锁没释放」比「并发丢一条颜色」更麻烦**，
当前部署形态是单实例本地预览器，收益不抵风险。

## 3.5 验收

```bash
node --test test/background-solids.test.mjs      # 13 条
node tool/test-all.mjs --only background-solids  # 走统一入口（含 skip/fail 口径）
```

覆盖：初始化 / 新增 / 改名（id·color 不变）/ 删除 / 恢复默认 / 非法 color（含「文件逐字节不变」）/
空名·超长·重名（含改名撞名）/ 数量上限 / 坏 JSON 自愈 / 读失败不覆盖 /
并发不丢 / 文件 0644 与目录 0755 / 备份轮转各留 5 份。

## 3.6 已知未做（避免被当成缺陷重复提）

- 没有 ETag / `?refresh=1`：几 KB 文件每次读没有 I/O 压力，引入缓存层只会带来「何时失效」的新问题。
