# 契约 · 插件（plugin/v1）

> 本契约约束「核心如何给插件开门、插件如何从门进出」，含插件清单、注册、资产提供者（容器解析）三个部分。
> 原「插件契约 / 资产提供者契约」已合并至此（后者只是前者的一个角色实现）。
>
> **一句话边界**：核心给插件开一扇门（暴露接口），插件从这扇门进出；**墙上不许凿洞**。
>
> 关联：[渲染面契约](渲染面.md) · [数据与接口契约](数据与接口.md)

---

## 一、五类角色

插件按能力注册，角色由清单里的 `provides` 声明：

```jsonc
// plugins/<id>/plugin.json
{ "id": "unity-live2d-bundle", "provides": ["asset-provider"] }
{ "id": "spine-editor",        "provides": ["editor", "exporter"] }
{ "id": "my-panel",            "provides": ["panel"] }
```

| 角色 | 核心暴露的接口 | 插件职责 | 现状 |
|---|---|---|---|
| `asset-provider` | `canHandle(file)` / `resolve(file)` + 宿主注入的取资源能力 | 容器 → 文件映射 | **已落地**：宿主 `infra/plugin-host.js` 已接线（`/api/plugins` → 注入 `files[]` → `register` → prefilter/findProvider/materialize），bundle 类资源已进渲染链路 |
| `renderer` | `mount(document, host)` / `unmount()` | 渲染一类内容 | 核心内部实现，**未开放**给插件注册 |
| `editor` | `Document` 读写 + `applyCommand(cmd)` | 修改模型数据 | 留位（不实现） |
| `exporter` | `Document` 只读 + 写输出 | 导出 skel/atlas/json/图片 | 留位 |
| `panel` | `mountPanel(slot)` | 往右栏/工具栏注入 UI | 留位 |

一个插件可同时提供多种角色；核心按 `provides` 注册进对应注册表；**未声明角色 = 无效注册**。

## 二、清单契约（`plugin.json`）

| 字段 | 类型 | 必选 | 语义 |
|---|---|---|---|
| `id` | `string` | ✅ | 与目录名一致；重复注册被拒绝（不覆盖已有） |
| `name` | `string` | ✅ | 人类可读名 |
| `provides` | `string[]` | ✅ | 角色列表；决定核心去哪个注册表 |
| `label` | `string` | 可选 | 角色库变体标签文字；缺省回落 `id`。**配色由宿主决定**，插件不自创 |
| `version` | `number` | 可选 | 清单版本，原样透传前端 |
| `entry` / `files` | `string` / `string[]` | 可选 | 加载优先级 `files[]` → `entry` → `index.js`（按数组顺序注入） |
| `fileKinds` | `string[]` | 有解析能力时必填 | 可读取的容器种类；空数组＝只注册不参与解析 |
| `produces` | `object` | 有解析能力时必填 | `{ kind, entry, memory? }`，见 §三 |
| `assets` | `string[]` | 可选 | 插件自带数据文件（如 `profiles/*.json`） |
| `errorCodes` | `string[]` | 可选 | 可能抛出的错误码自描述 |

### 2.2 内存声明：`produces.memory`（准入代价由插件说，不由核心猜）

解包要吃掉多少内存，**只有解析容器的插件知道**（它看得到纹理张数/尺寸、moc3 大小、解压后容器多大）。
核心不该拿「源文件大小」去猜 —— 实测证明那个变量解释力很弱（R² 0.695 vs 0.764 对比见设计文档）。

```jsonc
produces: {
  kind: 'live2d',
  entry: 'model3.json',
  // 可选：声明本容器解包的**内存代价**。三个字段都可独立省略。
  memory: {
    decompressedBytes,   // 解压后容器总大小（由 blocksInfo 求和得出，**不需要真的解压数据块**）
    rgbaBytes,           // Σ(w × h × 4)，容器里所有纹理解码后的裸像素总量
    peakBytes,           // 可选：峰值上限。插件自己更准时用这个，核心直接采信
  },
}
```

**核心的两段回落**（顺序固定）：

```
① 声明了 peakBytes  → 直接采信（插件最懂自己的容器），不叠加任何安全垫
② 什么都没声明      → 回落到「按源文件大小 × 分段倍数」（粗估兜底，既有行为，保证不倒退）
```

**核心不维护任何预估模型**：不同插件的容器结构完全不同（UnityFS 块表 / ZIP 中央目录 / 纯目录），
一张核心侧通用表套所有插件必然对谁都不准，且每加一个插件都要重标定一次。
所以「算得准不准」是**插件自己的责任** —— 插件应当声明 `peakBytes`；不声明就走粗估兜底，
偏差也由该插件承担。核心只做一次比较：`声明峰值 vs 预算`。

> `decompressedBytes` / `rgbaBytes` 仍保留为**可选的诊断与自查字段**（供插件自己算 `peakBytes`
> 时使用，也便于人工核对），但核心不再拿它们套公式。

**规则**：

- `memory` 是**可选**字段 —— 不声明不影响插件可用，只影响准入判断的精度
- 声明必须**可核实**：`decompressedBytes` 要能从容器自身的块表推出来，不许写经验值糊上去
- 声明的口径是**字节**（不是 MB），避免不同实现之间的单位歧义
- **`peakBytes` 一旦声明，核心不再叠加安全垫** —— 安全垫的责任转移给声明方

### 2.3 内存声明的自查门禁（`tool/check-plugin.mjs`）

责任虽然归插件，但**核心的检查脚本要替插件作者把明显的错挡住** —— 声明写错在这里就该报，
不要等到用户加载时才发现「预估 200MB 结果吃了 900MB」。

| 代号 | 检查 | 级别 | 判据 |
|---|---|---|---|
| **M1** | 参与解析但未声明 `memory.peakBytes` | ⚠️ warn | 提示「将回落源包粗估，偏差由本插件承担」；只注册插件不检查 |
| **M2** | 字段类型/单位不合法 | ❌ fail | 三个字段必须是**正整数（字节）**；单位写成 MB 的常见错误要明确指出 |
| **M3** | 违反物理下限 | ❌ fail | `peakBytes` 必须 ≥ `rgbaBytes`（纹理解码后的裸像素量）；`decompressedBytes` 必须 > 0 |
| **M4** | 低于固定开销下限 | ⚠️ warn | `peakBytes` < 固定项量级（当前实测 ≈103 MB）时提示「疑似漏算运行期固定开销」 |
| **M5** | 静态声明与实算不一致 | ⚠️ warn | 给了 `--sample <容器>` 时实算 `decompressedBytes`，与**静态**声明值偏差 >20% 时提示「声明可能已过期」 |

#### M2–M4 的检查对象：静态声明 **或** 实算返回值

内存声明有两种形态，门禁必须两种都覆盖：

```
形态 A：静态声明   plugin.json 里写死数值（固定尺寸的插件）
形态 B：动态声明   plugin.json 只声明「支持哪些字段」，数值由运行期 estimateMemory() 每包算出
                  ← 这是主流形态（容器尺寸随包变化）
```

所以 **M2–M4 的检查对象是「能拿到的那个值」**：

```
① 有静态声明值          → 查静态值
② 无静态值但有 --sample → 实跑 estimateMemory()，查**实算返回值**
③ 两者都没有            → 报「跳过（无检查对象）」，并**明确说明是跳过而不是通过**
```

**为什么必须有 ②**：动态声明的插件如果只能被「跳过」，M2–M4 对实际插件就等于不存在 ——
而恰恰是动态声明最容易把单位写错（`return { peakBytes: 400 }` 本意 400MB）。

**③ 的措辞是硬要求**：「跳过」与「查了没问题」在报告里必须可区分，否则门禁会给出虚假安全感。

**为什么 M3 是 fail 而不是 warn**：`ΣRGBA` 是纹理解码后的裸像素总量，**内存里必然存在**这一份，
所以峰值不可能小于它。这不是「可能不准」，是**逻辑上不可能成立**，必须拦住。

**M5 只 warn 的原因**：插件可以用自己的方法算（这是它的自由），偏差可能来自方法差异而非错误，
所以只提醒「对一下」。

**声明口径的一致性要求**（与 §2.2 呼应）：

```
· 单位一律字节，不用 MB（避免 1024 与 1000 两种口径混用）
· peakBytes 是**该包解包时的峰值上限**，不是稳态占用
· 声明必须可核实：能给出一条能从容器自身推出来的路径
```

## 附：`produces` 完整形状

```jsonc
produces: {
  kind: 'spine' | 'live2d',      // 内容类型，唯一来源（见 §3.2）
  entry: 'resolve(file)',        // 入口的表达方式（说明性）
  memory?: { … },                // 见 §2.2
}
```

清单为 JSONC（可带注释）。宿主**原样透传**展示与契约字段，不改写、不解释、不写死登记（删目录即删能力）。

### 2.1 清单是唯一的注册形态

插件必须以 `plugins/<id>/plugin.json` 落盘并声明 `provides`。**无清单的形态一律不注册**，
核心会打印可读原因（缺清单、合法角色有哪些）。

理由：角色是「这个插件能干什么」的唯一声明。缺了它，插件就是没人认识的黑盒 ——
**宁可明确拒绝并说明原因，也不要让它半死不活地挂在那里。**

## 三、注册契约

```js
(function () {
  const host = window.SpineViewerPlugins;       // 宿主注入面
  if (!host) { console.warn('宿主未就绪，未注册'); return; }
  host.register({
    id, name, fileKinds,
    canHandle(file) { return boolean },          // 纯判定，无副作用
    async resolve(file) { return { prefix, files, entry } },
  });
})();
```

| 规则 | 宿主行为 |
|---|---|
| 未调用 `register()` | 标记「脚本已加载但没有调用 register()」 |
| 参数非对象 / 缺 `id` | warn 并忽略 |
| `id` 重复 | warn 并**拒绝注册**（不覆盖已有） |
| 注册成功 | 广播 `spineviewer:plugin-registered` 事件 |

脚本是**注入式经典脚本**（非 ESM），必须同步 `register()`。

### 3.1 `canHandle` 的纯判定边界

```
允许：读 file 的字段（含 file.bytes，若宿主已给）、做容器魔数判定
禁止：发起任何 I/O（网络、文件系统、DOM 写入）、修改外部状态、抛异常
```

| 情形 | 返回值 | 理由 |
|---|---|---|
| 有 `file.bytes` 且魔数不匹配 | `false` | 确定不是本插件的容器 |
| 有 `file.bytes` 且魔数匹配 | `true` | — |
| **没有** `file.bytes` | `true`（保守放行） | 此时无法判定，交给后续 `resolve` 报错；判 `false` 会让无扩展名的包**永远无法被选中** |

**不得**为了判定主动去取字节 —— 那是 `resolve` 的事。返回布尔，不返回置信度分数。

插件内部 `try/catch` 允许，但**catch 后必须留日志**（`host.log`），不得静默吞成 `false` ——
否则调用方只看到「这个文件没有提供者」，属静默失败，排查成本极高。

### 3.2 `kind` 的唯一来源

```
content kind（spine / live2d）  ⟵ plugin.json 的 produces.kind   【唯一来源】
容器 kind（files / bundle）      ⟵ plugin.json 的 fileKinds
```

- `register()` 的 descriptor **可以**带 `kind` 便于调试，但**核心不读它** —— 避免两处声明打架
- 一个插件只声明一个 `produces.kind`；若解出的内容类型不唯一，拆成多个插件
- **禁止**在 catalog 里按插件 id 猜类型（「猜对能用」也算违规，它让契约失效）

`kind` = 内容类型（决定渲染分支），`source` = 容器类型（决定是否需解包）。**`bundle` 不得进 `kind`。**

### 3.3 `register()` 与 `plugin.json` 的分工

| 内容 | 放哪里 | 理由 |
|---|---|---|
| `id` / `name` / `label` / `fileKinds` | 两处都要，值必须一致 | 清单供服务端扫描与可见性判定，注册供前端调用 |
| `provides` / `produces` / `assets` / `errorCodes` | **只在清单** | 属声明，运行期不该变 |

## 四、资产提供者：接口

```js
{
  id: string,                       // = 插件 id
  kind: 'live2d' | 'spine',         // 产出内容类型（不写容器类型）
  canHandle(file) → boolean,
  async resolve(file) → { prefix, files, entry },
}
```

| 成员 | 必选 | 语义 |
|---|---|---|
| `canHandle(file)` | ✅ | 判定「这个文件是否归我解」，纯判定 |
| `resolve(file)` | ✅ | 解析出全部文件与入口路径；失败**抛带原因的错误**，不得返回缺字段半成品 |
| `prepare()` / `revoke()` | ❌ 不保留 | 释放由核心按 `prefix` 调 `VirtualFS.revoke`；插件不持有生命周期 |

### 4.1 `file` 参数形状

`canHandle(file)` 与 `resolve(file)` 收到的是**同一个** `file`，字段**平铺在顶层**，没有 `ctx` 包装：

| 字段 | 类型 | 必选 | 说明 |
|---|---|---|---|
| `rootId` | `string` | ✅ | 资源根 id |
| `rel` | `string` | ✅ | 资源根内相对路径 |
| `name` | `string` | 可选 | 显示名（含扩展名） |
| `size` | `number` | 可选 | 字节数（未知时缺省） |
| `profile` | `string` | 可选 | 该资源根配置的 profile 名，用于选 `profiles/<profile>.json` |
| `bytes` | `Uint8Array` | 可选 | 宿主已读入的字节；**给了就不必再发起 I/O** |

> **类型由宿主保证**：`file.bytes` 一定是 `Uint8Array`（不是 `ArrayBuffer` / `Buffer` / `DataView`）。
> 宿主在调用前完成归一，插件可直接按 `Uint8Array` 使用，不必自己判断类型。
> 反面代价：宿主原样传 `ArrayBuffer` 时，插件侧魔数解析会抛错并被 catch 吞成 `false`，
> 调用方只看到「没有提供者」—— 静默失败。

**取字节的两条通道（按优先序）**：

```
① file.bytes 存在  → 直接用，不产生 I/O
② 不存在           → 走宿主注入的取资源能力（按 rootId + rel 取）
                     不得自行拼 URL、不得访问约定外路径
```

### 4.2 `resolve()` 产物规范

```js
resolve(file) → {
  prefix: string,                        // VirtualFS 前缀
  files:  Map<relPath, Blob | string>,   // relPath 用 "/" 分隔，允许子目录
  entry:  string,                        // 必须是 files 里的某个键
}
```

| 规则 | 说明 |
|---|---|
| `prefix` 格式 | `vfs://<providerId>/<rootId>/<相对目录>/`，**全局唯一**；重复注册由核心抛错 |
| `prefix` 生命周期 | 由**核心**在卸载/切换时 `VirtualFS.revoke(prefix)`；插件不自行 revoke，但必须保证同一 prefix 下不混入无关文件 |
| `files` 的键 | 相对 `prefix` 的路径，**允许子目录**（如 `textures/tex.png`）；同一文件不得有两个键 |
| `files` 的值 | `Blob`（二进制）或 `string`（**按 UTF-8 读回**）；**不得放 Blob URL** —— URL 不是文件内容 |
| `entry` | 必须是 `files` 的键（不是 URL、不是绝对路径） |
| 体积 | **不设单包上限**，峰值由核心控制（实测单包可达 40MB+：2 张 4096² 纹理 + 3MB moc3 + 34 个 motion） |

### 4.3 两种包型的 `entry` 取值

| 包型 | `entry` 指向 |
|---|---|
| 原生 Cubism 文件集（包内已有 `.model3.json`） | 包内**实际存在**的那个 `*.model3.json` 的键 |
| Unity 集成版（只有 moc3 + 纹理 + 曲线） | 插件**重建**出的 `model3.json` 的键 |

> `AssetProvider.resolve(file)` 与 `VirtualFS.resolve(url)` **同名不同物**：
> 前者「容器 → 文件表」（插件实现），后者「URL → 可用地址」（核心实现）。书面一律写全称。

## 五、职责边界

| 允许 | 禁止 |
|---|---|
| 读容器（UnityFS / zip / 目录） | patch 加载器、拦截 fetch、装全局中间件 |
| 把文件放进 `files`（Blob / 字符串） | 直接调 `VirtualFS.register`（由核心注册） |
| 决定 `entry` 指向哪个文件 | 持有 `window.__LIVE2D_STAGE__` 等内部引用 |
| 声明 `kind`（内容类型） | 按插件 id 让 catalog 猜类型 |
| 读 `profiles/<profile>.json`（游戏差异数据） | 代码里写死游戏名 / 目录名 / 路径 |
| 返回可读错误信息 | 产出缺字段资产让下游崩 |

游戏差异（命名约定等）一律走 `profiles/*.json`，由资源根配置的 `profile` 字段选择。

## 六、核心侧时序

```
选中一个 source='bundle' 的条目
  → 按 provider 找到 AssetProvider
  → canHandle(file) === false → 拒绝装载并提示（不试下一个瞎猜）
  → resolve(file) → { prefix, files, entry }
  → VirtualFS.register(prefix, files)          ← 核心做，不是插件做
  → 构建 Document：entry 与 assets 的 url 走 VirtualFS.resolve
  → surface.activate(document)
失败任一步：VirtualFS.revoke(prefix) + 记 warnings / lastError，不影响其它模型可加载
```

**可退化性**：本插件缺失或抛错，只影响它负责的条目；普通目录型模型（`source:'files'`）照常可用。

## 七、验收条款

| # | 条款 | 验证 |
|---|---|---|
| PL1 | 插件必须有 `plugin.json` 且声明合法 `provides`；缺清单不注册且打印可读原因 | 移走清单文件 → 不注册 + 有说明 |
| PL2 | `id` 重复被拒绝，不覆盖已有 | 两个同 id 插件 |
| PL3 | `canHandle` 纯判定：无 I/O、不改外部状态、不抛异常 | 静态检查 + 单测 |
| PL4 | `canHandle` 无 `bytes` 时返回 `true` | 单测 |
| AP1 | 插件代码内无 `window.` 赋值、无加载器 patch、无绝对路径/游戏名字面量 | 静态 grep |
| AP2 | `resolve` 抛错 ⇒ 不产生条目级半成品，可继续加载其它模型 | 构造坏包 |
| AP3 | 未声明 `produces.kind` ⇒ `kind:null` + warning，渲染层拒绝装载 | catalog 断言 |
| AP4 | 删除 `plugins/<id>/` ⇒ 该条目隐藏或标不可用，其它能力不受影响 | 手工：移走目录刷新 |
| AP5 | 切模型后该 prefix 被 revoke（Blob 不累积） | `VirtualFS.stats()` 连开 5 包 |
| AP6 | 插件可脱离核心单测：喂假 `file`，断言 `files` 与 `entry` | 单测 |

## 八、契约完备性判据
