# 契约 · 渲染面（render-surface/v1）

> 本契约约束「把模型画出来」这一层：渲染器接口、Document 形状、能力声明、激活切换、相机归属、动作语义。
> 原「渲染器 / 面板能力 / Document / 动作列表与循环」四份独立契约已合并至此（它们描述的是同一层，分开写会导致同一事实多处登记、各自漂移）。
>
> **一句话边界**：渲染面只负责「把一个 ready 的 Document 画出来」，
> 不负责「舞台多大、背景什么颜色、控件是否可用、资源从哪来」。
>
> 关联：[插件契约](插件.md) · [数据与接口契约](数据与接口.md) · [状态契约](状态.md)

---

## 一、职责边界

| 事 | 归属 | 说明 |
|---|---|---|
| canvas / overlay / GL 上下文、尺寸、DPR、z 序、可见性、帧时钟 | **StageSurface** | 渲染器不碰 DOM、不自己建 canvas |
| 几何（`cssW/cssH/dpr/res`） | **StageSurface.geometry()** | 渲染器只读，不自行测 DOM |
| 资源位置与字节 | **VirtualFS + Assets 层** | 渲染器只消费已解析好的 `Document.assets` |
| 切换渲染面 | **`surface.activate(document)` 唯一入口** | 外部不得直接调 `mount/unmount` |
| 模型装载、动画、皮肤、外观 | **渲染器** | 各自解释，不外泄给面板 |
| 相机语义（档位/范围/锚点/复位） | **统一相机**（`render/camera`） | 渲染器只提供 backend |
| 控件是否可用 | **面板层**按 `capabilities` 判定 | 渲染器不参与 UI 判定 |
| 修改模型数据 | ❌ 渲染器无此职责 | 只有 Editor 经 `applyCommand` 改 Document |

## 二、渲染器接口

```js
{
  id: 'spine' | 'live2d' | (将来 'three'),
  capabilities: {
    settings:  ['fps','dpr','msaa','textureFilter','pma','fit', …],
    debugDraw: ['bones','meshes','boundingBoxes','paths','regions','clipping','hulls'],
    camera:    'ortho-2d' | 'orbit-3d',
  },
  async mount(document, host) → info,        // 入参必须是 ready 的 Document
  unmount(),                                 // 释放当前内容（含自建 GL 资源）
  dispose(),                                 // 彻底释放；幂等
  isActive() → boolean,
  camera: { zoomStep, zoomTo, panBy, reset, scale },   // 属性对象，不是函数
  setSetting(key, value) → boolean,          // 面板唯一落地口
  getSetting(key) → value | null,            // 回显生效值
  setBackground?(mode, palette),             // 可选；不实现即由 CSS 承担
  stats?(), debug?(),                        // 排障用，其他模块不得依赖
}
```

`host = { canvas, overlay, requestRender(), onResize(cb), geometry() }`（即 Surface 句柄）。

### 2.1 舞台对外键面（Spine 33 键）

舞台 API 被名册 / 面板 / 播放条 / 持久化依赖，实测 `Object.keys(stage).length === 33`；
**改任一键均属破坏性变更**。

> **键数口径**：按组列出 32 项，其中 `setDebug` 在「设置」与「渲染」两组各出现一次（同名，后挂载者生效），
> 去重后 31；另有 2 个不属于任何组的键补齐到 33：`animationDetails`、`buildDocument`。
> **校验一律按 33 判** —— 按 31 判会漏掉这两个键。

| 组 | 键 |
|---|---|
| 主体 12 | `load` `unload` `stats` `samplePixels` `applySettings` `play` `pause` `seek` `setAnimation` `resize` `dispose` `debug` |
| 设置 8 | `setFit` `setTextureFilter` `setSpeed` `setLoop` `setDebug` `setFpsLimit` `setDprMode` `setPma`（`setPma` 必须重传贴图） |
| 资源 4 | `getSkins` `setSkin` `setMixMode` `setPartFilter` |
| 视图 5 | `camera` `getView` `setView` `ensureEngineReady` `resetView` |
| 渲染 3 | `setDebug`（覆盖版） `setFilter` `rebuildWithAntialias` |

**三个必须保持的易踩点**：

1. **`setDebug` 定义两次**：设置组 for-of 生成一份、渲染组再覆盖一份，**最终生效的是后者**（语义不同）；不保留覆盖顺序则调试绘制静默变样。
2. **`camera` 是属性对象**，不是方法（`api.camera()` 会抛）。
3. **构造期只收 `opts.canvas` / `opts.onStatus`**，其余设置一律走 `applySettings` / setter。

实现位置：入口 `spine/canvas.js`（唯一出口，纯再导出），实现分在同目录
`canvas-{runtime,document,view,pixels,engine,api,api-groups,entry}.js`；其中任一处的键装配改动都等同于本契约的破坏性变更。

`stats()` 共 20 字段（与 `debug()` 同源）：顶层 12 键
`model runtimeVersion runtimeKeys contexts frames fps loads disposes lastError animations settings view`；
视图 6 项在 `view` 内（`zoom panX panY userScale baseUserScale available`）。

### 2.2 卸载语义：`unmount` vs `dispose`

| 方法 | 语义 | 必须做到 |
|---|---|---|
| `unmount()` | 释放**当前内容** | 内容清空、**自建 GL 资源释放**、停止出帧、自隐藏；幂等 |
| `dispose()` | **彻底释放** | 在 unmount 基础上再销毁引擎/上下文与自建 DOM；幂等；之后可重新 mount |

**两面在 unmount 上的深度不同**（实测结论，不是风格偏好）：

| 面 | `unmount` 释放到哪一层 | 理由 |
|---|---|---|
| Live2D | 与 `dispose` 同一路径：销毁 PIXI app + 移除覆盖层容器 + 状态复位；渲染器实例本身不销毁，下次 mount 靠 `buildOverlay` 全量重建 | `app.destroy(true)` 的 removeView 会摘掉 canvas 只留容器，留下「容器在、canvas 不在」的中间态；下游若按容器复用，会渲染到**不在 DOM 的游离画布**上（页面全白，而 stats 与像素采样都正常）。app 与覆盖层 DOM 重建成本都很低，不值得维护第二套生命周期 |
| Spine | 只释放内容（`stage.unload()`：停循环 + 清骨架），**保留引擎与 WebGL 上下文** | 重建引擎要重新注入运行时源码、按版本选运行时、重建上下文并重传骨架/图集，代价高；保留有真实收益 |

> 前置条件不能依赖「上游永远不制造那个中间态」：`buildOverlay` 复用容器时**必须同时**确认容器里有 canvas，缺了就补建。

**调用方分流**（`Surface.disposeActive(mode)` 是唯一入口）：

```
同一渲染器换内容（spine→spine / live2d→live2d）→ unmount：保留引擎，再装载更快
换渲染器（spine↔live2d，含 bundle↔spine）        → dispose：彻底拆，不留旧 GL 上下文
Surface 自身销毁                                  → dispose
```

**换渲染器必须 dispose 的理由**：两面的 GL 上下文互不复用，保留旧的那份既是「遗留自建 GL 资源」，
也会让连续切换时上下文数量随切换次数增长（实测 dispose 路径下 canvas 数恒为 2、覆盖层恒为 1）。

## 三、Document（渲染器唯一入参）

```js
Document = {
  // 只读（现在必须有）
  id, kind, source, provider,                     // 来自 catalog
  rootId, rootName, name, srcDir,
  assets:  { entry, textures, atlas },            // 地址已经过 VirtualFS 解析
  skeleton:{ bones, slots, animations, skins },   // 只读快照
  meta:    { version, bbox, motions, expressions, extras },
  state:   'ready' | 'error',
  warnings: [],

  // 可写（先留接口，加编辑器时实现）
  params:  { /* 运行时参数：缩放/可见性/绑定 */ },
  dirty:   false,
  history: { undo(), redo() },

  dispose(),                                      // 释放本 Document 持有的资源（含 VirtualFS 前缀）
}
```

| 分区 | 谁能写 | 谁能读 |
|---|---|---|
| 只读部分 | Assets 层（构建时） | 所有人 |
| `params` / `dirty` | **只有核心**（经 `applyCommand`） | 所有人 |
| `history` | 核心 | Editor（触发撤销/重做） |

**任何插件不得直接操作引擎对象**（skeleton / camera / texture）。改数据只有一条路：发 Command。

### 3.1 生命周期

```
catalog entry（ModelEntry）
  → Assets 层：解包（provider）→ VirtualFS.register → 解析地址 → 校验必要字段
      · 通过：state='ready'
      · 失败：state='error' + warnings（不进入渲染层）
  → surface.activate(document)
  → 切换/卸载：document.dispose() → VirtualFS.revoke(prefix)
```

三条硬规则：

1. **渲染器只会收到 `ready`** —— 取资源失败在进入渲染层之前就已失败，渲染器里没有「资源缺失」分支。
2. **`dispose()` 幂等** —— 重复调用不报错、不二次释放。
3. **失败必留痕** —— `state='error'` 时 `warnings` 含可读原因（不靠「字段为空」隐式表达）。

### 3.2 与 ModelEntry 的关系

```
Document = { ...ModelEntry, assets: 已解析, skeleton: 快照, runtime: { params, … } }
```

| 字段 | 取值 | 消费方 | 含义 |
|---|---|---|---|
| `kind` | `spine` / `live2d` | 渲染器 | 内容是什么，决定走哪条渲染分支 |
| `source` | `files` / `bundle` | AssetProvider | 资源怎么来，决定要不要解包 |
| `provider` | 插件 id | Assets 层 | 未安装对应插件 ⇒ 条目隐藏或标不可用 |

**`bundle` 不得进 `kind`**（否则渲染器里会长出「bundle 其实等于 live2d」这类特判）；
`kind` 由提供者 `produces.kind` 决定，不由 catalog 猜。

### 3.3 Command 协议（编辑器唯一入口，现在只定形状）

```js
applyCommand({ type: 'setBoneRotation', bone: 'arm_L', value: 30 })
applyCommand({ type: 'setSlotVisible',  slot: 'cape',  visible: false })
applyCommand({ type: 'setParam',        key: 'scale',  value: 1.2 })
```

核心负责：**校验 → 应用到 Document → 置 `dirty` → 触发重渲染 → 入撤销栈**。插件只负责发命令和自己的 UI。

| 约束 | 说明 |
|---|---|
| 命令必须可校验 | 非法参数拒绝并返回原因，不产生半改状态 |
| 命令必须可撤销 | 每条命令入栈；粒度（按命令 / 按帧）待加编辑器时实测再定 |
| 渲染器只观察不改写 | `unmount` 后引擎对象销毁，Document 不因此变化 |
| 无第二种改数据方式 | 不提供 `document.setParam()` 之类的后门 |

### 3.4 写盘通道

1. 保存一律走服务端 `POST`，**先备份再写**（校验 → 备份 → 写 → 失效缓存）。
2. 写接口维持**单写者**；插件不得自行 `fetch` 写接口。
3. 导出由用户显式触发（下载），不自动落盘。

## 四、能力声明与面板投影

面板**只问「当前渲染器支持什么」**，不问「引擎有没有这个方法」。

| 事 | 归属 |
|---|---|
| 控件有哪些、放哪一组 | 面板 schema（声明式，`panel/schema.js`） |
| 控件需要哪项能力 | 控件声明的 `capabilityKey`（声明期确定，不随运行状态变） |
| 当前有哪些能力 | 渲染器 `capabilities`（**唯一来源**） |
| 可用 / 禁用 / 不构建 | 面板层计算（能力与控件所需键比对） |
| 值如何生效 | `renderer.setSetting(key, value)`，面板不得直连引擎方法 |
| 回显实际生效值 | `renderer.getSetting(key)`，显示生效值而非请求值 |

### 4.1 能力键登记表

| 能力键 | 对应控件 | 语义 | Spine | Live2D |
|---|---|---|---|---|
| `fps` | `ctl-fps` | 渲染限帧 | ✅ | ✅ |
| `dpr` | `ctl-dpr` | 渲染像素比 | ✅ | ✅ |
| `msaa` | `ctl-msaa` | 抗锯齿 | ✅ | ❌ 运行期切换需重建 PIXI app ⇒ 不构建 |
| `textureFilter` | `ctl-filter` | 双线性 / 最邻近 | ✅ | ✅（走 PIXI scaleMode） |
| `presetFilter` | `ctl-filter-preset` | 12 档片元改写 | ✅ | ✅（语义不等价，各自实现） |
| `animation` | `ctl-anim-list` 等 | 动作切换 | ✅ | ✅（`bridge.playLabel`） |
| `pma` | `ctl-pma` | 预乘口径四档 | ✅ | ❌ 真引擎差异 ⇒ 不构建 |
| `fit` | `ctl-fit` | 初始缩放三模式 | ✅ | ❌ 真引擎差异 ⇒ 不构建 |
| `skin` / `partFilter` / `mixMode` | 对应控件 | 皮肤 / 部件筛除 / 混合过渡 | ✅ | ❌ `setSetting` 显式 `return false` ⇒ 不构建 |
| `debugDraw:*` | `ctl-debug-*` | 调试绘制 | ✅ | 声明为空 → 不构建 |

> **本表只是 `capabilities` 的登记簿，不是另一份真相源**。判断依据永远是渲染器实际声明。
> `textureFilter` 与 `presetFilter` 曾共用键 `filter`，导致「只支持纹理过滤」的渲染器把「滤镜预设」也点亮；现为两键。

### 4.2 控件三态规则

| 条件 | 表现 |
|---|---|
| 所需能力在 `capabilities` 中 | 可用 |
| 所需能力不在列表中（单项设置） | `disabled` + `title` 说明 |
| 整组能力都不存在 | **不构建该控件**（不占位） |
| 渲染器未就绪 / 无能力信息 | 仅保留与渲染器无关项（主题、背景） |
| 控件未接线到任何能力 | `disabled` + `data-pending` |

原则：**「这类东西对这种模型不存在」→ 不构建；「这类东西存在但这种渲染器不做」→ 禁用并说明。**

**「不构建」≠「隐藏」**：能力不支持的项必须根本不构建（无 DOM、无监听、无样式计算），
而不是构建后 `display:none` —— 隐藏会让「不支持」继续占用布局与事件成本，且容易被误判为「存在但被关掉了」。

### 4.3 不支持项必须逐项归因

每个被判为「不构建」的能力，必须能指出**具体技术原因**（见 4.1 表最后一列）。

**红线**：渲染器声明了支持的能力必须全部接线可用；**不许因为「还没接线」就把它从 `capabilities` 里删掉或标成不支持** ——
那会让「面板很干净、0 个禁用项」看起来像完成，实际是功能缺失。

判定方法：把 `capabilities` 键集合与「实际可操作控件集合」逐项对齐，差集里每一条都必须能指着具体技术原因；指不出来的一律视为**未接线**。

### 4.4 能力自检（防「声明了但没实现」）

面板装配完成后对当前渲染器执行一次自检：

```
对 capabilities.settings 的每一项 key：
  取该控件当前值 v（或声明的 defaultValue）
  调 setSetting(key, v)
    · 返回非 true ⇒ 违规：声明支持但未实现
    · 抛异常      ⇒ 违规：setSetting 不得抛
  调 getSetting(key)
    · 返回 null 或与请求值不一致且非可解释差异 ⇒ 违规
对 capabilities.debugDraw 的每一项：对应控件必须存在且可应用
```

输出 `__WEB__.panelSelfCheck() → { passed, violations: [{key, expect, actual}] }`；
违规时面板顶部告警一行 + 写 `lastError`，**不静默**。自检非空即回归失败。

### 4.5 回落策略

| 场景 | 契约行为 |
|---|---|
| 取不到 `capabilities` | 视为「无渲染器」：仅显示与渲染器无关项 |
| 渲染器切换 | 每次切换**重算**三态 + **重跑自检** |
| 值不生效 | 以 `getSetting` 的生效值回显 |

**「未声明即不支持」是默认立场**；「默认全支持」会让缺陷静默存在。

### 4.6 落地路径

```
控件变更
  → applyPanelSetting(id, value)
    → 由 id 找 capabilityKey 与 settingKey
      → state.currentRenderer.setSetting(settingKey, value)
        · true  → 记录并回显 getSetting 结果
        · false → 记 warn「渲染器不支持该设置」，控件回退到生效值
    → 不得出现 `stage.setXxx()` 这类直连某个渲染器对象的写法
```

与渲染器无关的项（主题、背景、播放条的纯 UI 状态）由外壳直接处理。

### 4.7 显式豁免：哪些「直连渲染器」**不算**违规

上面那句「不得出现 `stage.setXxx()`」是**针对用户设定项**说的。有三类操作**不在** `setSetting` 的覆盖范围内，
它们直连渲染器实例是**允许的**，不需要扩成能力键：

| 类别 | 具体操作 | 为什么豁免 |
|---|---|---|
| **内容选择** | 读皮肤列表（`getSkins()`）、切换皮肤（`setSkin(name)`） | 这不是「渲染参数」，而是**换一份内容**。能力键描述的是「这个渲染面支不支持某项设置」，皮肤支持与否取决于**模型本身有没有多套皮肤**，与渲染器能力无关；而且当前资产库中模型 skin 数普遍为 1，扩成能力键只会多一个永远单值的键 |
| **视图薄转发** | 舞台的 `setView(...)` | 它只是把视图参数转给**相机 backend**，相机归属已由 §六 规定（统一相机 + 渲染器 backend），不属「面板设置」这一层 |
| **非用户触发的自愈** | 防卡死看门狗的 `pause()` / `play()` | 这是故障自愈动作，不是用户操作，也就不存在「面板控件 → 能力判定」这条链 |

**豁免不等于放任**，仍受这些约束：

```
① 只能调用渲染器**接口上已声明**的方法（上面的 setSetting 契约图仍适用于真正的设置项）
② 不得绕过统一相机（视图类只能走 §六 的入口，不得直接改 camera 字段）
③ 豁免项本身仍要可观测：出错必须记日志，不得静默
④ 新增豁免必须**先改本节**再写代码；不许"先直连、事后补理由"
```

**判据**：一个操作该不该走 `setSetting`，问一句 —— **「换个渲染器，这个操作还成立吗？」**

```
皮肤 / 动作 / 视图 / 自愈   ⇒ 换渲染器也成立（各面自己的实现），属「内容与视图」
帧率 / DPR / MSAA / PMA / 滤镜 ⇒ 换渲染器可能不成立，属「渲染参数」⇒ 必须是能力键
```

## 五、激活与切换

```
surface.activate(document)
  if (swapping) return              // ① 串行：同一时刻只允许一次切换
  setStageMode('loading')           // ② 先统一遮住：任何方向都不会叠加
  await disposeActive()             // ③ 统一卸载（幂等，按 activeKind 分派）
  await mountKind(document)         // ④ 装载新内容
  setStageMode(kind)                // ⑤ 换面
  finally swapping = false
```

三条硬约束：

1. **`data-stage-mode` 只允许 `activate()` / `disposeActive()` 写**，其它地方一律不得写。
2. **切换必须串行**（`swapping` 保护），并发切换返回或排队，不允许两次装载交错。
3. **`dispose()` 幂等且自隐藏**：不依赖调用方记得藏自己的画布。

> 结构理由：只要「每个分支各自负责清理对方」，新增一个渲染面就会再漏一次。
> 已知取舍：先遮后换会让切换瞬间短暂空白；去掉空白的正解是「新内容首帧就绪后再换面 + 上层不透明遮盖」，当前不做。

## 六、相机归属

| 事 | 归属 |
|---|---|
| 档位倍率、缩放范围、锚点、复位语义 | **统一相机**（`render/camera/index.js` + `constants.js`） |
| 值如何落到具体引擎 | 渲染器的 **backend** |
| 像素→世界坐标换算 | 统一相机（backend 不做换算） |

backend 只做四件事：`getScale` / `setScale` / `pan(dx,dy)` / `resetView`。
**钳制只能发生在统一相机一处**；backend 内再夹一次即违规（双重钳制会改变手感）。

参数唯一来源 `render/camera/constants.js`：`MIN 0.125` / `MAX 16` / `STEP 0.1` / `FIT_MARGIN 0.05`；
逻辑中不得出现这些裸数字。

Spine 与 Live2D 各带一个 backend，共用同一套统一相机与同一份常量；
「相机归渲染器」的含义是「相机接口由渲染器暴露」——`camera: 'ortho-2d'` 就是这一层，将来 3D 渲染器自带 `'orbit-3d'`。

## 七、动作列表与循环

### 7.1 唯一数据源

动作列表**只能有一处来源**：模型装载结果返回的动画清单（含每个动作的时长）。

```
右栏「动作」组 与 底栏动作控件  →  必须读同一份数据
不得各取一处，不得一处有数据另一处为空
```

### 7.2 列表形态

每条动作 = **动作名 + 时长**：

| 字段 | 来源 | 缺失时 |
|---|---|---|
| 动作名 | 模型内原始名（`cut_A` / `idle` / `touch_head`） | 必须显示，不可省略 |
| 时长 | 动画数据里的时长（`6.2s`） | **不显示时长**，不得显示 `0s` 或 `—` 冒充 |

- 当前播放中的动作必须**高亮**
- 列表顺序 = 模型内声明顺序，**不做字母排序**（顺序本身就是播放顺序）

### 7.3 两处入口，行为一致

右栏「动作」组与底栏动作控件是**同一功能的两个入口**：

```
· 同一份列表、同一顺序、同一条时长
· 点击任一处都能播放该动作
· 播放后两处的高亮/选中态同步更新
· 不允许一处是完整列表、另一处是原生下拉且行为不同
```

底栏可用下拉形态（空间受限），但内容必须与右栏逐项一致；右栏必须是可见列表。

### 7.4 循环语义

右栏「动作」组内并列两个开关，各自管一件事，**不得合并、不得互相影响**：

| 开关 | 管什么 | 开启 | 关闭 |
|---|---|---|---|
| **混合模式** | 切换动作那一瞬间的过渡 | 约 0.2s 渐变 | 硬切 |
| **循环播放** | 播完之后接谁 | 按列表顺序逐条播完剩余动作，末尾回到第一条 | 停留当前动作，重复播放它 |

两个开关正交：改一个不得改变另一个的状态与行为。

底栏不设「单动循环」按钮：循环由右栏「循环播放」开关接管，底栏只保留动作选择、上一个/下一个、播放暂停等传输类控件。

**禁止语义**：「随机播放」「只对第一个动作循环」「播完停在最后一个」。

### 7.5 覆盖范围

Spine 与 Live2D **都必须实现**，不得因「另一面没有」而省略：

| 面 | 动作来源 |
|---|---|
| Spine | `skeletonData.animations` |
| Live2D | Cubism motion groups（`idle` / `complete` / `effect` / `home` / `login` / `mail` / `main_N` / `mission` / `touch_head` / `touch_body` / `touch_special` 等） |

Live2D 的 group 名与 motion 名都要能区分显示（形如 `group / motion`），不得只显示 group 而丢掉具体动作。

当前播放项的唯一真相是播放控件（`#transport-motion`）的值；右栏高亮必须跟随它，
不得自己维护第二份「当前动作」状态（见[状态契约](状态.md)的单一真相原则）。

## 八、禁止事项

1. 读写舞台几何（`clientWidth` / `getBoundingClientRect`）—— 只从 `host.geometry()` 取
2. 直接 `import` 另一个渲染器模块，或按内容类型写死对方逻辑
3. 声明了 `capabilities` 却没实现对应 `setSetting`
4. 画背景、写 `data-bg`、写 `data-stage-mode`
5. 携带另一类模型的内部分支（如 Spine 里判断 Live2D）
6. 自己实现内存资源解析（应走 VirtualFS）
7. 在 `unmount`/`dispose` 里遗留自建 GL 资源
8. **写尺寸型内联样式**（`style.width` / `style.height`，含 canvas 的 `attr` 与 `style` 两套尺寸）—— 写入权归 Surface，渲染器只能请求更新
9. 在渲染器内保留「资源缺失 / 404」分支 —— 取资产失败必须发生在进入渲染层之前

> 第 8 条的实际代价：覆盖层曾被写成内联 px 且从不随几何更新，旋转后画布被 `overflow:hidden` 裁在左上角；
> 而几何、PIXI、canvas backing 全是对的，导致「检查几何是否更新」的排查手段全部失效，且「手动重载模型」能临时恢复，极具误导性。

## 九、扩展判据

**新增一个渲染面**：

```
1. 写 render/<kind>.js：capabilities + mount/unmount/dispose/isActive + camera + setSetting
2. main.js：surface.register(create<Kind>Renderer())
3. 面板零改动（按 capabilities 自动生成/禁用）
4. Document 契约不变（新增 kind 只是多一种内容类型）
```

判据：加 3D 渲染器时**不需要改 VirtualFS、不需要改资产提供者、不需要改面板 schema**；
若要改这些，说明扩展点没留够 —— 先补契约再实现。

**加编辑器**：不需要改渲染器、不需要改 VirtualFS、不需要改插件加载器，
只新增一个 `editor` 实现 + 补 Document 可写部分。做不到就是扩展点没留够。

已知难点（属实现难度，不是架构缺口）：`.skel` 二进制需可写表示与回写编码；撤销栈粒度需实测手感。
