## 一、功能缺陷

### 1.1b 前端 VirtualFS 无容量上限、无淘汰

`infra/vfs.js` 把解包出的 Blob 与 Blob URL 存在内存 `Map` 里，**没有任何 MAX 或淘汰机制**，
只靠 `revoke(prefix)` 在切换/卸载时释放（`document.js`、`plugin-host.js` 两处调用）。

风险：只要哪条切换路径漏了 `revoke`，Blob 会累积到刷新为止。
`stats()` 能报出 `{prefixes, files, bytes, urls}`，**可观测但不自动兜底**。

> 对照：服务端解包缓存（`data/unpacked/`）有上限与 LRU（20 目录 / 8GB），
> 前端这一层没有。两层不是一回事，别混。

### 1.2 部分碧蓝航线目录名未映射（Live2D 7 + Spine 9）

上游名称表没有这些键（`_ii` / `_new` / 罗马数字等后缀变体），界面回退显示拼音目录名。
**功能不受影响**，只是名字不好看。

解决方向见[设计/名表](../设计/名表.md)（v2 索引表，**尚未实施**）。

### 1.3 少数 Spine 骨架解析失败

目录里没有同名 `.atlas` 的骨架（零件/切片型资产）会报 `SPINE_ERR_PARSE`。
**这是如实报错，不是给假数据** —— 属资产本身不完整。

### 1.4 多皮肤路径未经真实数据验证

舞台已提供 `getSkins()` / `setSkin(name)`，但当前资产库中模型 skin 数普遍为 1，
只有单皮肤路径被实测覆盖。**接线是对的，但缺真实样本验证。**
