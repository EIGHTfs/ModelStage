## 一、能做什么

| # | 能力 | 入口 | 要点 |
|---|---|---|---|
| 1 | **列资源根** | `GET /api/roots` | 当前含 bd2 / azurlane / azurlane_spine / azurlane_bundle |
| 2 | **列目录与模型** | `GET /api/tree?root=<id>` | 按魔数识别 bundle / 目录型；被禁插件条目带 `hiddenByPlugin` |
| 3 | **取文件** | `GET /api/file?root=&path=` | 路径穿越受保护 |
| 4 | **模型元数据（两类通吃）** | `GET /api/model-meta?root=&path=` | `path` 可为**目录或文件**，回 `resolvedFile`；Spine **3.6 / 3.7 / 3.8 / 4.1** + Cubism |
| 5 | **动作语义** | 同上返回 `motions[]` | `{name, group, loop, confidence, rule}`；规则数据化在 `tool/spine-motion-rules.json` |
| 6 | **装载前预检** | `GET /api/bundle/probe?root=&path=` | 只解析容器/对象表/纹理格式，不解码像素；比真正装载快一个量级 |
| 7 | **资源包 → 标准模型目录** | `node tool/export-bundle.mjs --root=<id> --path=<资源>` | 产出可被任何 Live2D 运行时加载的目录（含 motion3） |
| 8 | **插件发现与自描述** | `GET /api/plugins` | `fileKinds`（接管哪类条目）/ `produces`（产出摘要）/ `errorCodes` |
| 9 | **统一模型清单** | `GET /api/catalog` | `ModelEntry`：`kind` / `source` / `entry` / `assets` / `meta`；前端唯一取数口 |
| 10 | **服务端解包** | `POST /api/unpack/{resolve,file,capacity,stats}` | 含内存准入（可用内存 vs 预估峰值）、指纹缓存、分阶段统计 |
| 11 | **背景与纯色预设** | `GET/POST /api/backgrounds`、`/api/backgrounds/solids` | 纯色预设 5 个接口，原子写 + fsync + 串行队列 |
| 12 | **就绪信号** | `GET /api/ready`、`GET /api/ready/stream` | 阶段状态机 + SSE（先推全量再推增量） |
| 13 | **诊断取证** | `window.__DIAG__` + `POST /api/diag` | 错误/警告/事件时间线 → `data/diag.jsonl` |
| 14 | **错误码** | 各接口返回体 `code` | `ULB_ERR_*` 15 个 + `SPINE_ERR_*` 4 个；同因同码、已发布不删改 |

## 二、纯函数库

这些模块与前端框架无关，换框架零改动，可单独测试。

### 2.1 `plugins/unity-live2d-bundle/lib/`（Unity 资源包解析与解码）

| 模块 | 职责 |
|---|---|
| `bytes` / `unityfs` / `serialized` / `typetree` / `extract` | 容器 → 对象表 → 抽取资产 |
| `etc2` / `dxt` / `texdecode` / `png` | ETC2 与 BC 家族解码 → PNG 编码（真压缩，流式 deflate） |
| `model3` / `anim-to-motion` / `common-strings` | 生成 Cubism `model3.json` 与 `motion3.json` |
| `errors` | 15 个 `ULB_ERR_*` 码表 + `fail()` |
| `bundle-probe` | 装载前预检（浏览器与 Node 共用同一实现） |

### 2.2 `tool/lib/`（服务端与工具层）

| 模块 | 职责 |
|---|---|
| `spine-runtime` / `spine-meta` | 定位 Spine 运行时 → 解析 `.skel` → 元数据（含 4.1 的 atlas/texture 约束） |
| `spine-motions` | 动作名 → group / loop / confidence 纯函数（规则在 `tool/spine-motion-rules.json`） |
| `cubism-core` | Cubism Core 的 vm 沙箱（取真实参数 Id） |
| `export-bundle` | 导出编排（估算 / 磁盘检查 / 纹理 / 动作 / model3 / 收尾） |
| `check-perms` | 文件权限预检（644 / 755；权限错会让服务静默 404） |
| `atomic-json` | 原子 JSON 写盘（tmp → fsync → rename）+ 串行队列 + 备份轮转 |

### 2.3 `tool/` 门禁脚本

| 脚本 | 作用 |
|---|---|
| `check-single-source.mjs` | 禁止前端业务代码直调单路扫描接口（只许 `/api/catalog`） |
| `check-plugin.mjs` / `check-plugin-node.mjs` / `check-plugin-host.mjs` | 插件契约与宿主接线检查 |
| `check-inline-size.mjs` | 尺寸型内联样式的唯一写入者检查 |
| `check-console.mjs` | 页面零错误门禁 |
| `test-all.mjs` | 统一回归入口（前置检查 + 套件调度） |

## 三、质量基线

| 项 | 当前状态 |
|---|---|
| 回归套件 | 统一入口 `node tool/test-all.mjs`，全部套件通过即视为基线绿 |
| 静态门禁 | 单一数据源 / 插件契约 / 内联尺寸 / 页面零错误，四项挂在前置检查层 |
| 引擎数值对照 | 相机（多步六项 `===`）与外观（PMA 四档 + 12 滤镜像素占比差在阈值内）两引擎并跑全等 |
| 审计 | 每次提交 blocker 0；评分随 diff 规模波动，不作为质量判据 |
| 诊断探针 | 页面级 `__DIAG__` 0 error；落盘 `data/diag.jsonl` |

## 四、已知限制（真实存在，不是待办）

1. **Spine 运行时版本必须匹配到 minor** —— 4.2/4.3 运行时不能解析 4.1 骨架
2. **部分 Spine 模型解析失败** —— 目录里缺同名 `.atlas` 时按 `SPINE_ERR_PARSE` 报错，**不给假数据**
3. **纹理格式** —— 现网资源基本为 ETC2_RGBA8；ASTC / PVRTC / BC6H / BC7 **未实现**，
   会抛带格式号的错误，不静默产坏图
4. **预检不解码纹理像素** —— 只判格式是否可解码
5. **同一 moc3 的参数表**在导出时按包缓存，不跨进程共享
6. **内存峰值** —— 解包峰值仍高于源包数倍；已做原地解压、零拷贝读取、PNG 流式编码等优化，
   但整张纹理的解码仍是主要开销（分块解码未做）

## 五、可选的后续（按需，不是待办）

- **第二个游戏 profile**：需要一个资源包类型的游戏目录（当前唯一资源包目录是 `live2d/`）
- **导出走 HTTP**：要把导出做成任务队列（jobId + 进度 + 并发 1 + 磁盘配额）
- **纹理格式扩展**（ASTC 等）：等有真实资源再做
- **整洁度清理**：魔数与圈复杂度告警（不产生功能缺陷）
