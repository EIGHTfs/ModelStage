# 贴图超分辨率调研（Spine / Live2D）

> 调研日期：2026-10-26 ｜ 结论先行：**超分不是普遍有效的手段，要看资源来自哪条链路**。
>
> **定位**：这是**后续插件功能**的预研，当前只做调研与分析，不落地代码。
> **已确认场景**：用户实际觉得糊的情况是 **「相机放大后糊」** —— 不是 DPR2 大屏、也不是
>   "某些模型特别糊"。这一条把优先级改了，见 §九。

---

## 一、先说结论

```
① 资源包（UnityFS/ETC2）解出来的贴图已经是 4096×4096 —— 再超分没有意义，
   该链路真正的问题是**ETC2 块压缩伪影**，不是分辨率
② 松散 Live2D 目录的图集是 2048×2048 —— 只有在 DPR 2 大屏（渲染 3840×2160）
   或被相机放大时才不够用，这时 2x（4096²）确有收益
③ Spine 图集是 2048×512 长条 —— 技术上能做，但必须**重写 atlas 坐标**
   （权威格式里 page 只有 size/format/filter/repeat/pma，**没有 scale 字段**）
④ 零依赖约束下，最划算的顺序是：先调渲染参数（0 成本）→ 实时着色器锐化/放大
   （纯 GLSL、不改资源）→ 最后才考虑离线 AI 超分（要外部二进制 + 磁盘 ×4）
```

---

## 二、现状（实测数据）

### 2.1 三条链路的贴图分辨率

| 来源 | 实测尺寸 | 说明 |
|---|---|---|
| 松散 Live2D（`.../live2d/abeikelongbi_3/textures/texture_00.png`） | **2048×2048** | 单图集页，角色全身 |
| 资源包解出（`data/unpacked/*/files/texture_00.png`） | **4096×4096** | 已经是 4K |
| 资源包解出（`texture_01.png`） | 2048×2048 | 第二页 |
| Spine 图集（BD2 `char000101.atlas`） | page `size:2048,512`；另有 `2048,1024` | 长条打包，`filter:Linear,Linear` |

### 2.2 有效采样密度（决定"糊不糊"的关键）

以 1080p 窗口、角色占满屏幕高度为例：

```
DPR 1（渲染 1920×1080）：2048 图集 / ~1080 显示像素 ≈ 1.9 texel/px  → 过采样，清晰
DPR 2（渲染 3840×2160）：2048 图集 / ~2160 显示像素 ≈ 0.95 texel/px → 临界
相机放大 2x            ：等效 0.48 texel/px                     → 明显发糊，双线性放大
```

**结论**：糊的成因按贡献排序是
① 相机放大或 DPR 2 导致的**上采样**（双线性软化）
② ETC2/DXT 块压缩伪影（资源包链路）
③ 源图本身分辨率不足（仅松散 Live2D 在极端放大时）

## 三、技术路线对比

### A. 实时着色器放大 + 锐化（零依赖，推荐先做）

```
原理  EASU/FSR1 式边缘导向放大 + RCAS/CAS 对比度自适应锐化；或 Anime4K 风格的
      梯度检测 + 细线重建（后者对线稿更强，但要做多 pass）
挂载  Spine：已有片元注入管线（engine/filters.js 的 __FILTER__ 模板），加一段即可
      Live2D：PIXI 自定义 Filter（片元着色器同源）
成本  GPU 每帧多 1~2 次采样上界；1080p/DPR2 下约 0.2~0.5 ms（需实测）
收益  边缘更利、双线性软化的观感显著改善；**不增加纹理内存、不动任何资产**
局限  无法"恢复"不存在的细节；对 ETC2 块状伪影无效（甚至会把伪影强化）
```

### B. 离线 AI 超分（收益最大，但重）

```
工具  waifu2x-ncnn-vulkan / Real-ESRGAN（anime 权重）—— 都是外部二进制，放 tool/ 自备
做法  Live2D：直接把 textures/*.png 换成 2x 版本（moc3 的 UV 是归一化的，**可以不改模型**）
      Spine：必须同时重写 atlas —— page size ×2、每个 region 的 bounds ×2、
             offsets/split/pad 里"原始尺寸"也 ×2，rotate 不变
存储  磁盘 ×4（2048²→4096² 单页 PNG 体积约 3~4 倍）
内存  纹理内存 ×4（2048² RGBA ≈ 16MB → 4096² ≈ 64MB/页）
风险  Spine atlas 重写一旦错位，表现为"图错位/露边"，且 3.8 / 4.1 / 4.2 三套运行时都要验
      不能改仓库里的原始资产 —— 必须做成**可配置的覆盖层**（原图 + 覆盖目录）
```

### C. ETC2 伪影去除（针对资源包链路，唯一有效手段）

```
现状  资源包贴图已是 4096²，超分无收益；但 ETC2 是 4:1 块压缩，渐变区常见块边与色带
做法  解码后（texdecode → RGBA 阶段）加一次去块/双边滤波；或离线 denoise 后落缓存
成本  解码期一次性（可缓存），不进每帧
收益  对大色块渐变（皮肤、布料）改善明显；线条锐度无变化
```

### D. 已有参数的性价比排查（0 成本，必须先做）

```
· DPR：auto/1/1.5/2 —— 若用户在大屏用 auto 且 auto 取到 2，等价于强制上采样；可给"性能/清晰"两档预设
· 纹理过滤：现在是双线性 / 最邻近两档；可加"双三次（bicubic）"档 —— 纯 shader 内 4 次采样
· mipmap：当前未见启用；缩小显示时无 mipmap 会有闪烁与锯齿，启用后缩小更干净
· 各向异性过滤：斜视/斜置部件（躺姿）时提升明显
```

## 四、可行性判定（按资产）

| 资产 | 换 2x 贴图要不要改模型 | 判定 |
|---|---|---|
| Live2D（松散目录） | **不用**（moc3 UV 归一化） | ✅ 最容易，先在这里验证效果 |
| Live2D（资源包解出） | 不用，但源已 4096² | ⛔ 无收益，改做 C |
| Spine（3.8 / 4.1 / 4.2） | **要重写 atlas**（无 scale 字段） | ⚠️ 可行但需专门工具 + 三版本回归 |

## 五、推荐落地顺序

```
第 1 步（0 成本，先量）
  用现有面板逐档对比：DPR 1 / 1.5 / 2 × 纹理过滤（双线性 / 最邻近）
  截图 + 记录"有效 texel/px"与观感结论，确认瓶颈到底在分辨率还是伪影

第 2 步（小，纯 GLSL）
  A 路线：加一个「清晰度」档位（关 / 轻锐化 / 边缘放大），Spine 走 __FILTER__ 注入，
  Live2D 走 PIXI Filter。判据：同一帧截图对比 + 边缘梯度指标上升、无光晕

第 3 步（针对性）
  资源包链路做 C（去块），因为它的瓶颈与分辨率无关

第 4 步（重，按需）
  只在"用户经常放大看"的前提下做 B，且**只先做 Live2D**（不用改模型坐标系），
  Spine 等 Atlas 缩放工具写出来、三版本回归通过再上
```

## 六、必须先回答的三个问题（否则容易白做）

```
① 用户到底在什么条件下觉得糊？
   DPR 2 大屏？相机放大？还是资源包那条链路？三者解法不同（D / A / C）
② 收益怎么量？
   只靠"看起来更清晰"会做成"过锐化"（边缘光晕、噪点放大）。
   需固定一组指标：边缘梯度均值、拉普拉斯方差、与 DPR 1 基准的 SSIM
③ 能不能改原始资产？
   不能。超分结果必须落在**覆盖层/缓存目录**（像 data/unpacked 那样可重建），
   原资产保持不动，否则换机器/换游戏就还原不回去
```

## 七、风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| Spine atlas 重写错位 | 图错位、露边、残影 | 写工具 + 先在单个模型上逐区域比对 UV；三版本运行时回归 |
| 纹理内存 ×4 | 多页模型可能顶到预算 | 走现有内存准入（capacity/budget），超限不启用 |
| 过锐化光晕 | 观感反而更差 | 锐化强度限幅 + 与原始帧做差分对比 |
| 每帧额外采样 | 低端机掉帧 | 档位默认关；开启后纳入 FPS 监控 |
| 改原资产 | 不可逆 | 一律落覆盖层/缓存，原文件只读 |

## 八、待你定的选择

```
① 只做 D（调参 + 加双三次档）：0 依赖、0 磁盘，收益中等
② D + A（加实时锐化/放大档位）：纯 GLSL，收益明显、可开关，推荐
③ D + A + C（再做资源包去块）：覆盖三条链路，工作量中等
④ 全套含 B（离线 AI 超分，先只 Live2D）：收益最大，要外部二进制 + 磁盘 ×4 + Spine atlas 工具
```

## 九、场景确认后的优先级修正（相机放大后糊）

用户实际反馈是**相机放大之后糊**。这和"整体不够清晰"是不同的问题：

```
放大后糊的机制：屏幕上 1 个像素对应的贴图纹素 < 1（texel/px < 1）
  ⇒ 双线性插值在放大时做的是"把 4 个 texel 混成一个像素"，
     细节没有更多像素可采，只能变软
```

### 9.1 这一场景下四条路线的实际效果

| 路线 | 对"放大糊"有没有用 | 说明 |
|---|---|---|
| A 实时锐化 / 边缘放大 | **部分有用（缓解）** | 只能让软掉的边缘重新变利，无法补出细节；放大倍数越大越无力，且容易出现光晕 |
| B 离线 AI 超分 | **根治手段** | 真正提高源分辨率（texel/px 回到 >1），是唯一能"补像素"的路 |
| C ETC2 去块 | 无关 | 那是压缩伪影，与放大无关 |
| D 调参 | **部分有用** | 放大时**不能误用 mipmap**（会选更粗的层更糊）；`magFilter` 用线性；上采样换双三次比双线性略好，但同样补不出细节 |

**结论修正**：既然瓶颈是放大，那么

```
即时缓解 = A（着色器锐化，可开关、零依赖）
根治     = B，且**只需要对松散 Live2D 做**（2048² → 4096²）
           —— 资源包那条已经 4096²，放大到 2 倍仍有余量，不必做
           —— Spine 那条要做 atlas 重写工具，优先级最低
```

### 9.2 放大场景还该查的两件事（成本极低）

```
① magFilter 与 mipmap 的配合：放大时若 mipmap 存在且 LOD 选取偏低，会采到粗层
   ⇒ 核对 minFilter 的 mipmap 链是否在 magFilter 侧被误用
② 是否给"最大放大倍数"设提示：超过 1:1 texel 后继续放大必然是糊，
   可以在状态栏显示当前 texel/px，让"糊"变成可解释的量而不是玄学体感
```

### 9.3 插件化形态（以后落地时的归属）

现有插件角色是 `asset-provider / renderer / editor / exporter / panel`。超分能力可以落成两类，互不冲突：

```
① 资产变换型（偏 asset-provider）：输入原始贴图 → 输出放大后的贴图
   · Live2D：直接替换 textures/*.png（moc3 UV 归一化，**不需要改模型**）
   · Spine：额外产出改写后的 atlas（size/bounds/offsets/split/pad 全部 ×S）
   · 产物必须落缓存目录（可重建），原资产只读
② 渲染增强型（偏 renderer 能力键）：着色器锐化/边缘放大档位
   · 与现有 __FILTER__（Spine）/ PIXI Filter（Live2D）同一套注入方式
   · 作为能力键暴露，面板可开关；默认关
```

真正实现时的验收口径（先立判据再动手）：

```
· 同一相机位、同一帧，开/关对比截图
· 边缘梯度均值上升，且**与放大前基准的 SSIM 不下降**（防过锐化）
· 纹理内存增量与 FPS 变化（放大档位开启前后各测一次）
```
