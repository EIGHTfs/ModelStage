# 设计 · 内存指示条

> 舞台与设置面板里那条**三色内存条**：总内存 / 可用内存 / 服务端已占用。
> 目的：让「现在还有多少余量」一眼可见，不必去翻日志或敲命令。

---

## 一、数据来源

一次请求拿全部三个值，**不新增接口**：

```
GET /api/unpack/capacity        ← 不带 sourceMb 参数
→ { memTotalMb, memAvailableMb, memAvailableSource, rssMb, budgetMb, ratio,
    sourceMb: null, peakEstMb: null, reason: "no-package", … }
```

| 字段 | 语义 |
|---|---|
| `memTotalMb` | 物理总内存 |
| `memAvailableMb` | `/proc/meminfo` 的 `MemAvailable`（内核估算的「真要用了能腾出多少」，含可回收 buff/cache）|
| `rssMb` | `process.memoryUsage().rss` ⇒ **服务端进程已占用** |

### 1.1 为什么不用 `peakEstMb`

`peakEstMb`（解包峰值预估）**不进 UI**，只在日志里看。原因：

- 它只对**资源包**（容器单文件）有值；散装目录形式 `sourceMb` 为 null ⇒ `peakEstMb` 也为 null（`reason: "no-package"`）
- 它是「准入判据」用的预估，不是「此刻占用」的事实；放进指示条会与旁边两个真实值混为一谈

> 准入判断那条链路（`estimatePeakWithBasis` / 分段模型 / 实测回填）与本文无关，不受影响。

## 二、视觉：单条叠加式

```
[服务端 112][——— 其他占用 5210 ———][可用 2655]      全长 = 总 7977
 └ 橙 ┘      └ 底槽色 ┘              └ 绿 ┘
```

- 轨道宽度 = 100%，代表 `memTotalMb`
- 每段宽度 = `值 / memTotalMb × 100%`
- 顺序固定：**服务端（左）→ 其他（中）→ 可用（右）**
- **三段百分比之和修正到 100%**：四舍五入的余数补给宽度最大的那一段，否则轨道末尾会露缝

### 2.1 为什么这么排

把「可用」放最右，让它与轨道右端对齐 —— 这样「服务端段 + 其他段」的总长度就等于**已用**，
读者不需要做减法就能看出「还剩多少」。若把可用放中间，剩余量就要靠两段间隙去估。

## 三、颜色令牌

定义在 `src/web/style.css` 的 `:root`，**五套主题各一份**：

```css
--mem-total:     /* 底槽 = 总内存 */
--mem-available: /* 可用段 */
--mem-server:    /* 服务端已占用段 */
```

规则：

- **不许内联色值**，一律 `var(--mem-*)`
- 五套主题（dark-cyan / eye-gray / day-paper / neon-violet / cloud-blue）都要给值
- **三段必须互相可分辨** —— `day-paper` 是浅色主题，浅绿会撞白底，需单独调深

## 四、位置

同一组件在两处复用，**不写两份实现**（模块：`src/web/panel/memory-bar.js`）：

## 五、刷新时机

```
选中一个有资源的模型（加载成功后） → 拉一次
展开设置面板                     → 拉一次
```

**不做常驻轮询、不 `setInterval`。** 这是契约要求（事件驱动；定时器只在判断本身依赖时间时才用），
数字停在拉取那一刻是**预期行为**，不是缺陷。

边界：

```
没选中模型 / 加载失败  → 整条隐藏（不留空壳、不显示 0）
请求失败              → 隐藏 + 记一条 warn 日志，不静默、也不显示假数字
```

## 六、无障碍与触摸端

```
① 整条 role="img"，aria-label 写全三个数值
   （"内存：总 7977 MB，可用 2655 MB，服务端已占用 112 MB"）
② 文字行始终可见，不做 hover / title 才显示
③ 不加 tooltip、不加 hover 态交互
④ 本条不可点，但不得遮挡其它可点元素
```

**为什么写死这条**：目标设备是触摸端（Android Edge），没有鼠标悬停 ——
任何依赖 `title` 或 hover 才能看到的信息，在那种设备上等于不存在。

## 七、验收判据

| 项 | 判据 |
|---|---|
| 数据真实 | 三个数字来自 `/api/unpack/capacity`，代码里无写死数值 |
| 三段合 100% | 三个百分比相加 = 100%（含余数修正）|
| 令牌生效 | 改 `:root` 的 `--mem-*` → 两处显示同步变；五套主题逐个核对 |
| 未选中不显示 | 清掉模型选择后整条消失，不留空壳 |
| 请求失败 | 隐藏 + 有 warn 日志，不显示假数 |
| 无定时器 | 相关文件 `grep setInterval` = 0 |
| 无内联色 | 新增代码 `grep "#[0-9a-fA-F]\{3,6\}"` = 0 |
| 触摸可用 | 不依赖悬停即可看到全部信息 |
