# 任务：调研 live2dviewex 资源包（LPK）能否被本项目支持

## 一、目标

判断 `资源/live2dviewex/` 下的模型包能否被本项目（ModelStage）识别/加载，
需要什么工作；给出结论与证据，不改产品代码。

## 二、数据现状（已查明，不用重复）

```
位置   资源/live2dviewex/
规模   15 个子目录，每个 3~4 个文件
构成   每个目录：<id>.lpk + <id>.png + config.json (+ 个别带 ugcid / 一个带 mp4)
```

已确认的三件事（起点，别重查）：

| 文件 | 事实 |
|---|---|
| `*.lpk` | **标准 ZIP**：头部 `50 4b 03 04`（PK\x03\x04）；首个 entry 名以 `87` 开头 |
| `config.json` | Live2DViewerEX 元数据：`{lpkFile, file, previewFile, fileId, type, stereoMode, title, author, description, …}` |
| `*.png` | 预览图（571KB 级别） |

## 三、要做的事

```
1. 解包一个 lpk（用系统 unzip，不引依赖），列出内部文件与目录结构：
   · 里面是 moc3 + 纹理 + model3.json（Cubism 4），还是 moc（Cubism 2），还是 Spine 的 .skel/.atlas/.json
   · 内部路径是否有统一前缀、是否含多余文件（音频/视频/脚本）
2. 抽样 3~5 个 lpk 覆盖不同目录，确认结构是否一致（有的目录只有 mp4 没有 lpk，说明是什么）
3. 判断与我们的扫描器契约的差距：
   · 我们的 Live2D 扫描器期望：目录里 *.model3.json（或 .model.json）+ 同目录纹理 + moc/moc3
   · 我们的 Spine 扫描器期望：*.skel/.json + *.atlas + 散图
   · ⇒ 缺的是"lpk 是容器"这一层：解包后是否就能被现有扫描器吃到
4. 给结论：① 直接可用（说明怎么放）② 需要插件（哪种 runtime：node 还是 exec）
   ③ 需要产品改动（改哪个扫描器、改什么判据）
5. 顺带记录：`config.json` 的字段里有没有本项目清单能复用的信息（标题/作者/预览图）
```
