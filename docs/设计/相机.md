# 设计 · 相机

> 目标：**Spine 与 Live2D 共用同一套相机语义**（档位、范围、锚点、复位），差异只在 backend。
> 强制约束（钳制单点、参数常量、backend 职责）见[渲染面契约](../契约/渲染面.md) §六与 INV-03 / INV-11。

---

## 一、形态

```js
createCamera({ backend, limits = { min: 0.125, max: 16 } }) → {
  zoomStep(dir),      // userScale *= (1 + dir * STEP)，clamp limits
  zoomTo(scale),      // clamp + 写回
  panBy(dx, dy),      // 语义 = 屏幕像素增量，内部乘子交 backend
  reset(),            // 归 1（或保留）+ 让 backend 重新 fit
  scale(),            // 读当前 userScale
  note(msg),          // 日志
}
```

**backend 只提供「怎么落地」**：

```js
backend = {
  getScale() → number,
  setScale(v),            // Spine: camera.zoom = baseZoom / v；Live2D: zoomRatio = v
  pan(dx, dy),            // 各自处理内部乘子与方向翻转
  resetView(keepScale),
  fit?(),                 // 只有 Spine 有（subject / animation / all）
}
```

## 二、哪些共用、哪些各留

| 逻辑 | 共用？ | 理由 |
|---|---|---|
| 档位公式 `1 + dir * STEP` | ✅ | 两边都是「每档 ±10%」，语义一致 |
| 范围 `[0.125, 16]` | ✅ 同一份 `limits` | 统一手感的前提 |
| 超界钳制 | ✅ **只在一处** | 双层钳制会让上层改不动（改了也没效果） |
| 锚点 = 视口中心 | ✅ 语义层 | 两边实现方式不同但可见效果等价 |
| 复位 = 归 1 或保留缩放 | ✅ | |
| 平移参数单位 = 屏幕像素 | ✅ 语义层 | |
| 节流（每帧合并） | ✅ | 两边都该有 |
| **`fit` 三种模式** | ❌ 各自 | Live2D 无骨骼/插槽/动画帧概念，`subject` / `animation` 无法直接实现 |
| **`baseZoom` 重算** | ❌ 各自 | Spine 是 `camera.zoom = baseZoom/userScale`；Live2D 是 `model.scale` 直接乘 |
| **pan 内部乘子** | ❌ 各自 | Spine 需世界单位换算；Live2D 是 1:1 跟手。**刻意不同**，统一会破坏其中一边的手感 |
| **fit 边距** | ✅ 同一 `FIT_MARGIN` | 边距不同会让初始大小差几个百分点 |

> 注意：「相机归渲染器」**不是**「相机归 Spine」。Spine 与 Live2D 各有一个 2D 渲染器、
> 各自提供 backend，**共用同一套统一相机与同一份常量**。

## 三、参数常量（唯一来源）

```js
// render/camera/constants.js
export const CAMERA = {
  MIN: 0.125,        // 最小缩放（相对 fit）
  MAX: 16,           // 最大缩放
  STEP: 0.1,         // 一档 ±10%：scale *= (1 + dir * STEP)
  FIT_MARGIN: 0.05,  // fit 留 5% 边距
};
export const SUBJECT_EXCLUDE = ['bg', 'back', 'background', 'effect', 'mask', 'scene', 'kazari'];
```

**逻辑代码里不得出现 `0.125 / 16 / 0.1 / 0.05 / 0.98` 这类裸数字**（INV-11）。
原来 Live2D 用 `0.98` 表示留 2% 边距，现统一写成 `1 - CAMERA.FIT_MARGIN`。

## 四、手势语义

| 输入 | 语义 | 要点 |
|---|---|---|
| **滚轮** | 每触发一次 = 一档，固定 ±10% | **只看 `deltaY` 方向，不看幅度**；不换算成 `deltaY/120`；不做加速度/惯性 |
| **拖动** | 屏幕像素增量直接交给 backend | 内容跟随手指（相机反向移动）；每帧合并，避免拖动风暴里多次重算 |
| **双指捏合** | `起始 scale × (当前两指距离 / 起始两指距离)` | **距离比乘法**（绝对式，不累积漂移），不是每帧增量 |
| **双指中点位移** | 单独走 pan | 缩放与平移作用于不同字段，同一次 move 里先缩放再平移 |
| **双指 → 单指** | 用剩余手指位置重建起点 | 不跳变 |
| **复位** | 归 1（或保留当前缩放）+ 让 backend 重新 fit | 不是简单把数值归零 —— 会重算 `baseZoom` |

**锚点一律是视口中心**，不做「围绕光标缩放」。
副作用：滚轮时光标下的细节会移动 —— 这是**接受的既有行为**，不是缺陷。

**触控板捏合**走 `wheel + ctrlKey` 同一条路径，表现为逐档 ±10%，不另开分支。

## 五、三条几何等式（必须写死）

```
① 覆盖层容器：position:absolute; inset:0（= 舞台的 100%），不参与布局、不改变舞台尺寸
   → 断言 overlayRect === stageRect（每次 activate 与 resize 后）

② 渲染器像素尺寸 = 覆盖层 CSS 尺寸 × 引擎口径 DPR
   → 断言 overlayCanvas.width === cssW × effectiveDpr，且 === stageCanvas.width

③ 模型缩放基准：fitScale = min(vpW / boundsW, vpH / boundsH) × (1 − FIT_MARGIN)
   → vpW / vpH 用**引擎侧逻辑尺寸**（canvas.clientWidth/Height），不是 canvas 像素尺寸
```

**②的由来**：覆盖层初始 `display:none` 时 `clientWidth/clientHeight` 为 0，
渲染器会退回默认尺寸（如 800×600）；若首次可见时不重新校准，画面就按错误的逻辑空间绘制，
表现出来是「一块内容矩形」。所以**禁止在隐藏态读尺寸**，且从隐藏变可见后必须重新校准一次。

## 六、同一个 `scale` 在两种模型上的物理含义（数学基础）

```
Spine ：camera.zoom = baseZoom / userScale
        ⇒ 视野宽度 = viewportWidth × baseZoom / userScale
        ⇒ userScale 翻倍 = 视野减半 = 模型放大 2 倍

Live2D：model.scale = fitScale × zoomRatio
        ⇒ 模型像素尺寸 = 原始包围盒 × fitScale × zoomRatio
        ⇒ zoomRatio 翻倍 = 模型放大 2 倍
```

⇒ 语义一致（都是**线性放大倍数**），前提是 `fitScale` 取法一致（同一 `FIT_MARGIN`、同一视口口径）。

**这条是「相机统一」成立的数学基础**：统一相机只需保证「同一个 `scale()` 值 → 两种模型放大倍数相同」，
而 DPR / 画布 / 边距三者必须同源（第五节）。

## 七、fit 与主体包围盒

**问题**：用「全部部件的并集包围盒」做 fit，遇到带大场景板的模型会把人物压得很小
（场景板远大于人物 ⇒ 包围盒被撑大 ⇒ 缩放系数很小）。

**规则**（按优先级，逐级退化，每级降级都打 warn）：

```
① 部件名命中 SUBJECT_EXCLUDE（不区分大小写、子串匹配）→ 整件排除
② 名字不可用 / 无有意义命名 → 退回 alpha 并集（剔除全透明区域）
③ 两条都不足 → 退回全包围盒
```

Live2D 没有骨骼，等价实现是「只用可见绘制件的 alpha 包围盒」。

**测量必须在渲染 ≥1 帧之后进行**，且结果缓存到模型实例上（不要每帧重算）。

## 八、背景所有权与透明清屏

### 8.1 三条所有权

| 事 | 唯一负责人 | 其他方只能 |
|---|---|---|
| CSS 几何（舞台区域多大） | StageSurface | 读取 |
| 背板像素尺寸（canvas.width/height、resolution、viewport） | 渲染器，且**只能由 Surface 传入的几何推导** | 不得自行计算 |
| 背景（棋盘 / 纯色 / 透明 / 自定义图） | StageSurface（CSS 写 `data-bg`） | **渲染器不得绘制任何背景** |

棋盘底纹是**舞台容器的 CSS 渐变**，不是模型贴图、不是 canvas 内容、不是渲染库画的。

### 8.2 清屏必须透明（一个真实的坑）

渲染库的构造参数里设「透明背景」可能**不生效** —— 它的 renderer 仍以不透明色清屏，
整块画布盖住舞台的 CSS 背景，只有模型画到的像素不是黑的。
表现：模型周围出现一块矩形，矩形内可见背景色、矩形外纯黑。

**修法三条（都要）**：

```js
app.renderer.backgroundAlpha = 0;       // 构造参数不够，必须显式写 renderer
app.renderer.backgroundColor = 0x000000;
app.renderer.clearBeforeRender = true;
// 覆盖层 canvas 的 CSS 也显式 background: transparent
```

**还有一个更隐蔽的层次**：第三方渲染器在渲染模型时会**直接改 GL 状态**
（如 `gl.clearColor`），而宿主只在启动时读过一次 `backgroundAlpha`，之后清屏用残留值。
所以只在初始化时设一次不够，**必须在每次清屏前强制纠正**：

```js
// 包一层 renderer.clear（幂等，带 __transparentClearInstalled 标记）
renderer.clear = function (...args) {
  gl.clearColor(0, 0, 0, 0);
  renderer.backgroundAlpha = 0;
  return origClear.apply(this, args);
};
```

**常驻断言**：`loadModel()` 完成后采样画布四角，若**四角 alpha 全 > 0** 说明被不透明底盖住，
打 warn 自曝，不依赖人眼发现。

> 注意采样点位置：画面中心通常落在模型上，那里 `alpha=255` 是**正确**的（模型不透明）。

## 九、诊断采集（跨模型对比）

用途：同类模型里只有个别表现异常时，靠截图与零散采样定位不了。

**采集时机**：模型「装载完成且渲染出首帧」后立即采集**一次**，避免污染。

**必采字段**（键名固定，便于逐字段 diff）：

```js
[MODELCMP] {
  id, name,
  internalSize: { w, h, originalW, originalH },   // 模型自身几何
  canvasSize:   { w, h },                          // 内部单位，非像素
  display:  { w, h, x, y, scale, rotation, pivot, anchor },
  bounds:   { x, y, w, h },                        // 全包围盒
  extract:  { w, h, bboxW, bboxH, bboxX, bboxY, opaqueRatio },  // 实际绘制可见范围
  fit: { basis, basisW, basisH, fitScale, appliedScale, offsetX, offsetY, margin },
  textures: [{ w, h }],
  model3: { version, hasLayout, motionGroups, physics, pose },
  viewport: { w, h, dpr }, camera: { scale }, stageMode,
}
```

**硬要求**：

- 字段名 / 单位 / 采集时机三处统一，不同模型之间才可比
- **`extract` 必须做**，不许用 `getBounds()` 替代 —— 后者不含可见范围信息
- 采集失败时输出 `*_error` 字段，不要整条丢掉（否则 diff 会误判「缺失即不同」）

**判定规则**：某字段在异常模型上与正常模型差异 > 20%，且正常模型之间差异 < 5% ⇒ 该字段是差异源。

## 十、验收判据

```
同一 URL、同一操作序列下：
· 三条几何等式全部成立（overlay / canvas / css×res）
· 画布四角 alpha 全 0，模型区非 0
· 两个不同模型（含大场景板与小尺寸模型）表现一致
· Spine 与 Live2D 的滚轮档位、缩放范围、复位行为一致
· 人物主体占比落在 0.35 ~ 0.75；两个差异较大的模型占比差 ≤ 15%
```

**跨渲染的数值比较不成立**（两套美术不同），降级为定性：两种渲染下背景都铺满舞台、模型居中不贴边。

## 十一、明确不做

- **不做「围绕光标缩放」** —— 锚点统一为视口中心
- **不做缩放惯性/缓动** —— 立即生效，避免与帧循环产生额外时序
- **不为 Live2D 实现 `subject` / `animation` 两种 fit 模式** —— 缺骨骼与插槽概念，只做「主体包围盒 + 边距」
- **不统一 pan 的内部乘子** —— Spine 的世界单位换算与 Live2D 的 1:1 跟手是两种正确形态，
  强行统一会让其中一边手感变差
