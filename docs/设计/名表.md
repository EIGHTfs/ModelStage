# 设计 · 名表（规范）

> **位置**：`config/names/<游戏完整中文名>.json`（如 `碧蓝航线.json`）。文件名与 `resources.json` 里根的 `names` 字段**逐字一致**。
> 名表不入主分支，存在 `names` 分支（见 §三点五）。
> **性质**：纯数据文件。手工维护，**没有任何自动生成/同步流程**。
> **目标**：显示效果与旧名表**逐条一致**；本设计只改三件事 —— `name` 支持多语言、删几个无关字段、加显式归并字段。

---

## 一、格式（规范）

```jsonc
{
  "_meta": {
    "v": 2,
    "game": "碧蓝航线",
    "mergeBy": "id"
  },
  "characters": {
    "aerbien_3": {
      "id": "aerbien_3",
      "name":    [ { "lang": "zh", "text": "阿尔比恩" } ],
      "costume": [ { "lang": "zh", "text": "香气来朱阁" } ],
      "icon": "aerbien_3.png"
    }
  },
  "byAsset": { "aerbien_3": "aerbien_3" }
}
```

### 字段定义

| 字段 | 必填 | 含义 |
|---|---|---|
| `_meta.v` | ✅ | 格式版本，当前 `2` |
| `_meta.game` | ✅ | 游戏显示名 |
| `_meta.mergeBy` | ✅ | **声明用条目的哪个字段做归并键**。读方按它取键，不硬编码字段名 |
| `characters` | ✅ | 以**角色 id** 为键（与旧表同）。键 = 该条目的身份 |
| `characters[].id` | ✅ | 归并字段：**同 id 即同一角色**。初始与键相同 |
| `characters[].name` | ✅ | 多语言名数组，**至少一项** |
| `characters[].costume` | ✅ | 多语言皮肤名数组；无皮肤写 `[]` |
| `characters[].icon` | ⬜ | 头像文件名（相对头像根）|
| `byAsset` | ✅ | **资源文件名 → 角色 id**（与旧表同形）|

### 硬规则

```
· name / costume 都是 [{lang, text}]，至少一项（空数组 = 丢名字，校验拦）
· byAsset 的键是真实资源文件名，原样（含大小写、含 _2/_g/_alter 等后缀）
· 不做后缀推断：查表只按文件名精确匹配
· 归并只认 _meta.mergeBy 声明的字段相等，不认文件名相似度
· 没有 normalize / how / source / sourceUrl / generatedAt / counts / nameZh / npc / assets
```

## 二、服务端统一入口

**服务端不认识名表结构**，只当一个文件读。整个服务端关于名表只有一个读入口：

```
src/server/data/names.mjs
  loadNamesTable(namesId) → { table, error, detail }
     · 读 config/names/<namesId>.json
     · 进程内缓存（按 namesId）
     · 原样返回：{ source:'names', specVersion, game, mergeBy, characters, byAsset }
     · 文件不存在 → NO_TABLE；解析失败 → BROKEN；未配置 names → NOT_CONFIGURED
  getNameTable(root)  → 拿到表或 null（拿不到记一条 warn，不静默）
  clearNameCache()    → 导入配置后清缓存
```

**唯一出口**：`GET /api/names?root=<id>`

```jsonc
{ "root":"azurlane", "tableId":"azurlane", "source":"names",
  "specVersion":2, "game":"碧蓝航线", "mergeBy":"id",
  "characters": { …原样… }, "byAsset": { …原样… } }
```

### 硬规则

```
· 服务端不解析 characters[].id / name / costume / icon（头像解析除外，见下）
· 服务端不归一化、不补默认值、不改大小写、不排序、不校验业务字段
· 改名表结构 ⇒ 服务端零改动
· 校验由 tool/check-index.mjs 在提交前做，不在运行期兜底
```

**唯一例外**：`resolveIconUrl()` 需要 `byAsset[key]`（取角色 id）与 `characters[id].icon`（取头像文件名）。
这两处读取集中在 `models.mjs` 的一个函数里，不扩散。

## 三、语言读取

```js
// src/shared/names.mjs
pickName(names, lang = 'zh')
```

**规则**：

```
· 当前只维护中文 ⇒ 调用方一律用默认值，恒定取 lang: 'zh'
· **不接受外部传语言**（页面 / URL / 配置都不传）—— 现在只有中文，做出可选语言是假能力
· 回落链：命中 lang → 'zh' → 数组第一项（数组非空就一定有名字）
· 取不到返回空串，调用方回落显示资源文件名（与旧版一致）
```

**预留**：`lang` 参数是唯一入口，**本次不改**（数据只有中文）。
将来要接多语言时：名表里补第二语言的元素 → 调用处传用户语言 → 回落链自然生效。
不改数据结构、不改服务端、不改 `pickName` 实现。

> 注意：多语言数组是**格式能力**，不是当前功能。当前界面只显示中文；
> 等真有第二语言数据再开参数，避免"能切但没有数据"的假能力。

## 三点五、名表的存放：`names` 分支

名表不进主分支（体积大、且是手工维护的数据，不该混在代码历史里）。

```
主分支 main         config/names/ 在 .gitignore 中，永不入库
分支  names         只放名表：config/names/{碧蓝航线,棕色尘埃2,天命之子}.json + 一份 README
```

**取用**：

```bash
# 只把名表取到工作区（不影响当前分支）
git checkout names -- config/names

# 或克隆后直接切到该分支
git clone -b names <repo> <dir>
```

改完名表提交到 `names` 分支，不要在 `main` 提交它们。

## 四、职责分工

| 位置 | 职责 |
|---|---|
| `config/names/<id>.json` | 数据本体（手工维护）|
| `src/server/data/names.mjs` | 读文件 + 缓存 + 错误码，原样透传 |
| `src/server/data/models.mjs` | 仅头像解析：`byAsset[key]` + `characters[id].icon` |
| `src/shared/names.mjs` | `pickName()` 取值、`mergeKeyOf()` 取归并键 |
| `src/web/roster/list.js` | 查表、归并、显示（唯一消费方）|
| `tool/check-index.mjs` | 结构校验（提交前门禁）|

## 五、验收

```
1. 显示与旧版逐条一致：同一份快照（角色行文本 + 变体行文本）diff 为空
2. 三个游戏角色数 / byAsset 数与旧表相等：2558/2557、231/421、2583/2583
3. 皮肤名不丢：有 costume 的条目数相等 —— azurlane 1512 / bd2 207 / dcg 2378
4. 服务端不认识结构：grep -nE "mergeBy|\.id\b|costume|name\[0\]" src/server/data/names.mjs 为 0
5. 语言：pickName 默认取中文；缺 zh 时取第一项；不传 lang 的调用点全绿
```

## NIKKE 名表的来源与生成规则

`config/names/NIKKE.json` 不是随仓库分发的：`config/names/` 与 `config/resources.json` 都在
`.gitignore` 里（本地配置），入库的只有 `config/resources.example.json`。重建方法如下。

**数据来源**：`<NikkeSpine 项目>/assets/names.json`（该查看器自带 80 个角色的中文名）

```
{"c010": {"name": "拉毗", "skel": ["00"]}, "c011": {"name": "尼恩", "skel": ["00"]}, ...}
```

**生成规则**（资源键 → 角色号用正则 `/^(c\d+)/`，不依赖目录层级）：

```
1. 读我们的清单 config/models/spine.nikke.json，取出所有模型名（如 c010_00、c010_aim_00、c010_cover_00）
2. 每个模型名取开头 c<数字> 作为角色号（→ c010），归入该角色
3. characters：每个角色号一条，name 取源名字；byAsset：每个模型名 → 角色号
4. 顶层写 _meta: {v:2, game:"NIKKE", mergeBy:"id"}（同角色多变体按 id 合并成一行）
5. 在 config/resources.json 的 nikke 根上加 "names": "NIKKE"
```

**实测覆盖**：源 80 条 ↔ 我们的 247 个模型名，247/247 全部归类成功、0 个角色号在源里缺名。

**已知未做**：变体（`00` / `aim` / `cover` / `skillcut`）在名册里仍显示资源目录名，
没有中文标注。若要显示"瞄准 / 掩体 / 技能立绘"，需要走名表的 costume 字段，
并确认前端消费 costume 的方式（当前只用了 characters + byAsset）。
