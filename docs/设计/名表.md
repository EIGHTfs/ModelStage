# 设计 · 名表（v2 索引表）

> **状态：提案，尚未实施。**
> 当前生效的是 v1 名表（`config/names/<game>.json`）。本文描述的是把「名表 + 匹配表 + 头像目录」
> 三件合并成一份本地索引表的重设计，实施前不要按本文操作。
>
> 相关：接口见[参考/接口清单](../参考/接口清单.md) §一；资源根配置见 `config/resources.json`。

---

## 一、要解决的痛点

| # | 痛点 | 事实 |
|---|---|---|
| P1 | **主键脆弱**：名表以资源目录名（多为拼音）为键 | 部分目录是后缀变体（`_ii` / `_new` / 罗马数字），上游表无此键 ⇒ 界面回退显示拼音 |
| P2 | **中文名依赖上游数据** | `nameZh` 全部由上游 JSON 转出，上游缺则空 |
| P3 | **头像与资源仓绑定** | 头像目录被删则全破图；头像源仓与资源仓分离 |
| P4 | **新游戏接入全靠手工写转换器** | 每个游戏一个导入脚本，重复劳动 |
| P5 | **覆盖率无运行时记录** | 头像/名字命中数只在生成时算一次，运行时无感知 |

## 二、核心思路

```
一个 config/index/ 目录，本地手工维护：
  每游戏一个索引文件，记录「资源键 → 角色 ID → 多语言名称 → 头像」

角色 ID 用各游戏原生稳定 ID（数字 ID / ship id / 前缀 ID / 角色代码）
资源目录名降级为「匹配线索」
名称支持多语言，本地手工补的永远优先于上游（重跑不覆盖）
头像本地化，运行期零外仓依赖
上游数据只当初始导入的原料，之后本地表是权威源
```

## 三、数据模型

```jsonc
// config/index/<game>.index.json
{
  "_meta": {
    "v": 2,
    "game": "碧蓝航线",
    "idSemantics": "ship_id",                  // 本游戏角色 ID 的语义（按游戏异构）
    "roots": ["azurlane", "azurlane_spine"],   // 本索引服务的资源根
    "normalize": "strip-suffix:_ii,_new,_hx + roman-numerals",   // 归一化规则（按游戏可配）
    "updatedAt": "…"
  },
  "characters": {
    "62": {                                     // 角色 ID（各游戏原生 ID 的字符串形式）
      "name": [                                 // 角色名：数组，元素为各语言名
        { "lang": "zh", "text": "阿尔比恩" },
        { "lang": "en", "text": "Albion" }
      ],
      "costumes": {                             // 皮肤：皮肤 ID → 多语言名（同结构）
        "3": { "name": [ { "lang": "zh", "text": "晨光里的事故" } ] }
      },
      "avatar": "62.png",                       // 头像文件名（相对头像库；无则省略）
      "tags": ["轻巡"]                          // 可选，树内筛选用
    }
  },
  "byAsset": {                                  // 资源键归一化 → { 角色ID, 皮肤ID? }
    "aerbien_3":      { "char": "62", "costume": "3", "how": "upstream" },
    "dahuangfengii_2": { "char": "97", "costume": "2", "how": "manual" }
  }
}
```

**多语言名称约定**：

- 角色名与皮肤名统一用 `name` **数组**表达，元素为 `{ lang, text }`
- 语言字段**可缺**（某语言没有就不写该元素），但**至少一个** —— 校验对空数组报错拦截
- 界面显示顺序：当前界面语言 → 中文 → 数组第一个元素；全部缺失才回退资源目录名

**要点**：

- **一份文件管全部**：角色、皮肤、多语言名、头像文件名、资源键匹配都在里面，
  界面与服务端只读它，不再拼「名表 + 匹配表 + 头像目录」三件
- `byAsset` 的键是**归一化后的资源键**，规则写在 `_meta.normalize`（按游戏可配）
- `how` 字段标记来源（`upstream` / `fuzzy` / `manual`），导入工具重跑时**保留 manual 条目**
- **v1 兼容**：`config/names/*.json` 保留只读，读索引表失败时回退 v1，迁移期双轨

## 四、头像本地化

```
组织：<游戏>/<角色ID>.png（皮肤级头像 <角色ID>_<皮肤ID>.png，可选）
暂存：单独一个私有仓存全部游戏头像，不进主项目仓（主仓保持轻量）
部署：本机拉到固定位置，resources.json 的头像根指向它
```

**三条提取路**（一次性工具，提取后可删）：

1. 资源目录自带 `icon.png` → 首扫时拷入
2. 仓内头像目录 → 全量拷入并按索引表重命名为 `<角色ID>.png`
3. 无源 → 占位图（界面兜底，不阻塞）

**纪律**：头像仓只进 png 与清单 json（每游戏一份 `<角色ID> → 文件名` 映射），不混入代码。

## 五、已定决策

| # | 决策 |
|---|---|
| D1 | **角色 ID 语义按游戏异构**：接受。`_meta.idSemantics` 写明每游戏 ID 语义；界面只显示名字不显示 ID，异构无碍 |
| D2 | **头像不入主仓，入单独私有仓**。主仓 index 只存 `avatar` 文件名，文件本体在头像仓 |
| D3 | **多语言名用 `name` 数组**（元素 `{lang, text}`）：子字段可缺，数组不能为空 |
| D4 | **界面补录暂不做**：本期只做「未命中红点提示 + 手工改 index.json」，不做写回端点 |
| D5 | **游戏内本地化表可导入**：从游戏自带的多语言 Excel/JSON 表抽角色名作 index 初稿（`how: upstream`），人工再补 |

## 六、扩展新游戏的最小步骤

```
1. 克隆资源仓到本机（资源仓与项目仓分离，资源不进项目 git）
2. 写 config/index/<game>.index.json 初稿：_meta（idSemantics / roots / normalize）+ 名字源
3. 头像：跑对应提取器进头像仓的 <game>/（或置空占位），头像仓推送、本机拉取
4. resources.json 加根，names 字段改指新 index（v2 读 index、缺则回退 v1）
5. 界面跑通：byAsset 命中项正常聚合，未命中项红点提示 → 手工补 byAsset（how: manual）
```

## 七、实施改动面

| 子系统 | 改动 |
|---|---|
| 名表 spec 工具 | 升 v2 schema + v1 迁移函数；`check` 拦空 `name` 数组 |
| 头像仓（私有） | 各游戏 png + 清单 json；主仓 `.gitignore` 掉本机克隆目录 |
| 服务端 | 只改两块：名表读取（index 优先、v1 兜底）+ 头像 URL 解析（头像仓目录优先） |
| 角色树聚合 | 聚合键改「资源键 → 归一 → byAsset → 角色 ID」；未命中红点 + `how` 提示 |
| 导入工具 | 每游戏一个 `import-index-<game>`，只产出初稿，合并时保留 manual |
| `resources.json` | 碧蓝两根路径切全量仓；v2 下 `icons.dir` 弃用 |

## 八、验证标准（实施后）

```
1. 各游戏 index.json 全过 spec 校验（空 name 数组报错）
2. 碧蓝未命中目录清零（normalize 规则覆盖后缀变体）
3. 断源测试：删掉全部资源仓，头像仓 + index.json 仍能显示名字与头像
4. 回归：跨格式聚合（同一角色同挂 Live2D + Spine）行为不变，无头渲染自检通过
```
