# 插件插槽：面板、工具栏与舞台叠加的扩展点

> 状态：**设计草案，未落地代码**。
> 取代 `docs/设计/插件扩展点-renderer与panel.md` 里 `panel` 角色的"合并控件表"部分（那份仍有效的部分见文末「与既有设计的关系」）。

---

## 一、要解决的问题

插件目前只能贡献**资源处理能力**（`asset-provider`：`canHandle` / `resolve`）。
它不能往界面上加任何东西 —— 面板、工具栏、舞台叠加层都只能改宿主源码。

旧方案（`registerControls({group, controls})`）只覆盖了"往面板加控件"这一种形态，且有三个缺口：

```
① 只能追加，不能替换/占位 —— 想换品牌名、想替换某个内置控件的选项集，没有位置可注册
② 没有排序位 —— 多个插件往同一分组加控件时，谁先谁后无解
③ 没有回收语义 —— 插件被禁用/卸载/加载失败后，残留要靠各处手写清理
```

---

## 二、设计来源与取舍

借鉴"插槽树"模型：**界面不是写死的代码，而是一棵插槽树；插件往插槽里注册内容，外壳只负责摆位**。

| 借鉴 | 说明 |
|---|---|
| 三种插槽类型 | 单值（覆盖）/ 列表（按 order 追加）/ 键值（按字符串键各占一格） |
| 注册契约 | `id` / `order` / `label` + 宿主注入的 **owner props** |
| 生命周期 | `register` 返回 disposer，交给宿主统一回收；卸载即还原 |
| 风险等级 | 插槽目录标注「追加」还是「遮蔽」，装之前可见 |

**不照搬的两处**（本项目形态不同，照搬代价大于收益）：

```
① 不引入 ESM 动态模块与依赖注入：现有插件是经典脚本挂 window 全局，装载模型不变；
   只把 API 收敛为 window.ModelStagePlugins.slots
② 不造"会话/工作区/权限"钩子：单机查看器没有这些概念，空壳钩子只会误导后来人
```

---

## 三、插槽树（第一版只开右栏三项，顶栏与舞台叠加留后）

| 插槽 | 类型 | 语义 | 典型用法 | 风险 |
|---|---|---|---|---|
| `panel.brand` | 单值 | 后注册覆盖先注册 | 换品牌名 / 副标题 | replace |
| `panel.group.<name>` | 列表 | 按 `order` 追加到指定分组 | 往「设置」组加控件 | append |
| `panel.control.<key>` | 键值 | 按控件 id 占位，可整体替换该控件 | 替换某内置控件的选项集 | replace |
| `toolbar.actions` | 列表 | 按 `order` 追加按钮 | 截图 / 对比 / 重置视角 | append ｜ **第二步** |
| `stage.overlay` | 列表 | 按 `order` 叠加到画布之上 | 调试叠加层 / 水印 | append ｜ **暂不排期** |

**风险语义**（写进插槽目录，`/api/plugins` 一并下发）：

```
append  —— 只追加，不动原生内容。默认允许
replace —— 会替换同位置的原生内容。插件必须在 plugin.json 的 slots 里**显式声明**才能注册
shadow  —— 会遮蔽原生界面（第一版不开放任何 shadow 插槽）
```

未在清单里声明的插槽，注册时**直接拒绝并记一条 warn**（不是静默忽略）——
否则"装之前就能看到它会遮蔽什么"这句话不成立。

## 四、注册契约

```js
// 插件脚本（经典脚本，与现有插件同一装载方式）
const slots = window.ModelStagePlugins.slots;

const dispose = slots.register('panel.group.设置', {
  id: 'sharpness.control',      // 必填，同插槽内唯一
  order: 100,                   // 可选，仅列表插槽有意义（小在前）
  label: '清晰度',               // 必填，可读名（诊断与冲突提示都用它）
  render(props) {               // 返回声明式控件描述，不操作 DOM
    return { kind: 'segmented', options: ['关', '轻', '强'], value: props.settings.sharpness };
  },
  onAction(action, props) {     // 用户操作回调（可选）
    props.setSetting('sharpness', action.value);
  },
});

// 插件卸载时
dispose();
```

### 4.1 owner props（宿主注入的只读上下文）

**现状可复用**：`panel/view.js` 的 `renderControl(ctl, ctx)` 已经带一个 `ctx`，其中已有
`isWired(id)` / `initialValue(id)` / `onSetting(id, value)` / `disabledReason(id)`。
本设计**不推翻它**，只把 ctx 补成标准 owner props（下表里标"已有"的三项直接沿用）。

| 字段 | 内容 | 为什么需要 |
|---|---|---|
| `geometry` | `{ cssW, cssH, dpr }` | 叠加层要按实际像素定位，不能让插件自己量 DOM |
| `activeSurface` | `'spine' \| 'live2d' \| null` | 控件要按当前渲染面显示/隐藏 |
| `document` | 只读摘要 `{ rootId, rel, kind, files }` | 插件要知道"现在看的是什么"，但不该拿到可变引用 |
| `settings` | 只读视图 + `setSetting(key, value)` | 控件读写设置只能走这条通道（能力键白名单仍然生效） |

**约束**：owner props 每次渲染重新计算并冻结；插件**不得**持有跨渲染的引用（宿主不保证对象身份稳定）。

### 4.2 回收

```
register() 返回 disposer；宿主把它登记进该插件的 effect 列表
插件卸载 / 被禁用 / 加载失败 / 热重载 → 宿主按**注册逆序**调用全部 disposer
```

这是本设计里最该先落地的一条：没有它，插件一旦能碰界面，残留就只能靠人肉排查。

## 六、验收判据

```
1. 插件装上：右面板出现其声明的控件，位置在约定分组内、按 order 排序
2. 两个插件往同一列表插槽注册：按 order 排列，互不覆盖；id 重复时后注册者被拒绝并给出冲突提示
3. 插件未声明 replace 类插槽却尝试注册：被拒绝 + warn（不是静默忽略）
4. 卸载插件（禁用或删目录）：控件消失、原生界面完全还原（截图与安装前逐像素相同）
5. 加载失败（脚本抛错）：已注册部分被回收，界面回到无插件状态，并在诊断面板给出原因
6. 插件新建分组：出现在面板中、order 排在所有内置组之后、id 带 plugin.<pluginId>. 前缀；
   与内置组同名时诊断日志有提示
7. 回归：不装任何插件时，面板控件数、顺序、默认值与本设计落地前逐项一致；
   浏览器测试的组数断言为"内置 9 组必须都在 + 允许额外组"
```

## 七、分步落地

**范围决定：第一版只做右栏，顶栏留第二步。**

```
第 1 步：插槽基础设施 + 右栏插槽（含允许插件新建分组）
  · 插槽表 / order 排序 / disposer 回收 / 清单校验 / /api/plugins 下发
  · schema 从静态常量改为"内置表 + 插槽聚合"；group id 已稳定（motion/skin/play/filter…）可直接作插槽名
  · 把既有 registerControls 改造成往 panel.group.<name> 注册（行为不变，先证明基础设施对）
  · 允许插件新建分组 —— 规则见 §七·一；同时把浏览器测试断言改成"内置 9 组必须都在 + 允许额外组"

第 2 步：单值插槽
  · panel.brand（单值）验证覆盖语义与"卸载还原"

第 3 步：顶栏（toolbar.actions）
  · 先付前置账：内置 5 个按钮从 index.html 手写迁成声明式表，否则插入点与排序无定义
  · 图标只能给白名单图标名（复用 panel/icons.js）+ 文本兜底，不许插件塞 SVG/DOM
  · 按钮插在 header 内部，影院模式自动跟随隐藏；窄屏需要上限或溢出菜单

第 4 步（暂不排期）：stage.overlay
  · 涉及渲染层与画布事件，风险高于面板；等真实需求出现再开
```

### 七·一、插件新建分组的规则

```
命名：分组 id 必须带插件前缀 `plugin.<pluginId>.<name>`（防两个插件撞名、也便于诊断时一眼看出归属）
排序：内置组的 order 为 0~99；插件组缺省 order = 1000，同 order 按注册先后
冲突：id 已存在 ⇒ 拒绝注册 + warn（列出冲突的双方），不静默覆盖
标题：label 必填；允许与内置组同名（id 不同），但要在诊断日志里提示"与内置组同名"
```
