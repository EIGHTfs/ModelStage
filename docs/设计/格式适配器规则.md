# 规则：新增格式只加适配器，不改扫描器

## 规则

```
文件格式差异（JSON / JSONL / 二进制 / 未来其它）只能出现在「适配器」层。
扫描器只产出内存模型，不感知磁盘上的编码方式。
```

## 现状落点

| 层 | 文件 | 职责 |
|---|---|---|
| 适配器 | `src/server/data/manifest-jsonl.mjs` | 读写 `.json` / `.jsonl`，双读回落，`complete` 判定 |
| 扫描器 | `src/server/data/spine.mjs`、`live2d.mjs` | 生产内存模型（models 数组 + 头字段），不做编码分支 |
| 消费者 | `src/server/data/catalog.mjs`、`src/routes/*` | 只认 `readManifest()` 的返回形状 |

## 判据

```
新增一种存储格式时：
  ❌ 不在 spine.mjs / live2d.mjs 里加 if (format === …)
  ✅ 在适配器里加一条读写分支，对外仍返回 { meta, models, complete, badLines }
```

## 为什么

同一份数据只有一处编码真相。扫描器里一旦出现格式分支，新增格式就要改 N 个扫描器，
且两条路径的字段口径会漂移（历史上 spine 与 live2d 的清单头就分叉过：多出 rootName/count/version）。
