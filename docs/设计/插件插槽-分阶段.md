# 插件插槽：分阶段实施骨架

> 状态：**阶段骨架，等待调研补充细节**。设计依据见 [插件插槽](插件插槽.md)。
> 每个阶段必须能独立验证、独立回退；上一阶段不通过不进入下一阶段。

---

## 分阶段原则

```
① 每阶段一个可观测的验收动作（curl / 浏览器测试 / 截图），不靠"代码看着对"
② 每阶段结束时主链行为与开工前一致（不装插件时界面逐项不变）
③ 后一阶段只在前一阶段验收通过后开始；不允许"先铺开再一起调"
④ 每阶段单独提交，提交信息写明本阶段验收结果
```

---

## S1 · 插槽注册表与清单校验（无界面变化）

**做什么**

```
· 前端：window.ModelStagePlugins.slots.register / 插槽表 / disposer 列表（此阶段只登记，不渲染）
· 服务端：plugin.json 校验新增 slots 字段（字符串数组），对照插槽目录校验风险等级
· /api/plugins 下发每个插件声明的插槽与风险等级
· 未在清单声明的插槽 → 注册时拒绝 + warn（不静默忽略）
```

**验收**

```
1. curl /api/plugins：能读到 slots 与 risk（无插件声明时为空数组，不报错）
2. 单测：未声明插槽注册被拒绝、已声明通过、风险等级不符被拒绝
3. 不装插件时界面零变化（面板控件数/顺序与开工前一致）
```

**回退**：删掉注册表与校验，界面本来就没变。

---

## S2 · 列表插槽接入右栏（只往既有分组加控件）

**做什么**

```
· schema.js 从静态常量改为"内置表 + 插槽聚合"
· panel/view.js 渲染时合并插槽贡献；order 排序；id 冲突拒绝
· 既有 registerControls 改造成往 panel.group.<name> 注册（行为不变）
· 插件自定义设置键按清单声明并入 capabilities.settings（§8.3）
```

**验收**

```
1. 样例插件往「设置」组加一个开关：面板出现该控件、位置在组内末尾（order 缺省）
2. 控件值能存住并回读（刷新后保持）
3. 卸载插件：控件消失，内置控件逐项不变
4. 浏览器测试：内置 9 组仍全在、控件数 = 内置 + 插件
```

**回退**：恢复 schema 为静态常量，插槽贡献不参与渲染。

---

## S3 · 允许插件新建分组

**做什么**

```
· 分组 id 强制 plugin.<pluginId>.<name>；内置组 order 0~99、插件组缺省 1000
· 与内置组同名允许但诊断提示；id 冲突拒绝
· 浏览器测试断言改为"内置 9 组必须都在 + 允许额外组"
```

**验收**

```
1. 样例插件新建分组：出现在面板中、排在内置组之后、标题正确
2. 内置 9 组仍在且顺序不变
3. 与内置组同名：出现且诊断日志有提示
4. 浏览器测试通过（断言已改）
```

**回退**：拒绝新建分组（只保留往既有组加控件）。

---

## S4 · owner props 扩展（geometry / activeSurface / document）

**做什么**

```
· 现有 ctx（isWired / initialValue / onSetting / disabledReason）保持不变
· 补 geometry（cssW / cssH / dpr）、activeSurface（spine / live2d / null）、document（只读摘要）
· 每次渲染重新计算并冻结，插件不得持有跨渲染引用
```

**验收**

```
1. 样例插件控件按 activeSurface 显示/隐藏（切到 live2d 时隐藏，切回 spine 时出现）
2. 叠加类用法能拿到 geometry（在 canvas 尺寸变化后数值跟着变）
3. 面板既有控件行为零变化（回归浏览器测试）
```

**回退**：从 ctx 移除三项新增字段（插件侧降级为不可用）。

---

## S5 · 键值插槽与单值插槽

**做什么**

```
· panel.control.<key>（key 强制 plugin.<pluginId>.<key>）：按控件 id 占位/替换
· panel.brand（单值）：后注册覆盖先注册，卸载还原
```

**验收**

```
1. 键值插槽替换某内置控件的选项集：面板显示新选项、原控件不再出现
2. 单值插槽换品牌名：显示新文本；卸载后还原为 ModelStage
3. 两个插件抢同一 key：后注册者被拒绝并给出冲突双方
4. 卸载后截图与安装前逐像素相同（还原性）
```

**回退**：关闭这两类插槽（保留列表插槽）。

## 调研汇总（前端 / 服务端已回，测试待回）

### 现状偏差：骨架与代码不符的两处

```
① S2 **已半落地**：registerControls（plugin-host.js:236）、mergePluginControls、
   spineviewer:plugins-loaded 事件链（plugin-host.js:1277 → panel-settings.js:372）都已存在
   ⇒ S2 不是从零做，而是"把已有的控件合并改造成插槽注册"，范围要相应缩小
② S3 现在是**硬拒绝**：schema.js:341 对"插件新建分组"直接拒绝
   ⇒ S3 是"解除硬拒绝 + 改断言"，不是新增能力
```

### 两条高风险（必须前置到 S1，否则后面无法收场）

```
H1 没有 effect 容器、也没有卸载入口
   controlSections 只 push（plugin-host.js:244），全仓无删除；禁用插件 = 改配置 + 刷新
   ⇒ 插槽 disposer 若只挂"插件卸载"，实际只有"页面关闭"一个调用点，等于没有回收
   ⇒ S1 必须同时做：插件级 effect 容器 + unloadPlugin(pluginId)（即使界面还没接，也要能验证回收）

H2 注册窗口是瞬时的
   loadingPluginId 在 plugin-host.js:262 设、:273 清，窗口外注册拿不到 pluginId（只有一条 warn）
   ⇒ 异步注册（Promise/await 之后）必然被丢；插槽比控件更容易写成异步
   ⇒ 契约写明：register 必须同步调用；异步注册要被显式拒绝并给出可读原因
```

### 关键设计裁定（补进设计文档的口径）

```
① 聚合点：装配期（panel-settings.js 的合并处），schema.js 只提供纯函数合并；
   view.js 已接受 groups 参数，保持无感知 —— 不原地改 PANEL_GROUPS（它同时被 uiState SPEC 与测试遍历）
② 插槽目录**不在前端存副本**：单一来源 = /api/plugins 的 slotCatalog + slotErrors
③ 错误码分两值：unknown-slot（目录里没有）/ slot-not-open（有但阶段未到），文案不同
④ 分组匹配改用**稳定 id**（更正：内置组 id 早已存在，不需要补字段）
   九组 id 在 schema.js:47/59/69/108/135/154/162/204/220，view.js:340 已在用；
   问题只在两处按 title 匹配（schema.js:424-425 的 groupTitles、schema.js:341 的硬拒绝）⇒ 改按 id，约 2 行
   插槽命名随之从 `panel.group.设置` 改为 `panel.group.settings`（契约已同步）
⑤ owner props 用 **getter** 而非快照：geometry 来自 surface.geometry()（resize 后面板没订阅）、
   document 来自 state.selectedModel（换模型不重建面板）—— 快照会陈旧
⑥ 断言影响面：真正会挂的只有"组名逐字相等"（panel-actions.js:337 与 :445 的全等比较），
   组数与控件数都是动态取的（:301 / :453 / :198-201）
```

### 阶段范围修正（据上）

```
S1 追加：插件级 effect 容器 + unloadPlugin(pluginId) + 同步注册约束（H1/H2）
S2 缩小：改造既有 registerControls 为插槽注册（控件合并链路已存在）
S3 改为：解除 schema.js:341 的硬拒绝 + 改 expectTitles 断言 + 内置组补稳定 id
S4 追加：owner props 用 getter（geometry / document 会变，不能快照）
```

### 一条现状缺陷（与插槽无关，但会被插槽放大）

```
现象：面板重建会把用户手风琴展开态丢弃（实测 8899，真实入口 spineviewer:plugins-loaded）
      缺省 动作:开 设置:开 → 用户改成 动作:收 皮肤:开 → 重建后回到缺省
      节点被整体替换（.acc-trigger 全换），展开态只写在 DOM 上（view.js:341/370/373），无处可存
触发条件：该重建**当前无条件执行** —— dataset.pluginControls=0 时也重建
      ⇒ 「首次点容器包 → 插件装载完成 → 我展开的组被收起」今天就在发生，只是没人归因到这条链
修法（建议）：mountPanel 前把 aria-expanded 收成 Map<groupId, boolean>，渲染时优先读它（仅内存，不落盘）
      好处：同时覆盖"换渲染面"那条重建路径（main.js:518-520），那条现在同样会重置
归属：放 S1（与 effect 容器同一批），因为它属于"重建时机"这条链
```

### 测试侧要点（据测试调研）

```
· 组数断言已不写死（读 dataset.panelGroups）；唯一写死处是 expectTitles 的 9 个组名（S3 改）
· 还有三条硬断言不能放宽（未接线 disabled + data-pending 等），S2/S3 时期必须保住
· 还原性验收可用 #right-panel.outerHTML 逐字节比较（比"结构一致"严格、比逐像素稳定）
```

## 三份调研交叉汇总（前端 / 服务端 / 测试）

### 三方一致（可直接按此实现）

```
① 插槽目录单一来源 = 服务端常量表，随 /api/plugins 下发；前端不存副本
② 校验放清单校验期（"装之前可见"是这条的唯一成立条件）；非法项逐项降级，不整体拒绝
③ 组数断言本来就动态（读 dataset.panelGroups），只有 expectTitles 的九个组名是写死处
④ capabilities.settings 的并入点已存在（panel-settings.js:325 withPluginCapabilities），服务端只做校验+下发
```

### 两处必须补的实现增补（调研才暴露，原设计没写）

```
A. DOM 要暴露分组 id：现在手风琴节点只有标题文本，测试无法断言"额外组必须 plugin. 前缀"
   ⇒ panel-settings.js 渲染时写 data-group-id（约 1 行）
B. 插件控件的"孤儿能力键"检查会被跳过：orphanCapabilities 遍历的是静态表 PANEL_GROUPS
   （panel-actions.js:288-296），插件控件是渲染期合并出来的新数组 ⇒ 天然免检
   ⇒ 必须显式补一条：遍历"实际渲染的 groups"而不是静态表
```

### 一条不能放宽的底线（测试调研点名）

```
"来自插件"不能作为免检理由：
  enabledIds === declaredWired / disabledAllPending / orphanCapabilities === 0 / gateMiss === 0
  这四条在插件控件上同样成立，S2/S3 不许放宽
```

### 现状缺陷（前端补测实测，与插槽无关但会被放大）

```
面板重建丢弃手风琴展开态，且重建当前无条件执行（pluginControls=0 也重建）
⇒ 修法：重建前收 aria-expanded 成 Map<groupId, boolean>，渲染时优先读（仅内存）
```

## S1 拆分（有依赖，故拆两段）

```
S1-a（服务端，可先做）
  · 插槽目录常量表（name / type / risk / stage）+ plugin.json 的 slots / settings 校验
  · /api/plugins 下发 slotCatalog 与每插件的 slotErrors / settingsErrors
  · 校验顺序按设计 §4.2：unknown-slot → slot-not-open → undeclared-slot → risk-mismatch
  · 验收：curl 看 slotCatalog 形状；单测覆盖四类拒绝；老插件零改动可用

S1-b（前端，依赖 S1-a 的 slotCatalog）
  · 插件级 effect 容器 + unloadPlugin(pluginId)

  · 验收：浏览器脚本断言"已声明可注册 / 未声明被拒 / 卸载后登记表清空 / 重建后展开态不变"
```

## 六条口径定案（据三份调研的待确认项）

```
① 聚合结果**不得**进入 PANEL_GROUPS 静态导出
   否则 check-wiring 的 W2 会把插件控件报成孤儿能力键（误报）。聚合只在装配期产出新数组
② 渲染时写 data-group-id
   测试要断言"额外组必须 plugin. 前缀"，现在 DOM 只有标题文本；写入约 1 行
③ 还原性验收用 #right-panel.outerHTML 逐字节比较，归一化清单固定为：
   忽略 aria-expanded / 行内 style / 滚动位置 / 临时 class（含 data-pending 之外的时序类）
   第一版不做像素比对（软渲染下不可信）
④ 新增浏览器套件进 BROWSER_SUITES 但**不进 --all 默认门禁**
   提交门禁仍用 --all（避免每次提交都拉长）；S3/S5 验收时显式跑 --browser
⑤ "卸载后控件消失"属功能实现，**不留 skip 用例**：S1-b 一并实现 unloadPlugin，测试随之落地
⑥ 诊断出口用 window.__SLOT_STATS__（测试实例注入），不动既有 dataset.panelGroups / pluginControls
   避免 dataset 与 outerHTML 快照比对互相打架
```
