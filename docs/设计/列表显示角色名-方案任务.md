# 任务：左侧列表显示 `__data` 内的角色名 —— **只出方案，不改代码**

## 一、现象

左侧列表里容器条目全部显示 `资源包 __data`，无法区分谁是谁（截图里一屏十几个同名项）。

## 二、已验证的事实（可以直接用，不用重查）

```
① 包目录里只有 __data（181 个包中 173 个只有这一个文件，另 8 个多一份 README.txt）
   ⇒ 名字不可能来自目录里的旁文件，只能来自 __data 内部

② /api/analyze?path= 已经能拿到名字：
     00044c1c… → textAssets: cutscene_char000707.skel / .atlas
     f4721b1b… → textAssets: cutscene_char004091_1.skel / cutscene_char004091.skel / 两个 .atlas
   ⇒ 骨架名就是可读的角色名（cutscene_char000707 / npc_ellin / specialIllust51 …）

③ 当前 catalog 的 bundle 条目：id = bundle-<rootId>-<hash1>_<hash2>___data，name = "__data"
```

## 三、要解决的问题（方案必须回答）

```
1. 名字从哪取：TextAsset 里的 .skel 名（去掉 .skel）？多个骨架时取哪个？
   （f4721b1b 有两个骨架 char004091 与 char004091_1 —— 显示哪个、还是都显示？）
2. 什么时候取：
   a) catalog 阶段同步取（列表一次就要解析 N 个包）
   b) 列表先显示 __data，后台渐进补名字（类似扫描进度的做法）
   c) 滚动到可见才取（懒加载）
   d) 扫描时随清单一起落盘（一次算好，之后读缓存）
3. 性能与成本（必须给实测或估算）：
   · 181 个包，多数几十 MB；解析一次要读全文件 ⇒ 全量预读的总 I/O 与耗时
   · 是否只读"够用的字节"（容器头 + blocksInfo + CAB 对象表 + TextAsset 头），
     不全量解 —— 若可行，成本会低一到两个数量级，请优先考虑这条路
4. 缓存：名字存在哪（内存 / 清单 / 独立 json），失效条件是什么
5. 失败与降级：解析失败、加密包、非 UnityFS 时显示什么（保持现有 "__data" 兜底）
6. 与现有能力的关系：复用 /api/analyze 的分析实现，还是另写一条"只取名字"的轻量通道
   （后者更快，但要保证与 analyze 结论同源，不能两套解析）
```
