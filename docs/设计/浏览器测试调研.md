# 浏览器测试调研：哪些真的需要浏览器

> 状态：**调研稿（未改动任何测试）**。目的：先看清现状与可迁移比例，再决定怎么重写。
> 配套新规：**能静态扫/单元测/API 断言解决的，禁止起浏览器。**

## 一、要解决的问题

```
现状：浏览器注入测试共 10 个脚本、5188 行、94 条显式断言。
问题：其中相当一部分（控件清单、分组标题、localStorage 键名、/api/roots 的 CRUD 与错误码…）
      用脚本扫描 / node 单测 / HTTP 断言就能验完，却要起一次无头 chromium。
目标：只把**真正依赖浏览器**的断言留在浏览器里，其余迁出去。
```

## 三、四级判据（决定该用什么测）

```
第 1 级  纯逻辑                     → node --test（不需要服务、不需要 DOM）
         例：名册合并语义、搜索匹配、类型派生、默认值表、序列化/反序列化

第 2 级  HTTP 契约                   → node --test + 临时服务（仍然不需要浏览器）
         例：/api/roots 的 add/rename/toggle/remove、400/409/404、merged 语义

第 3 级  源码/契约表结构              → node --test 读文件断言（静态扫描）
         例：HTML 里有哪些按钮 id、schema 里有哪些控件、分组标题集合、localStorage 键名常量、
             有没有硬编码路径、按钮是否都有绑定证据

第 4 级  浏览器                        → 只有以下 6 类才允许起浏览器：
         ① 渲染像素（画出来没有、比例、颜色分布）
         ② 布局几何（rect、遮挡、滚动位置、scrollIntoView 实际效果）
         ③ 浏览器事件链路（真实点击/键盘/Esc/拖拽后的状态变化）
         ④ 存储与持久化（localStorage 实际写入与刷新后恢复）
         ⑤ 动画帧与时序（rAF 节流、循环推进、两帧对比）
         ⑥ 截图类产物（导出图片尺寸/内容）
```

**一句话**：断言的对象如果是"代码里的字符串/表结构/HTTP 响应"，就不该起浏览器；
只有当断言对象是"浏览器把页面渲染/布局/交互之后的状态"时，才需要。

```
合计：必须浏览器 ≈ 73 条（+ engine-b1 运行时决定）
      可迁出 ≈ 20 条（unit 4 / API 7 / static 9）
      迁移比例 ≈ 21%
```

### 4.1 为什么迁移比例不高（如实说）

```
因为这套浏览器测试的主体确实是"渲染与交互"：
spine-actions(13) + engine-b1 + debug-drag(9) + f3(4) + f1(4) + anim(15) + f2(7) + panel(10) + roster(10)
——这些断言的对象就是"浏览器把页面跑起来之后的状态"，静态扫描替代不了。
```

### 4.2 迁移的真正收益在别处

```
现状：浏览器套件**默认不进自动门禁**（要 --browser）⇒ 这 20 条可迁移断言平时**根本没人跑**。
迁移后它们进入 node 默认门禁，等于从「从不执行」变成「每次执行」。
—— 收益不是"少起几次浏览器"，而是"这批断言终于真的在跑"。
```

## 五、新规（本次确立，需写进项目规范）

```
① 写测试前先按 §3 四级判据选级别；能用 1~3 级的，禁止起浏览器。
② 新增浏览器断言必须在文件头注明「为什么必须浏览器」（对应 §3 的 ①~⑥ 哪一条）。
③ 一次浏览器启动要跑完一个脚本里的所有断言，禁止"一条断言起一次浏览器"。
④ node-test 套件里禁止 spawn chromium（浏览器只允许通过 tool/check-console.mjs 使用）。
⑤ 静态扫描断言只允许断言"契约级事实"（控件 id 集合、分组标题、键名常量、是否硬编码），
   不要断言实现细节（函数名、行数、字符串拼接顺序）——否则改实现就红，变成噪音。
```

## 六、风险（迁移可能降低捕获力）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 「API 通 ≠ UI 接线」 | f4 的 CRUD 迁到 API 测试后，仍可能出现"接口好用但按钮没接上" | 浏览器里保留最小冒烟：每个写操作点一次，断言列表有变化 |
| 静态扫描脆弱 | 断言源码文本容易变成"改实现就红" | §5⑤ 的契约级限制；断言对象优先用「导出表/JSON/schema」而不是源码文本 |
| 迁移期间双份真相 | 新 unit/API 测试与旧浏览器断言同时存在，口径漂移 | 每迁一条就在浏览器脚本里删掉对应断言（不保留两份） |
| 页面结构变化导致旧断言失效 | static 断言依赖 HTML 结构 | 断言 id 集合时用"包含关系"而不是"全等" |

## 七、实施计划（分批，每批独立验收）

```
P0  规范落盘：四级判据 + 五条新规写进测试文档（本轮调研之后做）
P1  f4-roots 迁 API 测试（最大一块，7 条）：新增 test/roots-api.test.mjs，浏览器脚本删掉对应断言
P2  roster 的合并语义 + 搜索匹配迁 unit（4 条）；localStorage 键名迁 static
P3  panel 的控件清单/分组标题/接线态迁 static（6 条）

P5  浏览器套件瘦身后重测一次全量耗时（本轮未实测：需要起服务 + --browser）
```

每批验收：新测试单独跑通 + 旧脚本对应断言删除 + 全量 node 门禁绿 + 浏览器套件仍能跑（只跑一次确认没被破坏）。
