# 锐化算法参考（给 sharpness 插件设计用）

> 调研日期：2026-10-27 ｜ 用途：为 `plugins/sharpness` 设计稿提供算法与参数依据
> **可信度说明**：本轮网络受限（gpuopen / raw.githubusercontent 多次超时），
> 标注「✅ 有来源」的是检索到的原文要点；标注「⚠️ 推断」的是基于本项目代码与常识的推理，
> 实现前应以实测为准。

---

## 一、三个候选算法

### A. Unsharp mask（经典，推荐）

```
out = c + amount × (c − blur(c))
blur = 3×3 二项式核 [1 2 1; 2 4 2; 1 2 1] / 16   （等价两趟 1D，或直接 9 次采样）
等价写法（省 1 次采样）：取上下左右 4 邻域，中心权重更高
```

| 维度 | 评估 |
|---|---|
| 采样数 | 5（十字）~ 9（3×3） |
| 可表达性 | ✅ 单表达式即可，完美适配本项目的 `__EFFECT_CHAIN__`（单 pass、≤3 行、无循环） |
| 参数 | `amount` 线性可控，观感可预测 |
| 缺点 | 边缘两侧出现光晕（halo），强度大时明显 |

**典型取值**（⚠️ 推断，需实测定档）：`amount = 0（关）/ 0.35（轻）/ 0.7（强）`；
若用"中心权重 5、邻域 −1"的写法，等价于 `amount ≈ 1.0` 的经典 USM，可作强档起点。

### B. 3×3 拉普拉斯锐化

```
out = c + k × (4c − up − down − left − right)
```

与 A 同族（拉普拉斯就是 USM 的一种核形），差别只在核权重。**采样数与 A 相同、伪影特性更硬**，
没有理由优先选它 —— 除非要故意做"硬锐"风格。

### C. CAS / RCAS（AMD FidelityFX 对比度自适应锐化）

```
✅ 有来源：强度是 0..1 的 float（GPUOpen CAS 1.2 手册：sharpness 通过
   FfxCasDispatchDescription::sharpness 传入，打包进内部常量缓冲）
✅ 有来源：RCAS 提供 RCAS_DENOISE 编译开关，用于"少锐化噪点"；
   文档建议**把胶片颗粒/噪点放在锐化之后**，而不是靠 denoise 开关
⚠️ 推断：核心是按局部 min/max 自适应降低强边缘的锐化力度（这正是它比 USM 少光晕的原因），
   但需要额外采样 + 分支，公式也长
```

| 维度 | 评估 |
|---|---|
| 抗光晕 | ✅ 比 USM 好（自适应压制高对比边缘） |
| 可表达性 | ⚠️ 差：需要局部 min/max（≥4~8 次采样）+ 分段逻辑，塞进"单表达式 ≤3 行"的模板会很勉强 |
| 结论 | **本期不用**。留给"效果链支持自定义函数"之后再考虑 |

## 二、本项目特有的三个坑（比算法选型更重要）

### ① 只能锐化 RGB，**绝不能锐化 alpha**

```
✅ 有来源（间接）：RCAS 文档提到"锐化会放大噪点"，同理锐化 alpha 会在边缘产生
   亮边/暗边（fringe）
⚠️ 推断：本项目素材大量是**预乘 alpha（PMA）**——Spine atlas 有 `pma: true`，
   Live2D 纹理同样是 PMA。宿主的 __FILTER__ 模板已把 c 还原成直通 alpha 再交给表达式，
   但表达式如果对"含 alpha 的四元组"整体锐化，边缘就会出现彩色描边
要求：设计稿必须写明「只对 RGB 做锐化，alpha 原样透传」，并在验收里查边缘有没有彩边
```

### ② Atlas 打包会导致**边缘串色（seam bleeding）**

```
⚠️ 推断（本项目特有）：Spine 用 2048×512 的图集、Live2D 用 2048×2048 单页图集，
   不同部件在图上紧挨着。3×3 / 十字采样在**区域边界**会取到邻居部件的像素
   ⇒ 锐化时边界可能吸进别人的颜色
缓解：
  · 用十字 5 采样（比 3×3 少碰到对角邻居）
  · 只在有 alpha 的像素上生效（透明处不锐化，边界多在透明与不透明交界）
验收：在部件边缘放大截图，看有没有"从邻块渗进来的颜色"
```

### ③ `u_texel` 必须真的赋值

```
✅ 有来源（本项目实测）：上一轮 u_texel 未赋值 ⇒ GLSL uniform 默认 0
   ⇒ texelSample(uv − 0) 取回自己 ⇒ 锐化恒等于原图 ⇒「开关没反应」
要求：设计稿里写清 texel = 1/纹理尺寸，由宿主按当前纹理下发；
插件侧无法自证时必须靠宿主的验收（chainSignature 非空 + 像素确实变化）
```

## 三、给设计稿的结论建议

```
1. 算法：Unsharp mask（十字 5 采样），明确写"不选 CAS/RCAS 的理由 = 单 pass/单表达式表达不下"
2. 参数：三档 amount = 0 / 0.35 / 0.7（起点值，实测再调），写清"档位默认值 = options[0]"
3. RGB only：alpha 原样透传，验收查彩边
4. 透明像素不锐化：先用 alpha 阈值做保护，避免图集边界串色
5. 复杂度：≤5 次采样，写明"低端机每帧成本"，并给出回退路径（关档 = 完全不挂滤镜）
```
