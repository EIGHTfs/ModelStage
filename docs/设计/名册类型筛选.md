# 名册类型筛选：动态类型 + 多选

> 状态：**设计稿（未实现）**。UI 形态、类型命名、持久化三项已定；实现路径待定（见第八节）。

## 一、要解决的问题

```
左栏名册目前只有关键词搜索。想按「资源类型」过滤：
· 类型**不能写死** —— spine / live2d / 资源包只是当前观测到的几种，
  将来某个插件能解出新内容类型时，筛选列表要自动跟着出现
· 可多选：选中多个类型 = 显示这些类型的并集
· 筛选即过滤：列表只出现对应类型的条目（与关键词搜索同时生效）
```

## 二、现状（每条附引用）

| 事实 | 位置 |
|---|---|
| 左栏宽度 304px | `src/web/style.css:39` `--left-w: 19rem` |
| 名册结构：资源根 → 游戏 → 角色 → 变体（三级树） | `src/web/index.html:90`（`#roster-search`）、`src/web/roster/list.js` |
| 搜索只做关键词过滤，纯函数 31 行 | `src/web/roster/filter.js`（`variantSearchText` / `charMatches` / `visibleChars`） |
| 条目自带内容类型 `kind` | `src/server/data/catalog.mjs:187`（`kind: 'spine'`）、`:277`（`kind: 'live2d'`） |
| 条目自带容器标记 `container` | `src/server/plugins/registry.mjs:464`（按魔数识别资源包） |
| 插槽目录共 5 项，**没有左栏/名册位置** | `src/server/plugins/slot-catalog.mjs:46/49/52/55/60` |

结论：**数据层已具备条件**——类型不需要新造，直接从当前名册条目的 `kind` / `container` 聚合即可。

## 三、已定决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | UI 形态 = **搜索框下方常驻「类型胶囊」行** | 一眼可见、一次点击即过滤；类型数量在可预期范围内 |
| 2 | 类型显示名 = **内置映射 + 未知回退原值** | id 完全动态；只给已知类型起可读名，未知的显示原值，不假装认识 |
| 3 | 选中状态 **持久化** | 与关键词分开存；刷新后保持 |
| 4 | 实现走 **A 纯内置** | 左栏属宿主骨架；类型来自解包结果而非插件能力（见 §8） |
| 5 | 胶囊数字 = **当前搜索条件下的可见变体数** | 与列表一致优先于数字稳定；输入时数字会跳动，属可接受代价 |
| 6 | **不按资源根筛选**，但预留扩展 | 当前只有游戏分组，资源根维度收益不明；先留接口位（见 §5.3） |
| 7 | 类型多时 **自动换行**，不折叠 | 与筛选器（滤镜）列表一致；折叠要多一次点击，窄栏浮层更难放 |

## 四、UI 规格

### 4.1 布局

```
┌─ 左栏 304px ──────────────────┐
│ [ 搜索角色 / 服装 / 变体… ]     │  ← 现有 #roster-search 不动
│ (Spine 12)(Live2D 8)(待解包 3)│  ← 新增：类型胶囊行（自动换行，可多行）
├───────────────────────────────┤
│ ▸ 游戏A                        │
│    角色1 · 变体…                │
└───────────────────────────────┘
```

```
· 高度：不固定 —— 胶囊 22px 高、行间距 6px，**按内容自动换行**
· 溢出：**换行**而不是横向滚动（类型多时高度增加，最多约 3 行；列表区随之上移）
· 空间上限：**不设数量上限、不做折叠交互**（不引入「更多」按钮）—— 全部类型都渲染并自动换行。
  若将来类型数量导致胶囊行过高，优先考虑"容器内滚动"而不是截断（截断会让某些类型不可选，等于隐藏功能）
· 数量：显示在该类型的括号里（口径见 §5.2）
· 位置：`#roster-search` 与 `#roster-list` 之间，独立容器 `#roster-type-filter`
```

### 4.2 状态与语义

| 状态 | 表现 | 列表行为 |
|---|---|---|
| 未选中任何类型 | 全部胶囊为未选中态 | 不过滤（等价「全部」） |
| 选中 1..N 个 | 选中的胶囊高亮（`aria-pressed="true"`） | 只显示 `kind ∈ 选中集合` 的条目（**并集**） |
| 与关键词同时存在 | 两者都生效 | 先按类型过滤，再按关键词过滤（**交集**） |

```
· 不额外提供「全部」按钮：全部 = 全部取消选中（避免"全部"与"什么都没选"两种状态混淆）
· 提供「清除」小按钮：仅在至少选中 1 个时出现，一次清空
```

### 4.3 交互与可达性

```
· 点击胶囊 = 切换选中（支持多选）
· 键盘：Tab 可达；Enter / Space 切换；选中态用 aria-pressed 表达（与工具栏按钮同一套语义）
· 胶囊是 <button type="button">，不是 <div>（复用现有 .mini-btn 的焦点样式）
```

### 4.4 空态

```
· 名册为空（没有资源根/没扫到条目）⇒ 整行隐藏（不留一条空白）
· 类型只剩 1 种 ⇒ 仍然显示（用户可能想确认"确实只有这一种"）
· 类型数多 ⇒ **自动换行**，不折叠成「更多」（与筛选器列表一致；折叠会多一次点击）
```

## 五、类型派生规则（不写死）

### 5.1 kind 取值现状（实测，决定筛选要处理几档）

| 阶段 | `kind` 取值 | 其它字段 | 依据 |
|---|---|---|---|
| **未解包容器**（资源包单文件） | **`null`**（可能为空） | `container: 'unityfs'`、`provider: <插件 id>` | `src/server/data/catalog.mjs:412`（`kind: provider.kind`，注释明确"可能为 null：宁可显式空，也不按插件 id 猜"） |
| **已解包 / 目录型** | `'spine'` | — | `src/server/data/catalog.mjs:187`、`:277`（live2d）、`src/server/data/live2d.mjs:128` |
| 同上 | `'live2d'` | — | 同上 |
| 插件清单声明的是 | `fileKinds: ['bundle']`、`provides: ['asset-provider']` | 不是产出类型 | `plugins/*/plugin.json` |

```
关键结论：**未解包条目的 kind 是 null**，不是 'bundle'。
所以筛选必须有「未知/待解包」这一档，否则这些条目在"选中任意类型"时会被全部滤掉 ——
用户会以为"资源包不见了"，实际是被类型过滤掉了。
```

```
处理规则：
· kind 为 null 的条目归入特殊类型 `unknown`，显示名「待解包」
· `unknown` 与其它类型一样参与多选（可单独选它，也可与 spine/live2d 一起选）
· 解包完成后 kind 变成 spine/live2d ⇒ 该条目从 `unknown` 档自动移到对应档（计数与胶囊随之更新）
```

### 5.2 聚合

```
输入：当前名册里所有变体条目（与列表同源，不额外请求）
规则：typeKey = 条目的 kind（内容类型）；容器单文件在未解包前 kind 可能为 bundle，也照此参与
输出：按出现次数降序的类型列表（并列时按 key 字典序，保证稳定）
```

```
· 类型集合**每次名册重建后重算**（资源根增删、解包完成导致 kind 变化都会触发）
· 若某类型在重算后消失：UI 上移除，但**持久化里保留**（下次出现时自动恢复选中）
```

### 5.3 计数口径

```
按「变体」计数（与列表叶子粒度一致），不按角色计数
口径 = **当前搜索关键词下、该类型的可见变体数**（不含类型过滤本身的影响）

为什么排除类型过滤的影响：否则选中 Spine 后，其它胶囊会瞬间变成 0 或消失，
用户无法据此判断"切到 Live2D 还能看到多少" —— 数字要回答"如果选它会有多少"。
```

### 5.4 预留：按资源根筛选（本期不做）

```
现状：名册已有"游戏分组"，资源根维度收益不明，本期不做。
预留方式：类型派生函数签名里保留 `scope` 参数（当前只传 { keyword }），
  将来加资源根维度时只需扩 scope 与 UI，不改派生逻辑本身。
```

## 六、显示名映射

```
位置：单一来源（建议 src/shared/type-labels.mjs，前端与将来的插件共用）
规则：已知 → 可读名；未知 → 原值（不做大小写美化，避免"看起来认识其实不认识"）

内置映射（初版，可增补）：
  spine   → Spine
  live2d  → Live2D
  unknown → 待解包      ← kind 为 null 的容器条目（见 §5.1），必须有这一档
  bundle  → 资源包      ← 当前代码不产出该值，保留以防将来有插件这样声明
```

```
为什么不做成插件声明：声明式 label 需要改插件契约 + 校验 + 向后兼容，
而"显示名"是本项目的展示决策，不是插件的能力声明 —— 放在宿主更合适。
若将来确实要插件自定义类型名，再抬成契约（届时作为可选字段，缺省回退本表）。
```

## 七、持久化

```
键：roster.typeFilter（与现有 roster 持久化键同前缀，复用 src/web/roster/persist.js 机制）
值：字符串数组（typeKey 列表），例如 ["spine","live2d"]
读取：过滤掉不在当前类型集合里的值（保留在存储里，不主动删）
写入：每次切换后写入；写入失败静默（筛选是增强，不阻塞主流程）
```

## 八、实现路径（**待定，需要拍板**）

结构性问题：**插槽目录里没有左栏/名册位置**（`slot-catalog.mjs` 现有 5 项：`panel.brand` / `panel.group.<groupId>` / `panel.control.<key>` / `toolbar.actions` / `stage.overlay`）。所以"做成插件"不是把代码塞进插件目录就行，而是要先决定 UI 归属。

| 路径 | 做什么 | 改动面 | 风险 | 满足"插件"表述 |
|---|---|---|---|---|
| **A 纯内置（✅ 已选）** | 改 `roster/filter.js`（加类型维度）+ `roster/view.js`（渲染胶囊）+ `index.html`（容器）+ `panel.css`（样式）+ 持久化 | 4~5 文件，约 150~200 行 | 低 | ✗（是内置功能） |
| **B 新增插槽** `panel.roster.filter` | 先扩 `slot-catalog`（新插槽 + 阶段 + 契约），再让插件注册胶囊；宿主提供"名册类型集合"数据 | 插槽目录 + 宿主渲染 + 插件契约 + 校验 + 测试 | 中高（要抬 stage、写契约、防插件间冲突） | ✓ |
| **C 混合（内置 UI + 插件供类型）** | 胶囊由宿主渲染；类型来源抽象成 provider，插件可注册"额外类型识别"（如"能解 ASTC 的包"） | 中等（新增一个数据层扩展点，不动 UI 归属） | 中 | 部分（插件只扩展类型来源，不接管 UI） |

**已定：走 A（纯内置），并把类型派生抽成函数边界（便于以后换成 provider）**，理由：

```
① 左栏是宿主骨架的一部分（三级树、搜索、持久化都在宿主里），
   插件接管这一块要连带定义"插件如何拿到名册数据、如何与关键词搜索共存"，
   契约成本远大于筛选本身的收益
② 当前类型集合来自**条目数据**，不来自插件能力 —— 插件并不掌握"这个条目是什么类型"，
   是解包结果决定的。让插件来渲染筛选器，等于让它展示自己并不拥有的数据
③ 若将来确实需要插件贡献"新类型识别能力"，走 C 的 provider 形态即可，
   不必把 UI 也交出去
```

## 九、验收判据

```
功能
· 胶囊集合 = 当前名册实际出现的类型集合（增删条目后自动变化）
· 多选为并集；与关键词为交集
· 刷新页面后选中状态保持；失效类型被忽略
· 名册为空时整行隐藏

正确性
· 纯函数单测：给定条目集合 + 选中类型 + 关键词，输出集合正确（含空集、全选、未知类型）
· 浏览器断言：胶囊数量 = 派生类型数；选中后列表内所有条目 kind ∈ 选中集合
· 计数：胶囊上的数字 = 该类型在当前关键词下的可见变体数（还是全量变体数？见 §10.3）

可达性
· 键盘可逐个聚焦与切换；aria-pressed 与视觉状态一致
```

### 10.2 实现时需要留意的两点（不是待定，是风险提示）

```
1. 解包后「跳档」：同一文件从 unknown 移到 spine/live2d，计数与胶囊会变。
   若用户正选中 unknown，解包完成后该文件会从当前视图消失（因为它已不属于 unknown）。
   ⇒ 处理方式：解包完成触发的名册重建里，若某条目离开当前选中集合，只更新列表，
      不自动改用户的选择（避免"我的选择被系统改了"）。必要时在列表空时给一句提示：
      「当前筛选下没有条目（有 N 个已移到其它类型）」——具体文案实现时定。
2. 换行后的高度抖动：类型数量变化（如某类型消失）会让胶囊行高度跳变，列表位置跟着跳。
   ⇒ 实现时给容器一个最小高度（单行高度），避免从 2 行变 1 行时列表猛地上移。
```
