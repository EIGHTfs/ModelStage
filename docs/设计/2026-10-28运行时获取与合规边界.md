# 运行时获取：探测、引导与（仅 Spine 的）自动下载

> 目标：运行时目录**不存在**时，从"启动就报错"变成"能自解释、能一键补齐"。
> 边界：**只对 Spine 4.x 做自动下载；Live2D 一律只引导不代下**（合规原因见 §二）。

## 一、现状

```
探测：Spine → tool/lib/spine-runtime.mjs（**不是** tool/resolve-runtimes.mjs，早前误记）
      Live2D → tool/resolve-live2d-runtimes.mjs
搜索顺序（**两者本来就不一致，本轮各自保持原样**）：
  Spine  ：项目内 src/spine-runtimes → 工作区共享 ../spine-runtimes → SPINE_RUNTIME_DIR
  Live2D ：LIVE2D_RUNTIME_DIR(env) → 项目内 src/live2d-runtimes → ../live2d-runtimes
命名约定：resolver 按 **`spine-webgl-<version>.js`** 拼文件名（spine-runtime.mjs:45,49）
两者都 gitignore（授权与体积），所以"全新 clone / npx 装出来"必然缺运行时
现状：缺了就是启动报错，用户不知道要下什么、放哪里、文件该叫什么名字
```

## 二、合规边界（这是本设计的硬约束，不是建议）

| 运行时 | 来源 | 做法 | 依据 |
|---|---|---|---|
| Spine 4.0.1+ | 官方 npm（维护者 badlogic，repo 指向 EsotericSoftware/spine-runtimes） | **可自动下载** | 用户本身有权从 npm 取；我们不构成再分发 |
| Spine 3.x | npm 无（最早 4.0.1） | 只引导 | 拿不到 |
| Live2D Cubism Core | 官方只在官网提供，下载需同意 Proprietary Software License | **只引导，绝不代下** | 脚本抓取 = 绕过 EULA 接受环节；且 npm 上 `live2dcubismcore` 是第三方转载、许可标错（ISC），不可依赖 |

另外两条必须写进产品文案：

```
· Spine Runtimes 是 Esoteric 自定义许可（非 MIT），**用的人要自己遵守**（商用需 Spine 授权）
  ⇒ 下载时必须显式确认一次，并把该包的 LICENSE 一并落地
· 我们不托管、不再分发任何运行时二进制；下载是"替用户从上游取"，落地在用户自己的数据根
```

## 三、落点（不能写进 src/*-runtimes）

```
npx / 只读安装场景下项目目录可能只读或临时 ⇒ 下载物必须落到**用户数据根**：
  默认 <dataRoot>/runtimes/spine/<version>/spine-webgl-<version>.js（+ LICENSE + SOURCE.json）
       <dataRoot>/runtimes/live2d/<ver>/（用户手动放入）
搜索顺序：**各自保持现有顺序不动，只在末尾追加 <dataRoot>/runtimes**
（Spine：项目内 → 工作区共享 → env → dataRoot；Live2D：env → 项目内 → ../ → dataRoot）

两条硬要求（原设计漏了，是决定成败的点）：
  ① **落地文件名必须归一化成 `spine-webgl-<version>.js`**
     resolver 是按这个名字拼的；npm 包里的 `spine-webgl.js` 直接落地会"文件在、但找不到"
     同时写一份 SOURCE.json（tarball URL + integrity + 落地时间），便于审计与追溯
  ② **`/spine-runtimes/index.json` 必须也列出 dataRoot 下的版本**
     它现在只扫单一目录（static.mjs:139 `listRuntimeVersions(ctx.runtimeDir)`）
     不改的话：resolver 找得到、前端列不出 ⇒ `?runtime=spine-4.1` 依然用不上
     选定修法：**合并 dataRoot（改 static.mjs，不改前端调用方）**
```

## 四、能力拆分：CLI 下载 + 只读状态接口 + 引导文案（**不动面板 schema**）

```
① tool/fetch-runtimes.mjs  —— 唯一的下载入口（CLI）
     --list                 列可用版本（从 registry 元数据读 versions，**不硬编码版本表**）
     --spine <version>      下载该版本 → 校验 → 落地 → 打印路径与许可提示
     --dir <path>           覆盖落点（默认 <dataRoot>/runtimes）
     --yes                  跳过交互确认（CI 用；仍打印许可提示）
     无 --yes 时必须交互确认一次许可，拒绝则退出 0 且不下任何东西

② 只读接口 GET /api/runtimes
     → { spine:{ available:[…], source, missing:bool },
         live2d:{ available:[…], source, missing:bool, guideUrl } }
     仅读探测结果；**不触发下载**（下载只在 CLI，避免网页被诱导联网）

③ 引导文案（终端 + 面板只读读数）
     缺 Spine 4.x  → 打印可复制命令：node tool/fetch-runtimes.mjs --spine 4.1
     缺 Spine 3.x  → 指向 GitHub 发布页（自备）
     缺 Live2D     → 打印官网页 URL + 目标目录 + 需要哪个文件（不代下）
```

## 五、下载实现要点

```
· URL 由 registry 元数据给出（dist.tarball），不拼字符串
· **校验用 npm 官方 dist.integrity（sha512）**，比自己算 sha256 更权威；失败即删半成品
· 解压：tgz = gzip + tar。只取单个文件，自己解析 512 字节 tar 头即可（零依赖，约 40 行）
  禁止 shell 出 `tar`（跨平台 + noexec 环境风险；项目已有 tool-self-detection 的教训）
· 包内路径从 `package/package.json` 的 main/module 或实际目录探测，**不写死**
· 默认不联网：只有显式跑 CLI 才下载；网页侧永不自动下载
· 失败分类可读：网络不可达 / 404 版本不存在 / integrity 不匹配 / 解压失败 / 落点不可写
```

## 六、验收

```
1. --list 列出真实版本（含 4.0.1~最新），且**没有** 3.x（证明不是硬编码）
2. --spine 4.1 → 下载 + integrity 校验通过 + 落地 + LICENSE 一起落
3. 故意把 integrity 改坏 → 明确报"校验失败"且**不留半成品**
4. 断网（或把 URL 换坏）→ 明确报"网络不可达/404"，不是超时挂死
5. 落地后引擎真的能用它：/?model=<4.1 骨架>&runtime=spine-4.1 装载成功（复用 URL 参数能力）
6. /api/runtimes 在"有/无运行时"两种状态下返回正确 missing 标记
7. 缺 Live2D 时：终端与面板都给官网 URL + 目标目录，**且没有任何下载动作**
8. 全量 node --test 保持全绿（新增单测覆盖 tar 解析与 integrity 校验失败路径）
```

## 七、明确不做

```
· 不做 Live2D 自动下载
· 不做面板上的"下载按钮"（下载只在 CLI；面板只显示状态与引导）
· 不做后台静默预下载、不做版本自动升级
· 不把任何运行时二进制入库，也不进 npm 包（files 白名单继续排除）
```
