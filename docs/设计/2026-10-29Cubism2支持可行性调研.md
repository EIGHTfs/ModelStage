## 零、结论先行

**① 待办 §五 那批"not-handled"的嵌套包，不是 Cubism 2 —— 它们是 Cubism 3/4（moc3），而且现在已经能打开了。**
不需要为它们做 Cubism 2 支持；这条待办的前提本身不成立（观察发生在 LZMA 修复之前）。

**② 如果将来真遇到 `.moc` 包：建议「不做」。**
不是"做不动所以要凑"，而是三条硬边界同时成立：官方 SDK 已不支持、格式无公开规范、渲染需要另一套专有运行时。
**唯一值得做的退化档是「贴图预览」——而它恰好不需要解析 `.moc`**，见 §四。

```
aierdeliqi_5:      probe.ok=true  moc3=1972288B → canHandle=true    textures=2 motions=15

```

### 1.5 为什么之前报 not-handled

canHandle = `probe.ok && !!probe.moc3`（`plugins/unity-live2d-bundle/index.js:511`）。
这些包是 **LZMA 压缩**，LZMA 未支持时 `probe.ok === false` ⇒ canHandle 返回 false ⇒ 宿主报 `not-handled`。

**LZMA 第 1 步（提交 `3c8958d7`）修完后，同一条链上 `probe.ok` 变 true、moc3 解得出来，canHandle 自然为 true。**
所以 §五 记录的现象属于"LZMA 缺口的另一种表现"，不是 Cubism 2 问题。

## 二、Cubism 2 的官方现状（实地查证）

### 2.1 官方明确：现行 SDK 不支持 .moc / .mtn

来源：Live2D 官方帮助《Cubism 2.1的模型和动作可以在新的Cubism SDK中使用吗？》
https://help.live2d.com/zh-CHS/cubismsdk/migrate-from-cubism2-to-newer-cubismsdk/ （页面标注 2021/10/26）

原文：

> **Cubism 3 SDK及以后的版本不能使用Cubism 2.1的嵌入式数据格式。.moc、.mtn**
> Cubism 3及以后版本的Editor可以读取Cubism 2.1的.cmox和.canx，并将其转换为.cmo3和.can3。转换后，可以将其输出为.moc3和.motion3.json。

这段话同时给出两个要点：
- **运行时侧**：现行 SDK 直接不支持 `.moc` / `.mtn`，没有"打开开关就能读"的路径
- **工具侧**：官方给出的迁移路径是**用 Cubism Editor 做格式转换**（`.cmox`→`.cmo3`→`.moc3`），这是**离线单模型的手工操作**，不是运行时能力

### 2.2 运行时仍属专有许可，与本项目既有约定一致

- Cubism SDK 下载页（https://www.live2d.com/en/sdk/download/web/）要求先同意 “Live2D Proprietary Software License Agreement” 与 “Live2D Open Software License Agreement”（实测页面文案）
- 本项目既有约定（`src/server/data/live2d.mjs:236`）：
  > `/** 探测 Live2D 运行时库（Cubism Core 受专有许可约束不入库，从本地已有副本取）。 */`
  对应 `src/server/http/static.mjs:109-112`：`live2dGuideUrl` 指向官方 SDK 下载页，`live2dNote: 'Live2D Cubism Core 需你本人同意官方专有许可，本项目不代下载'`

⇒ **Cubism 2 运行时（`live2d.js` / `live2d.min.js` 那一代）同样适用这套约定**：即便它还能找到，也只能由用户自行取得、页面只做指引，不能 vendor 进仓库。

## 三、技术边界（为什么"自研解析"不是可选项）

`.moc`（Cubism 2 的模型二进制）与 `.moc3`（Cubism 3+）是**完全不同**的格式，且 `.moc` 从未公开规范：

- 无官方格式文档（Live2D 只对 `.moc3` 提供 MOC3 Consistency Checker 等工具，`.moc` 无）
- 采用**算术/区间编码压缩**的私有二进制，字段布局只能靠逆向
- 内容不只是"网格数据"：包含 drawable 的顶点/索引/UV、变形器层级、父子变换、参数绑定、纹理索引表，**缺任何一块都出不了正确画面**

由此得到一个重要区分（这决定了 §四 的结论）：

```
要"看见点什么"（贴图）      ⇒ 不需要解析 .moc   ✅ 可行且便宜
要"模型动起来/正确显示"      ⇒ 必须完整解析 .moc ❌ 无规范，逆向风险极高
```

## 四、三种粒度的工作量估算

| 粒度 | 是否需要解析 `.moc` | 可行性 | 工作量 | 产出价值 |
|---|---|---|---|---|
| **A. 只提取贴图预览** | **不需要** | ✅ 可行 | **0.5~1 天** | 能看静态立绘（无动作、无变形） |
| **B. 能显示静态模型**（网格/变形器/正确姿态） | 需要（完整） | ⚠️ 无规范 | **数周~数月，且不保证完成** | 静态可动的模型 |
| **C. 完整动作播放** | 需要 + `.mtn`/`.physics` 解析 + Cubism 2 运行时语义 | ❌ 不建议 | 不可估 | 与官方运行时对等 |

### A 档为什么"不需要解析 .moc"（这是唯一可行的档）

`.moc` 包在实际资源里的形态通常是：`.moc`（模型）+ `.png`（一张或多张 atlas）+ `.json`（`model.json` 定义）或 `.mtn`。**贴图是独立文件**，与 `.moc` 的内部结构无关：

- 散目录形态：直接读 `.png` 即可
- Unity 资产包形态：`Texture2D` 对象本来就是完整可取的（本项目 `extract.findTextures` + `texdecode.decode` 已经支持 fmt 47/4/5/3/1/7/34/45/10/12/26/27）

所以 A 档的实质是：**识别"这是个 Cubism 2 包"→ 把贴图取出来显示 → 明确告知"模型数据未解析，仅供预览"**。

### 若真要走到 B 档，必须先解决的顺序

```
1. 核实 §2.3 那批社区项目到底是"打包官方运行时"还是"自研解析"（决定后面有没有参考实现）
2. 逆向 .moc：至少拿到 drawable 顶点/索引/UV + 变形器层级 + 纹理索引
3. 写一个独立的 Cubism2 渲染适配（不能复用 Cubism Core 那条 PIXI 通路：它只吃 moc3）
4. 逐模型验证（无权威参考，只能靠肉眼比对官方运行时的渲染结果 —— 而官方运行时又不能进仓库）
```

第 3、4 步是真正的成本中心，且第 4 步缺少可用的对照物。

## 五、与现有架构的关系

### 5.1 canHandle 认 `.moc` 会不会影响 moc3 路径

**不会误判，但有更省的做法**：`.moc` 与 `.moc3` 魔数不同（`MOC3` vs Cubism 2 的私有头），加一个分支是安全的。但：

- 现在的 canHandle 已经是 `probe.ok && !!probe.moc3`（内容签名判型，不猜扩展名）
- 若要支持 A 档，**不需要动 canHandle 的 moc3 判定**，只需在"两个插件都不认领"之后增加一条**兜底预览路径**（见 5.2），风险更低

### 5.2 产物结构怎么表达

现有 `entry` 契约（`.model3.json` 入口）无法表达 Cubism 2 包 —— 它没有 moc3、没有 model3.json。

A 档若要做，最小改动形态是：

```
不改 canHandle（保持"只认 moc3"），在宿主侧加一个「无法认领但含贴图」的降级预览：
  · 用现有 catalog/probe 已知的 Texture2D 清单（extract.findTextures 已支持）
  · 产物只给贴图 + 一句说明，不产出 entry.json、不进入正常装载链路
  · 好处：完全不碰 asset-provider 契约，也不给"能玩"的错觉
```

**这条我倾向"先不做"** —— 见 §六。

## 六、最终建议

```
【本批 75 个包】不需要任何 Cubism 2 工作 —— 它们是 moc3，LZMA 修完已能打开。
                建议把待办 §五 直接结案，并把结论写回待办（避免下次有人再查一遍）。

【真 .moc 包】  建议不做。三条边界同时成立：
                ① 官方 SDK 明确不支持 .moc/.mtn，唯一官方路径是用 Cubism Editor 离线转换
                ② 格式无公开规范，自研逆向工作量不可估且不保证完成
                ③ 渲染需另一套专有运行时；第 4 步验证还缺对照物

【若一定要做】  只做 A 档（贴图预览，0.5~1 天）：不解析 .moc、不碰 canHandle、不进装载链路，
                只把 Texture2D 取出来显示并明确标注"模型数据未解析"。
                先做前提：核实 §2.3 三个社区项目的实现性质。
```

### 为什么"不做"是这里的正确答案

这一项与刚做完的 LZMA、version 6 有本质区别：
- LZMA / version 6：**格式我们能读，只是我们的解析有缺口** → 修好就行（已修：126/126）
- Cubism 2：**格式与运行时都不在我们手里** → 不是"补个分支"能解决的

也就是说，即便投入数周逆向成功，也只能得到"和官方运行时差不多但不保证一致"的渲染，而官方运行时我们自己都不能分发。
