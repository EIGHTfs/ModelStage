# 渲染面元数据表：把 kind → 渲染器/画布/面模式 收成单一来源

> 2026-10-29 由「契约与代码不一致上报」触发。上报详见本文件 §一，来源为只读调研会话（未改任何代码）。

## 一、问题：契约承诺与代码现状的出入

`docs/契约/渲染面.md:461-462` 的判据：

> 加 3D 渲染器时**不需要改 VirtualFS、不需要改资产提供者、不需要改面板 schema**；
> 若要改这些，说明扩展点没留够 —— 先补契约再实现。

`src/web/render/surface.js:11` 的注释：

> 为什么这么分：新增渲染面（3D）时只加一个 `register()`，不必再改画布/尺寸/可见性逻辑。

**这两句话只对了一半。** 实测（逐行 grep，非推测）确认：契约点名的三项确实不用改，但
**「kind → 渲染器 / 画布 / 面模式」的推导是二元写死的**，加第三个渲染面时会被**静默误判成 spine**，
表现为功能错乱而不是报错 —— 这是最难排的一类。

 | 位置 | 现状 | 加 3D 时的后果 |
|---|---|---|
| `infra/document.js:67` | `entry.kind === 'spine' \|\| entry.kind === 'live2d'` | 3d 判不出 kind ⇒ 落到 `null` ⇒ `buildDocument` 判 `!kind` ⇒ `state='error'` ⇒ **永远进不了渲染层** |
| `infra/document.js:250` | `if (kind === 'spine') … else buildLive2dAssets` | 第三种 kind 被当 live2d 组装 |
| `render/surface-switch.js:101` | `document.kind === 'live2d' ? 'live2d' : 'spine'` | 3d 被标成 spine，`setMode` 写错面 |
| `render/surface-switch.js:69` | 同上（卸载模式判定） | `unmount` vs `dispose` 算错 ⇒ **遗留旧 GL 上下文**（契约 §五-7 明确禁止） |
| `render/surface.js:256` | `mode === 'live2d' ? … : 'spine'` | `data-stage-mode` 写成 spine ⇒ CSS 走 2D 分支；覆盖层显隐误判 |
| `render/surface.js:302` | `const isLive2D = rendererId === 'live2d'` | 3d 拿到 spine 画布 + overlay=null |

次要（显示错但不影响功能）：`render/camera/constants.js:40`、`roster/rows.js:137`、
`roster/list.js:145`、`app/model-actions.js:96`、`app/url-params.js:104,117`。

## 二、为什么不做逐文件打补丁

逐处加 `|| kind === '3d'` 的做法有明确的失败模式：

```
下一个渲染面（第 4 个）出现时，同样要再找一遍这些地方 —— 而它们散在 6 个模块、
没有任何清单，漏一处就是静默错误（不是崩溃，是功能错乱）
```

这正是 `drift-prevention` 说的「同一事实存在多处表达」：**"有哪些渲染面、每个面长什么样"这个事实，
现在被 10 处 `=== 'live2d'` 各自表达了一遍。**

## 三、设计：一张表 + 一次注册

### 3.1 渲染面元数据表（唯一真相）

新增 `src/web/render/surfaces.js`：

```js
/**
 * 渲染面元数据表：**「有哪些面、每个面长什么样」的唯一真相**。
 *
 * 为什么要有这张表：这个事实原先被十处 `kind === 'live2d'` 分别表达，
 *  加上第三个面时任何一处漏改都是静默误判（不报错、只是行为错）。
 *
 * 加新面时改这里一处 + 写 render/<kind>.js + register() 一次；
 *  所有消费方都从这张表取值，不再自己写二分判断。
 *
 * 字段说明（每个字段都对应一处原先的硬编码）：
 *   id            渲染器 id（= document.rendererId 的缺省值）
 *   kind          document.kind 的取值
 *   label         界面上显示的名字（原 roster/list.js 的三元表达式）
 *   badge         名册徽标的 CSS 修饰名（原 roster/rows.js）
 *   stageMode     写到 data-stage-mode 的值，CSS 据此选布局（原 surface.js setMode）
 *   overlay       'canvas' = 该面用覆盖层 canvas（原 isLive2D 判断）；null = 用舞台画布
 *   overlayVisible 覆盖层容器是否可见（原 setMode 里的 is-visible 切换）
 *   cameraKind    相机常量覆盖表的键（原 camera/constants.js limitsFor）
 *   deepLink      深链参数是否接受这个 kind（原 app/url-params.js）
 */
export const SURFACES = [
  { id: 'spine',  kind: 'spine',  label: 'Spine',  badge: 'spine',  stageMode: 'spine',  overlay: null,     overlayVisible: false, cameraKind: 'spine',  deepLink: true },
  { id: 'live2d', kind: 'live2d', label: 'Live2D', badge: 'live2d', stageMode: 'live2d', overlay: 'canvas', overlayVisible: true,  cameraKind: 'live2d', deepLink: true },
];
```

**加 3D 时只加一行**，并把 `deepLink` / `cameraKind` / `badge` 按需填上。

### 3.2 查询接口（消费方只用这些，不许自己遍历）

```js
byKind(kind)        // → 元数据 | null（未知 kind 返回 null，供调用方显式处理）
byId(id)            // 同上
knownKinds()        // → string[]（document.detectKind 用它判"是不是已知面"）
isKnownKind(kind)
stageModeOf(kind)   // 未知 kind → null（调用方必须处理，不许回落到 spine）
```

**关键约束：未知 kind 必须返回 `null`，不许"回落到 spine"。**
原代码每一处 `x === 'live2d' ? : 'spine'` 的隐含语义都是"不是 live2d 就是 spine"，
这在只有两个面时成立，加第三个面时全部失效。返回 null 强制调用方显式处理，
比"猜一个默认值"安全得多 —— 这是本次重构的核心原则。

### 3.3 注册表的反向登记

`surface.register(renderer)` 额外要求 `renderer.kind`，并断言 `byKind(kind)` 存在：

```js
register(renderer) {
  if (!renderer?.id) throw new Error('…必须有 id');
  if (!renderer.kind) throw new Error('…必须声明 kind（用于面元数据表校验）');
  if (!isKnownKind(renderer.kind)) throw new Error(`渲染面 ${renderer.kind} 未在 SURFACES 注册`);
  // 断言 id 与表一致，避免 register('spine-v2') 这类漂移
  …
}
```

这样"注册了渲染器但忘了加表项"会在**启动时**炸，而不是等用户点开 3D 模型才发现。

## 五、验收

```
1. **行为零变化**：spine 与 live2d 的全部既有行为不变
   - panel-actions / f1-controls / f3-reveal / roster-actions / spine-actions / pma-detect 全绿
   - 真机各开一个模型，画面正常（截图）
2. **未知 kind 显式失败**：构造一个 kind='three' 的 document
   - detectKind 返回 null 或抛错（不许当 spine）
   - surface-switch 明确报错（不许静默走 spine 分支）
   - 这条必须有单测 —— 它是本次重构的目的
3. **注册校验生效**：register 一个 kind 不在表里的渲染器 ⇒ 启动即抛错
4. **表覆盖断言**：SURFACES 里每个 id 都被 main.js 注册（防止加了表项忘了注册）
5. 全量 node --test 全绿；审计 blocker 0
```
